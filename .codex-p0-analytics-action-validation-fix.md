**结论**

根因是 [AnalyticsService.java](/home/james/complex-management/backend/src/main/java/com/complex/platform/analytics/AnalyticsService.java:240) 原来只校验 `StatusChangeRequest.action` 非空，然后直接写入 `analytics_risk_alerts.status`。内存仓库会吞掉任意字符串，但真实 JDBC 路径会撞上 V017 的 `chk_analytics_risk_alerts_status`，从而有机会把无效 action 变成数据库异常 / 500。

我做了这些改动：

- 在 [AnalyticsServiceTests.java](/home/james/complex-management/backend/src/test/java/com/complex/platform/analytics/AnalyticsServiceTests.java:169) 新增测试 `resolveRiskAlertRejectsInvalidActionWithApiExceptionCodeValidationFailed`，`action="send_wechat"` 必须抛 `ApiException` 且 code 为 `VALIDATION_FAILED`，并断言没有更新风险告警。

- 在 [AnalyticsService.java](/home/james/complex-management/backend/src/main/java/com/complex/platform/analytics/AnalyticsService.java:392) 增加 `requireRiskAlertResolveAction`，非法 action 现在服务层直接返回 `VALIDATION_FAILED`，不会落到数据库 CHECK 约束。
