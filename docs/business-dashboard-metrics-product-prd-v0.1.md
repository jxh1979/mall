# 经营看板指标产品 PRD V0.1

> 生成日期：2026-06-26（审计第二轮修改阶段补建，裁决#7）。依据：业务系统地图「经营看板」节（主要指标 + 谁会看）+ 业务枚举速查表相关状态；冲突时以三份业务 HTML 为最终解释权。
>
> 补建原因：经营看板 8 类指标业务 HTML 已明确授权，已有指标快照接口（`p2-business-metric-snapshots-api-contract-v0.1.md`）与聚合开发设计（`r5-spec-T12-dashboard-aggregation-dev-design-20260618.md`、`r5-aggregation-metrics-draft-20260618.md`），但**缺统一的看板指标产品口径**，指标定义散落各处。本文回填指标需求源，统一口径，不新增范围。
>
> 本文不写技术实现。落地承接见 §4。

## 1. 文档定位

经营看板让管理层和运营**看得懂、能追问**。它要能从总览下钻到票务、酒吧、供应链库存、游乐、商户、异常、对账和地产明细。看板不产生业务数据，只汇总展示；数据口径以各业务域与财务对账为准。

## 2. 指标分类（8 类，HTML 授权口径）

| 类 | 主要指标 |
|---|---|
| 收入 | 售票收入、酒吧收入、第三方回流收入、退款、净收入 |
| 客流 | 入场人数、酒吧入场、游乐核销人数、渠道客流 |
| 核销 | 权益发放数、核销数、核销率、拒绝数、人工放行数 |
| 会员 | 新增会员、积分发放、积分兑换、会员等级分布 |
| 供应链 | 采购到货、库存余额、吧台消耗、缺货预警、盘点差异、存酒余额 |
| 风险 | 待复核、异常事件、补录数量、第三方差异 |
| 财务 | 日结状态、对账差异、结算待确认 |
| 地产 | 招商线索与成交、铺位出租率、租金与物业费应收、能耗与楼宇设备告警、物业工单时效 |

## 3. 谁会看（按权限与数据范围）

| 角色 | 看什么 |
|---|---|
| 管理层 | 整体收入、客流、风险、商户表现 |
| 运营 | 今日运行、核销、异常、第三方回流 |
| 财务 | 退款、差异、日结、结算依据 |
| 票务/酒吧/游乐负责人 | 各自业务表现 |
| 采购/库管/酒吧店长 | 采购周期、库存消耗、存酒、盘点差异 |
| 集团高层 | 按职位模板的汇总 / 下钻各项目明细 / 跨项目对标（数据隔离仍综合体级，见地产域 PRD 集团下钻口径） |

## 4. 口径与落地承接

- **下钻**：看板支持从总览下钻到各业务域明细；同一套经营事实、按权限和数据范围展示。
- **数据真实性**：收入/退款/对账类指标必须从业务与财务系统取数，不手填、不伪造；第三方渠道未接入前相关指标置灰或标注未接入，不展示伪造数据。
- **多综合体**：单综合体下全部归默认项目，project 维汇总=平台口径合计、不伪造多项目；多综合体推广前补按 project 行级隔离的 scoped 读（见 `unified-standards-baseline §D14.5`）。
- 落地承接：指标快照接口见 `p2-business-metric-snapshots-api-contract-v0.1.md`；聚合作业/口径见 `r5-spec-T12-dashboard-aggregation-dev-design-20260618.md`、`r5-aggregation-metrics-draft-20260618.md`；正式接口以 `docs/openapi/openapi-p0.yaml` 为准。

## 5. 验收要点

- 8 类指标均可在看板呈现，并能下钻到对应业务明细。
- 收入/退款/对账指标与财务对账日结口径一致（不另算一套）。
- 不同角色按权限看到不同范围，无越权可见。
- 第三方未接入能力的指标不展示伪造数据。
