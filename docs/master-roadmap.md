# 项目总路线图

本文档用于主线程总控，记录娱乐综合体管理系统的阶段目标、专项线程任务、依赖关系和验收标准。

## 1. 总体目标

建设一个支持娱乐综合体长期经营的管理平台，覆盖：

- 多商户、多业态、多主体管理。
- 票务、通票、权益、核销、结算。
- 酒吧、游乐设施、餐饮、零售、机器人、监控、企业微信等第三方协同。
- 员工管理手机、安卓平板、一体机等现场设备。
- 全链路留痕、动态鉴权、安全风控、经营分析。
- 支持后续按模块逐步开发、部署和运营。

## 3. 阶段路线

> 修订说明（2026-06-07）：本阶段划分为**长期路线（按业务域线性铺开）**，与"P0 最小闭环收敛"口径不同。**具体 P0/P1/P2 边界以 `p0-implementation-task-list.md` 为准**；本节阶段内出现的 NFC 真核销、机器人调度、视频监控、第三方对账、企微 AI 客户需求识别等能力，**其真实优先级见各行就地标注**，不要据本节阶段位置推断其为 P0。依据 finding pboundary-6、pboundary-2（NFC）、pboundary-4（机器人）、pboundary-1（企微AI），及《统一口径基准》P0 边界口径。
>
> 关键能力优先级统一口径（与 p0-implementation-task-list / 统一口径基准一致）：
> - **NFC**：P0 仅预留设备凭证字段与界面入口；二维码通过摄像头/扫码模块读取，NFC 仅读取外部 NFC 腕带、标签、卡或设备中的权益标识；员工身份改用**设备指纹/Keystore 凭证**（非手机本机 NFC，D8）；闸机/NFC 设备厂商深度联动 = P2。
> - **机器人**：交接留痕 = P0；真实调度与状态联动 = P2。
> - **视频监控**：P0 仅留点位/时间/设备以推导候选摄像头；真实调阅与自动绑定 = P1，AI 异常识别 = P2。
> - **第三方对账**：P0 做基础对账与留痕；真实供应商字段/签名/复杂补偿 = P1。
> - **企微 AI 客户需求/语义质检 = P2**（基础会话同步与每日归档为 P0；下游 AI 增强分析统一归 P2，见 pboundary-1）。
> - **市场基准增强项**：已归档市场基准与对抗式审计提出的商户服务工单、酒吧高级账单、游乐安全告知/电子免责/预约排队等能力，不自动扩大 P0。MDM/Android 设备管控、企微配置、P0 完整应收应付台账属于已确认 P0 能力；商户账单门户、催缴、费用异议和复杂费用规则进入 P1。

## 5. 跨线程同步规则

| 情况 | 处理方式 |
|---|---|
| 只影响单一模块 | 在对应专项线程处理 |
| 影响数据库公共表 | 回主线程确认 |
| 影响鉴权、安全、结算 | 回主线程确认 |
| 影响部署或服务器 | 同步到06线程 |
| 涉及前后端接口变更 | 同步到03和04线程 |
| 设计已确定 | 写入 `docs/` |
