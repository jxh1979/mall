## 二、通票分账链专项(5 规则复核·激活过账前必修)

按用户 2026-07-22 确认的分账模型逐条核代码,结论:2违反 + 2部分 + 1基本OK。

**① 综合服务费层 → 违反(基准错+主体未实现)· P0/P1** 【=R-3】
- 现:comp fee 每次核销触发 / 按 entitlement_type(权益类型) / 仅专属商户 / 记在商户侧(`SettlementSettledConsumer.java:74/76`、`JdbcSettlementBillRepository.java:238`、`V268:16`无ticket_type列、`SettlementSettledEvent.java:38`带ticketTypeId却从不参与费率)。
- 应:门票综合服务费 = 每票一道 / 按票种 / 所有门票 / 归项目公司 / 分账前先扣(先渠道抽成、再综合服务费)/ 各酒吧池分成月度结算结出。
- **开发**:新建门票综合服务费模型(按票种收、归项目公司),与现有"专属商户费"解耦(专属费改名为"专属结算费"或按裁决处理);配置维度 项目×商户×票种;动资金引擎·TDD+守恒·同步 PRD。

**② 入场/酒水拆分 → 归属方符合 / 金额待确认 · P2**
- 核销归商户:归属方对(无归错商户漏洞,18/18);未核归项目:对(过期归project、账单聚合天然排除、守恒二分)。
- 金额两模式:专属=内部结算价直付;非专属=进池按排名/客数/固定额分(当前全走非专属池化)。**符合用户模型(专属直付 + 非专属池化并存)**,现无专属合同属正常。
- **开发**:P3 隐患修——`SettlementExpiryJob.java:79` 未核销行冗余写 verified_amount_cent,当前靠读取方类型过滤才不双计,**置 0** 防未来无过滤 SUM 双计。

**③ 核销顺序(入场先于酒水) → 违反 · P1**
- 现:核销主链无守卫(`TicketVerificationService.java:456-690`),酒水与入场两独立行互不引用;`gift_drink`分支`:674-688`直接扣次发赠饮。

- **开发**:核酒水权益前强制校验"同订单/同商户入场权益已核",未核则拒(`ENTRY_NOT_VERIFIED`);离线旁路同守;HTML已写"入场先于酒水"作依据。
