## 3. 已确认执行口径与后续配置项

| 事项 | 已确认口径 / 后续配置 |
|---|---|
| 数据分析服务是否第一阶段即独立 Python 服务，还是 P0 先全部由 Java 后端完成 | 已确认：P0 先由 Java 后端完成指标、风控和规则质检；P2 再引入独立 Python AI 服务 |
| 企业微信最低管理成本方案 | 已确认：管理员一次性完成企业微信后台授权和密钥配置，系统自动做员工映射、同步、失败告警、基础规则质检和留存策略 |
| 指标刷新频率标准 | 已确认：P0 接口查询/手动刷新 + 短周期缓存；实时推送后置 |
| 风险预警通知渠道 | 已确认：P0 系统待办 + 企业微信通知，邮件兜底；短信仅用于严重风险或 P1 配置 |
| 财务差异容忍阈值 | 已确认：P0 平台统一默认阈值，合同/商户可覆盖，覆盖留痕 |
| AI模型使用方案 | 已确认：合同日期和敏感文本优先本地 AI 大模型辅助判断，人工确认；P2 再引入独立 Python AI 服务 |
| 餐饮零售第三方数据校验 | 已确认：Webhook + 定时轮询校验，供应商支持时增加日终全量文件兜底 |

## 4. 建议下一步

建议下一步配置：

1. P0 风控规则的默认阈值，例如核销失败次数、财务差异金额、库存报损金额。

3. 各商户/合同是否覆盖平台默认财务差异阈值。
