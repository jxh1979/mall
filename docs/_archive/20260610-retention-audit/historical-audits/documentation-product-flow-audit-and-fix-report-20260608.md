# 产品流文档复核与修复报告 V0.1

审查日期：2026-06-08  
审查对象：`complex-management-system/docs/` 全量文档、需求追溯矩阵、产品总纲、各层 PRD/页面清单/字段字典/验收清单。  
审查方法：按 Product Design 的角色与业务旅程视角，检查“用户原始需求 -> 产品总纲 -> 分层 PRD -> 页面/字段/流程/验收 -> 开发设计/数据库/迁移”的可接续程度；同时按 documentation-specialist/doc-coauthoring 检查外部机器智能体能否直接接手。本轮追加对抗式审计：假设外部实施方按最少上下文理解文档，专查会导致业务旅程断档的漏表、漏任务、漏验收点。

## 1. 总体结论

本轮产品流复核确认：文档主体已经覆盖综合体管理系统的 P0 产品设计基础，主要问题不是新增大缺口，而是 `requirement-traceability-matrix-v0.1.md` 中多处旧审查状态没有跟随后续修复同步，仍显示“部分覆盖/有待对齐”。本轮已把这些滞后项改为准确状态，并补强少量仍需写入总纲或 PRD 的业务口径。

## 2. 本轮修复

| 修复项 | 处理结果 |
|---|---|
| 餐饮/零售通票权益 | 在票务 PRD §6.1 补充“折扣型权益 discount”和“券核销型权益 voucher”区别，明确第三方餐饮/零售不自研 POS，真实回流和对账按 P1 接入 |
| 职级与权限关系 | 在产品总纲已确认规则 30 补明：职级只影响默认权限模板、审批层级建议和薪资大范围，不能替代单一功能权限点 |
| 需求追溯矩阵旧状态 | 将 REQ-05/06/11/25/43/50/55/56/57b/62/64/66/79/82/83/84/92 从旧“部分覆盖/有待对齐”更新为已覆盖、已裁决并覆盖或 P1/P2 预留 |
| 产品索引旧口径 | 将“员工身份、NFC、私人手机”改为“设备凭证”，避免误导为读取手机本机 NFC 唯一标识 |
> 本段规则已归口至 `docs/scope-wide-coding-rule-canonical-V0.01.md` §A-04，本文不再重复记载。
| P0 任务清单产品流断点 | 将供应链 P0、客人 App/小程序、订台定金、最低消费、积分兑换扣库存从 PRD/开发设计同步到 `p0-implementation-task-list.md` 的可分派任务 |
| 对抗式旅程断点 | 将票务动态二维码防伪凭证补成 `TKT-011` 独立任务；将会员兑换礼物库存补入 `DB-013 point_gifts`；客人端二维码展示 `CUST-003` 改依赖 TKT-011，避免“页面可展示但无法防伪验签”的断档 |
| 跨文档离线核销边界 | 将票务、Android、游乐、业务拆解、前端说明和路线图中的离线同步/冲突统一标注为 P1 预留、P0 不启用，避免业务旅程和票务在线核验规则冲突 |

## 3. 已核验闭环

| 产品旅程 | 覆盖结论 |
|---|---|
| 客人购票/预定/二维码/积分/兑换 | 已由客人 App/小程序开发设计、票务 PRD、积分表、礼物库存和兑换扣库存闭环承接 |
| 客人端 P0 分派 | 已补 CUST-001~006 和 FE-015，覆盖登录、购票、二维码、订台、积分兑换和 Web/H5 展示 |
| 票务防伪核销 | `ticket_credentials` 已在开发设计、数据库说明和迁移中落地，并由 `TKT-011` 独立承接编码任务；支持凭证哈希、防伪哈希、签名版本、刷新秒数、在线验签和事后核对 |
| 票务/终端/游乐核销边界 | P0 只做在线核验、容量扣减、人工放行和检修状态拦截；离线同步/离线冲突仅 P1 预留，不进入 P0 编码 |
| 平板点酒 | 明确只做酒吧点酒下单，不代客购票；绑定酒吧、卡座、最低消费和支付流程 |
| 供应链 P0 | 已补 SUP-001~006 和 FE-014，覆盖供应商、供应合同、采购、库房、库存、吧台消耗、存酒、盘点报损 |
| 工作手机与私人手机 | 工作手机负责企业微信、扫码核销和 MDM 管控；私人手机只做注册、通知、状态和设备凭证绑定，不做现场业务 |
| 商户/合同/区块/平面图 | 平台治理已纳入商场区块、铺位号、经营面积、合同摘要和准入拦截；平面图按 P1 预留 |
| 销售服务分析 | 已补销售归属率、卡座服务责任完整率、送达确认率、服务责任变更次数、异常首响时长的指标口径、页面、字段和验收 |
| 风控下钻 | `risk_rules.domain` 与 `risk_alerts.object_type` 已补 order/service/table_session/service_responsibility，责任链风险可定位 |
| 多综合体集团视图 | P0 保留 `project_id`，集团视图统一 P2，不阻塞单综合体闭环 |
