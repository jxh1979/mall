# 平台治理层完成审计报告 V0.1

## 1. 审计定位

本文档用于确认综合体管理系统“平台治理层”的产品设计文档是否已经达到进入后续模块拆解和编码设计的基础要求。

平台治理层的职责是先回答以下问题：
- 综合体有哪些项目、空间、区域和点位。
- 有哪些商户、运营主体和合作关系。
- 合同核心摘要如何变成业务准入、阻断和升级审批依据。
- 员工如何通过私人手机 App、设备凭证（设备公钥/不可逆设备指纹）、审核、职级和公司工作手机建立可信身份（"NFC"按 D8 改为设备凭证，2026-06-07 收口）。
- 谁是员工、谁有岗位、谁在什么时间承担什么责任。
- 哪些企业设备归谁管理、被谁领用、在哪里使用。
- 谁能看什么、操作什么、管理哪些数据范围。
- 关键配置和敏感操作如何留痕、复核和追溯。

本次审计只检查产品需求、页面结构、字段、流程、低保真说明和验收口径，不涉及编码、数据库、接口实现、服务部署和 160 机器操作。

## 7. 已确认规则和后续排期事项

已确认规则：

| 规则 | 影响 |
|---|---|
| 员工私人手机 App 安装期在设备 Keystore 生成设备公钥/不可逆设备指纹（device_key_fingerprint）作为唯一可信标识并绑定员工；废止"读取手机本机 NFC 唯一标识"（D8/A6，2026-06-07 收口，finding decision-land-1）。工作手机通过摄像头/扫码模块读取外部客人二维码；NFC 仅读取外部 NFC 腕带、标签、卡或设备中的权益标识 | 影响员工注册、设备可信和身份确认 |
| 员工换私人手机时必须先解绑旧手机，再绑定新手机 | 影响设备变更审计和账号安全 |
| Root、调试或异常环境以手机端可检测能力为准，异常则失效并进入复核 | 影响员工 App 可用性和现场合规 |
| 办公区私人手机寄存柜不绑定固定柜，员工先到先选，离开时全部取走 | 影响寄存柜流程和现场管理 |
| 员工职级可按 M1-M10 并细分上/中/下；职级只绑定薪资大范围，具体薪资单独填写 | 影响权限、审批层级和后续 HR/薪资对接 |
| 合同或基础定义违规全部先卡住流程，但允许按后台配置的更高级审核层级放行 | 影响票务、酒吧、游乐、第三方和结算流程 |
| 升级放行层级支持上一级、上两级或最高权限，放行原因、审批人和审批层级必须留痕 | 影响风控和审计 |
| 权限按单一功能最小颗粒度配置，支持角色级和员工级完全自定义 | 影响权限配置、审批和后续 SaaS 化能力 |
| 未来需要集团视图和跨项目汇总视图，但 P0 先保证所有对象带综合体项目归属 | 影响项目数据模型和管理层看板 |
