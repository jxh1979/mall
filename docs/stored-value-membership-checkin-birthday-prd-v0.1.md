# 储值、连续签到与生日权益边界 PRD V0.1

> 权限边界：本 PRD 只提供产品细化；三份业务 HTML 拥有最终业务解释权。其他文档、配置、代码和数据结构均不得覆盖 HTML；HTML 未记载的新规则须经用户批准并写入 HTML 后方可生效。

日期：2026-08-01

状态：现行边界文档

## 1. 文档定位

本文只定义储值入口、连续签到和生日权益与会员、成长值、积分之间的边界。

- 储值完整规则：`docs/member-loyalty-and-stored-value-product-prd-v0.1.md`。
- 会员与等级：`docs/member-and-tier-product-prd-v1.0.md`。
- 积分与虚拟券：`docs/points-and-voucher-product-prd-v1.0.md`。
- 营销成本：`docs/merchant-points-settlement-rules-v1.0.md`。

## 2. 储值入口

- 储值账户支持按有效规则充值、消费、退款、冻结和解冻。
- 储值充值本身不产生成长值或积分，也不刷新积分有效期。
- 储值余额实际支付形成的消费结果，按积分 PRD 细化规则并受三份业务 HTML 约束，判断是否计入有效消费。
- 储值余额、资金、退款和账户责任不属于会员或积分域。

## 3. 付费会员已废止

付费会员订阅已于 2026-07-18 废止。全国会员身份免费，签到、生日、储值卡或权益包均不得形成付费会员身份。

## 4. 连续签到

- 会员每日最多成功签到一次；同日重复请求必须幂等。
- **HTML 权威口径：客人每日签到记连续天数，按连续天数阶梯奖励积分**（BSM L810）。奖励随连续天数分档递增，档位、档位阈值与每档奖励值由版本化规则配置。
- 连续天数按系统有效规则累计，中断后的处理由版本化规则明确。
- 签到可以发放营销积分，但不得增加成长值。
- 签到积分不得刷新积分有效期。
- 签到奖励必须单独记为营销积分，并锁定活动、成本承担法律主体、预算、规则版本和来源终端。
- 缺少有效活动、预算、审批或成本承担主体时，不得发放签到积分。

## 5. 生日权益

### 5.1 HTML 权威口径

- **HTML 现行权威口径为「生日加倍」：生日当天或生日月消费积分加倍**（BSM L811；ENUM L72「连续签到、生日加倍」）。
- **当前积分域实现**：生日权益以**营销积分或虚拟券**承载，消费订单锁定的**基础积分公式不被改写**（见 §5.2）。
- **差距登记**：上述实现与 HTML「消费积分加倍」口径**存在待改造缺口**——HTML 要求的是生日窗口内**消费积分本身加倍**，而非另发营销积分或券。该缺口的**落地方式待运营细化**（含加倍倍率、适用窗口、成本承担主体与是否计入成长值），细化方案须经审批并版本化后方可上线。在改造落地前，按 §5.2 的现行约束执行，且不得对外宣称已实现「消费积分加倍」。

### 5.2 现行实现约束

- 生日权益以会员经核验的生日信息和系统有效活动规则为依据。
- 规则可以定义生日当天、当周或当月等适用窗口，但必须审批、指定期限并版本化。
- 生日活动可以发放虚拟券或营销积分。
- 生日营销积分必须与基础积分、等级加赠积分分开记账，不得改写消费订单锁定的基础公式。
- 生日权益不得增加成长值，也不得刷新积分有效期。
- 生日券的转赠、资格和核销按积分与虚拟券 PRD 的细化规则执行，并受三份业务 HTML 约束。
- 缺少预算、审批或成本承担主体时，不得发布或继续发放生日权益。

## 6. 成本与系统化

- 签到和生日权益属于营销活动时，费用支付方可以是商户、项目发起平台法律主体、全国平台或其他登记赞助主体。
- 多个承担方的固定额或比例分摊必须按商户积分结算 PRD 的细化规则配置并分别锁定预算；配置不得改变三份业务 HTML 确定的责任边界。
- 签到规则、生日规则、奖励、预算、成本承担、审批、生效时间和版本必须全部由系统承载。
- 线下表格、口头决定或硬编码默认值不能作为运行时真源。

## 7. 验收标准

1. 同日重复签到只成功一次。
2. 签到和生日奖励可以形成营销积分，但不产生成长值。
3. 签到、生日和储值充值均不刷新积分有效期。
4. 生日活动不改变基础积分公式或订单锁定版本。
5. 缺少成本承担主体或预算时不发放权益。
6. 付费会员订阅不会因储值、签到或生日权益被重新启用。
