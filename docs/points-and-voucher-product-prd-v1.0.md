## 1. 文档定位

本文承接积分获取、冻结、确认、有效期、扣减、追回、积分商城、兑换订单、虚拟券、转赠与核销的现行业务规则并提供产品细化。与三个最高业务解释权 HTML 不一致时以 HTML 为准；本文新增而 HTML 尚未记载的规则，在用户批准并写入相应 HTML 前不生效。

以下规则的产品细化见：

- 会员身份、成长值、等级和等级倍率资格：`docs/member-and-tier-product-prd-v1.0.md`。
- 积分发行单价、项目价格、兑换下限、商户补偿和账期：`docs/merchant-points-settlement-rules-v1.0.md`。

其他文档可以引用本文作为产品细化资料，但不得据此覆盖三个 HTML。

## 2. 目标与非目标

### 2.1 目标

- 建立全国统一积分余额和逐笔可追溯账本。
- 区分商户消费积分与票务积分：前者按商户所属业态规则计算，后者按票种或票务产品规则计算，并分别锁定订单使用的规则版本。
- 用冻结期保证正常退款发生时积分尚不可使用。
- 明确账户活跃有效期、待追回机制和兑换限制。
- 统一“兑换成功必发虚拟券、发券不结算、核销才补偿”的业务链路。

### 2.2 非目标

- 积分不得用于普通收银抵现。
- 本文不定义会员等级门槛或成长值计算。
- 本文不定义商户实际补偿金额或价格下限；账期与收付的**骨干规则**在 §11A 登记，具体计费、开票与税务细则见 `docs/merchant-points-settlement-rules-v1.0.md`。
- 本文不规定代码、接口、数据库或页面实现。

## 3. 统一术语

| 术语 | 定义 |
|---|---|
| 积分 | 会员可在积分商城使用的权益单位，与成长值分别记账。 |
| 业态积分获取规则 | 平台按商户所属业态全国统一配置的“每 1 积分所需消费金额”。 |
| 有效消费金额 | 会员优惠后实际支付且符合本文口径的金额。 |
| 基础积分 | 按有效消费金额和业态规则计算的整数积分。 |
| 等级加赠积分 | 按基础积分和会员等级倍率计算的额外积分。 |
| 营销积分 | 不并入消费基础公式、按活动成本承担关系独立记账的积分。 |
| 待追回积分 | 已确认积分使用后发生特殊退款等事件形成的后续抵扣额度；不是负余额或现金债务。 |
| 积分商城 | 积分唯一允许消费的商城场景。 |
| 兑换订单 | 会员提交纯积分或积分加现金兑换后形成的业务单据。 |
| 虚拟券 | 兑换成功后生成、代表后续商品提取或服务履约资格的电子权益。 |
| 发券 | 扣除积分、预占库存或履约能力并生成虚拟券。 |
| 核销 | 商户实际完成商品交付或服务履约，预占转为实际消耗。 |

## 4. 角色与职责

| 角色 | 职责 |
|---|---|
| 会员 | 查看积分、发起兑换、持有或按券种规则转赠虚拟券。 |
| 全国平台 | 配置全国业态积分规则、有效期和最低刷新金额，审批并版本化。 |
| 项目 | 维护商户与项目关系、组织积分商城方案，不得覆盖全国业态规则。 |
| 商户 | 绑定有效业态、提交消费与退款事实、履约和核销。**凡纳入会员计划覆盖范围的在营商户，必须参加积分计划并强制发放消费积分**，不得私自关闭发分或修改发放比例（义务清单见 §6.1）。 |
| 活动发起方 | 配置营销积分及成本承担关系，锁定预算。 |
| 全国积分结算中心 | 接收已确认积分与已核销券的结算事实；具体费用规则见商户积分结算产品细化文档。 |

## 5. 积分账户与账本

- 全国会员使用一个可用积分余额，不按城市或项目拆成会员可消费子余额。
- 每笔积分必须保留会员、项目、商户、订单、积分类型、数量、发生时间、状态、规则版本和成本承担主体。
- 基础积分、等级加赠积分、营销积分必须分开记账。
- 账本记录不得因余额汇总、项目切换、退款或过期而被覆盖或删除。
- 积分余额不可转赠、提现或折现。

## 6. 商户消费与票务积分获取规则

### 6.1 全国统一配置

- 平台按业态配置“每 1 积分所需消费金额”。
- 同一业态在全国所有项目使用同一有效规则版本。
- 配置必须包含业态、每 1 积分所需消费金额、审批记录、生效时间和版本。
- 每个商户必须绑定一个有效业态并继承该业态规则。
- 项目和商户均不得新增本地覆盖值或自行修改。
- 商户缺少有效业态或有效规则时，会员积分能力不得启用，不能使用默认猜测值。
- **商户强制参加义务（依据 ENUM「积分与成长值来源」条·实测 L65）**：**凡纳入会员计划覆盖范围的在营商户，必须参加积分计划并强制发放消费积分**。义务包括：**接入会员系统、识别会员、按后台配置发放消费积分与成长值、接受退款冲减与审计、按规则结清积分相关费用**。**商户不得私自关闭发分，也不得私自修改发放比例**——关闭或改比例只能由平台按已审批生效的全国规则版本执行。
- **本条作为入驻条件之一写入入驻／租赁协议与会员计划协议**。入驻签约环节属**招商与租赁域**，交叉引用 `docs/leasing-acquisition-prd-v1.0.md` §6「线索→正式商户档案（签约转换）」与 §6A「签约后到期/变更/退出衔接」；**协议条款文本、合同变更与违约处置**属**地产全链域**，交叉引用 `docs/real-estate-full-chain-domain-prd-v0.1.md` §2「租赁全生命周期」（合同生命周期、违约金与欠费处置）。本文只登记积分侧的强制义务口径，**不重复定义协议条款**。（2026-08-04 F-FIN 交叉引用更正：原文把协议条款与违约处置整体指向 leasing PRD，而该 PRD 正文无协议条款/违约处置内容）

### 6.2 有效消费金额

有效消费金额是会员优惠后的实际支付金额。

计入：

- 现金；
- 银行卡；
- 微信支付；
- 支付宝；
- 储值余额支付。

不计入：

- 优惠券减免；
- 平台补贴；
- 商户折扣；
- 积分加现金兑换的积分部分；
- 积分加现金兑换的现金部分。

积分加现金兑换整单排除，不属于有效消费，不产生基础积分、等级加赠积分或成长值，也不刷新积分有效期。

### 6.3 票务积分规则

- 票务订单不读取商户所属业态的积分规则。
- 票务系统只提交票务订单、支付、履约、退款、冲正和核销事实；积分域按票种或票务产品已审批生效的积分规则计算票务积分，会员与等级域按独立的票务成长值规则计算成长值。
- 任一票务规则缺失时不得回落到商户业态规则或另一套成长值、积分规则猜算。
- **成本口径**：票务积分的发行成本——该发行成本在域间拆分之前从整单扣除且只扣一次，由各域按分配份额自然共担，不由该笔业务的收款主体单独承担，也不向核销环节的提供商户另行分摊（与通路费同机制，照 ENUM「跨域通票分配」条）。口径与 §7.2「票务例外」一致；另见 ticketing PRD §12B.2、BSM「酒吧通票可分配池的池金额」条·实测 L746、ENUM「酒吧通票可分配池」条·实测 L48。
  - 2026-08-05 用户裁决：原"收款主体承担"表述与 HTML 整单预扣机制矛盾（二次计费），已更正为共担口径（DEC-R7 第二批裁决）
- 多人票中的每一人次视为一张完整票；多次票的每一次有效核销人次视为一张完整票。退款、冲正和重复核销按对应人次处理，不得把整张父票只计算一次，也不得把同一人次重复计算。

## 7. 消费积分计算

### 7.1 公式

每个订单独立计算：

```text
基础积分 = floor(本单有效消费金额 ÷ 业态每1积分所需消费金额)
等级加赠积分 = floor(基础积分 × (会员等级倍率 - 1))
本单消费积分 = 基础积分 + 等级加赠积分
```

- `floor` 表示向下取整。
- 小数积分和不足 1 积分的消费金额不跨订单累计。
- 等级倍率来自消费时会员有效等级，等级资格见会员与等级产品细化文档。
- **等级倍率 ≥ 1（硬约束）**：倍率小于 1 会使 `等级加赠积分` 为负、本单消费积分**少于**基础积分，与「等级**加赠**」语义相反。**倍率 < 1 的等级规则版本不得生效**；倍率 = 1 时等级加赠积分为 0。本约束与 `docs/member-and-tier-product-prd-v1.0.md` §9、§7.2 同步。

### 7.2 成本归属和分账

- 基础积分与等级加赠积分分别记账。
- 两者成本均由发生消费的商户承担。
- 等级倍率由全国平台统一配置、审批、生效和版本化，商户不得另行约定倍率或倍率上限；缺少全国有效倍率版本时不得发放等级加赠积分。
- 营销活动额外积分单独记账，不并入基础公式，成本按活动发布时锁定的法律主体承担。
- **票务例外（本节「成本由发生消费的商户承担」不适用于票务积分）**：票务订单产生的积分发行成本（基础积分与等级加赠积分）——该发行成本在域间拆分之前从整单扣除且只扣一次，由各域按分配份额自然共担，不由该笔业务的收款主体单独承担，也不向核销环节的提供商户另行分摊（与通路费同机制，照 ENUM「跨域通票分配」条）。依据 BSM「酒吧通票可分配池的池金额」条·实测 L744、ENUM「酒吧通票可分配池」条·实测 L48；交叉引用 `docs/ticketing-entitlement-checkin-product-prd-v0.1.md` §12B.2「渠道费用两层结构与积分发行成本」。
  - 2026-08-05 用户裁决：原"收款主体承担"表述与 HTML 整单预扣机制矛盾（二次计费），已更正为共担口径（DEC-R7 第二批裁决）
- 只有积分转为可用时，基础积分和等级加赠积分才形成相应商户积分发行费。

### 7.3 规则版本锁定

订单必须锁定：

- 商户所属业态；
- 业态积分规则版本；
- 会员等级倍率版本；
- 特殊固定积分规则版本（如适用）；
- 项目、商户和成本承担主体。

配置变化不得追溯改变已形成订单的计算结果。

### 7.4 票务产品与商户消费规则边界

- 票种或票务产品只能使用自身已配置、已审批并已生效的固定积分规则，不得套用商户业态公式。
- 商户消费按商户所属业态公式；商户不得自行新增或改变全国业态规则。
- 积分规则和成长值规则分别配置，任何一方不得从另一方反推；缺少对应有效规则时该项不计算，不得回落猜算。

### 7.5 计算示例

示例一：业态规则为每 10 元 1 积分，会员折后实际支付 99 元，等级倍率 1.5。

```text
基础积分 = floor(99 ÷ 10) = 9
等级加赠积分 = floor(9 × (1.5 - 1)) = 4
本单消费积分 = 9 + 4 = 13
```

剩余 9 元不带入下一订单。

示例二：商品公开价 100 元，商户折扣 10 元，优惠券减免 20 元，会员以微信支付 70 元，则有效消费金额为 70 元；折扣和券减免不计入。

示例三：会员以 1,000 积分加 20 元现金兑换虚拟券，整单有效消费金额为 0，不产生消费积分或成长值。

## 8. 冻结、确认与退款

### 8.1 状态

| 状态 | 含义 | 是否可用 |
|---|---|---|
| `PENDING` | 消费已记录，关联积分在退款期内冻结。 | 否 |
| `AVAILABLE` | 履约完成且退款期结束，积分已确认。 | 是 |
| `CONSUMED` | 已用于积分商城兑换。 | 否 |
| `CANCELLED` | 退款、取消或纠错已撤销该笔积分。 | 否 |
| `EXPIRED` | 超过账户活跃有效期。 | 否 |

待追回积分是独立追偿额度，不以负数写入 `AVAILABLE` 余额。

**退回积分的账本落点（2026-08-04 补）**：因合规取消、商户无法履约或平台原因作废而**退回积分**时（见 §11.2）——

1. **新建一条 `AVAILABLE` 积分流水**承载退回额度；
2. 该流水**继承原兑换所消耗积分的到期日**，**不因退回而延长有效期**（否则「兑换后再退回」将成为无限续期的后门）；
3. **原 `CONSUMED` 流水不得改写、不得回退为 `AVAILABLE`**——兑换与退回是两个独立事实，各留各的账本行，以保证逐笔可追溯；
4. **原积分在退回时点已过期的**：退回流水**照建但直接落 `EXPIRED`（不可用）**，并留痕「原积分已过期」这一原因，**不得为其重设新的到期日、不得按当前时点重新计算有效期**。是否另行以营销积分或券补偿，属活动裁量，须单独审批并锁定预算，**不由本条自动发生**。

退回流水必须关联原兑换订单、原扣减明细、原因和审批记录（与 §11.2 一致）。

### 8.2 正常确认

- 消费关联积分先进入 `PENDING`。
- 履约完成并超过对应业务退款期后转为 `AVAILABLE`。
- 只有 `AVAILABLE` 积分可兑换。
- 只有转为 `AVAILABLE` 的消费积分形成商户积分发行费。

### 8.3 退款期内退款

- 全额退款取消该订单全部 `PENDING` 积分。
- 部分退款使用原订单锁定的业态规则和等级倍率版本，按退款后保留的有效消费金额重新计算。
- 原冻结积分与重算结果的差额转为 `CANCELLED`。
- 正常退款发生在冻结期内，因此不存在会员已使用该笔积分的情况。

示例：原有效消费 100 元，每 10 元 1 积分，等级倍率 1.5，原积分为 15。退款后保留有效消费 60 元：

```text
重算基础积分 = floor(60 ÷ 10) = 6
重算等级加赠积分 = floor(6 × 0.5) = 3
保留积分 = 9
取消积分 = 15 - 9 = 6
```

### 8.4 确认后特殊退款

确认后只有特殊退款、拒付、欺诈或系统纠错进入追偿流程：

1. 按原订单版本重算应保留积分。
2. 优先追回尚未使用的关联积分。
3. 不足部分记入待追回积分。
4. 后续新获得积分先自动抵扣待追回积分。**抵扣时点为该笔新积分由 `PENDING` 转 `AVAILABLE` 之时**，**不在 `PENDING` 阶段抵扣**——`PENDING` 积分仍可能因退款期内退款被取消，提前抵扣会造成待追回额度被错误冲减。每次抵扣须逐笔留痕，关联被抵扣的待追回额度与来源积分流水。
5. 待追回积分清偿前禁止兑换。

可用积分余额不得为负，待追回积分不构成会员现金债务。

**待追回积分的四类出口（2026-08-04 第三轮用户裁决 HC-09 / DEC-R6-22 定稿，已写入 ENUM「有效消费与冻结」条）**：待追回额度**只有以下四个出口，除此之外不得以任何其他方式消除**——

1. **追平**：后续新获得积分依次抵扣待追回额度，**抵扣至清零后自动解除兑换限制并留痕**（抵扣时点仍为 `PENDING` → `AVAILABLE` 之时，见上款第 4 条）。
2. **小额豁免**：**不超过豁免线的**待追回额度由**财务豁免并留痕**——豁免线为**业务参数、全平台统一可配、须同时配置上下限，出厂默认 100 积分及以下**。超过豁免线的不得豁免。
3. **不设时效**：未清偿的待追回额度**一直挂账，不因时间流逝自动消灭**；**不得设置自动时效清零或按期归零**。会员长期不消费导致的长期挂账属正常状态，不作处理。
4. **会员注销**：注销时待追回额度**作废登记、不形成现金债权，也不再追偿**（与 `docs/customer-app-miniapp-product-prd-v0.1.md` §3A「注销时积分、券、未核销的票一律清零」并行；作废须留登记痕迹，不得静默删除）。

> 原 C 类登记 AUD C-24「出口未定义」**已关闭**。**实现改造列入排期**：小额豁免的财务操作入口与豁免线配置、注销时的待追回作废登记，当前均无承载，属待改造缺口（登记见修复台账 §7.4）。除上述四条外，**仍不得由任何岗位手工核销待追回额度**。

## 9. 积分有效期

### 9.1 账户活跃有效期

- 积分采用**账户活跃有效期（滚动有效）**：会员在窗口内有过一次合格消费的，其名下积分**全部保持有效、不过期**；窗口内没有任何合格消费的，积分过期。**该窗口为业务参数，全平台统一可配，出厂默认十二个月，可配置为六个月或三个月，须同时配置上下限**（依据 ENUM「积分明细类型」条·实测 L70）。
- 只有**单笔金额达到后台配置的最低消费金额**的有效付费消费，才刷新全部尚未过期积分的有效期。**该最低金额为业务参数，全平台统一可配，出厂默认 10 元，须同时配置上下限**；未达该最低金额的消费不刷新有效期。
- **不设静默回落**：有效期窗口或最低金额**缺少有效配置版本时，不得按任何默认值静默运行**——须阻断相关能力（不执行过期判定、不刷新有效期）并告警，由平台补齐配置后恢复。本文各处出现的「十二个月」「10 元」**均为出厂默认值，实际以生效版本为准**。
- 项目和商户不得降低平台最低金额或设置本地刷新规则。

### 9.2 不刷新事件

以下事件均不刷新积分有效期：

- 注册或登录；
- 签到；
- 生日；
- 营销奖励；
- 积分兑换；
- 储值充值；
- 押金；
- 零元订单；
- 退款订单；
- 积分加现金兑换。

### 9.3 规则变更与过期

- 有效期规则变更必须审批、通知、指定生效时间并版本化。
- 新规则不得追溯缩短会员当前有效期。
- 积分过期后不恢复；之后发生合格消费，只为当时尚有效积分刷新有效期，并为新积分建立有效期。
- 过期处理必须保留积分来源、原到期时间、过期时间和规则版本。

## 10. 积分商城与兑换

### 10.1 唯一使用场景

- 积分只能用于积分商城。
- 酒吧、游乐、餐饮、零售、门票及其他普通收银交易不得直接用积分抵扣现金。
- 商城支持纯积分兑换和积分加现金兑换。
- 兑换定价与下限见商户积分结算产品细化文档。

### 10.2 兑换前置条件

兑换必须同时满足：

- 会员身份允许使用权益；
- 可用积分足够；
- 待追回积分为 0；
- 兑换方案、价格和规则版本有效；
- 库存或履约能力充足；
- 所需预算已锁定；
- 券种资格和适用范围满足；
- **该项目该商品的内部结算价 ≥ 积分兑换结算单价（不倒挂）**——发券前须逐笔校验，倒挂即拒绝发券（依据 ENUM「发券与核销结算」条·实测 L74：「发券前须校验内部结算价不低于积分兑换结算单价、不得倒挂」）。

任一条件不满足时不得发券。

### 10.3 发券

- 每次成功兑换均生成虚拟券，不直接形成已履约订单。
- 发券时正式扣除积分并预占库存或履约能力。
- 发券锁定项目、商户、券种、兑换方案和关联版本。
- 发券不形成商户补偿应收，不与商户结算。
- 重复提交必须由业务幂等控制，只允许成功一次。
- 同一种兑换券默认允许同一会员多次兑换；只有兑换方案明确配置“每会员累计兑换次数上限”时才限制。次数校验以会员、券种、有效方案和累计成功发券记录为准，幂等拦截不等同于累计次数上限。
- **倒挂商品不得上架兑换（硬闸）**：内部结算价低于积分兑换结算单价的商品，**不得上架积分商城兑换方案、不得发券**（ENUM「发券与核销结算」条·实测 L74）。**该闸为硬闸，不得经 §11A.3 的破线审批绕过**——破线审批只处理「兑换方案低于项目零售参考价下限或内部结算价下限」的定价情形，**不授权发布或发售倒挂商品**；已上架商品事后出现倒挂的，须立即下架该兑换方案，已发未核销券按 §11.2 处理。

### 10.4 核销

- 核销表示商户实际完成商品交付或服务履约。
- 核销时预占库存转为实际消耗。
- 只有实际核销或完成履约才形成商户补偿事实。
- 重复核销不得重复扣库存或重复形成补偿。
- 商户补偿计算见商户积分结算产品细化文档。
- 核销或完成履约后，该券转为“已核销（已使用）”，从可用券列表移出但保留在历史记录中；不得再次核销、兑换、转赠或恢复为可用。重复核销必须拒绝且不得重复扣库存或结算。

## 11. 虚拟券

### 11.1 券种要求

每一券种必须明确：

- 履约主体；
- 适用项目、商户、商品或服务；
- 核销条件；
- 有效期；
- 是否允许转赠；
- 是否具有实名、年龄、等级或其他资格限制；
- 到期、取消和作废处理；
- 库存或履约能力来源。

### 11.2 到期、取消与作废

- 券到期、取消或作废时释放未核销预占。
- 到期原则上不退积分。
- 合规取消、商户无法履约或平台原因作废时退回积分。
- 退回积分必须关联原兑换订单、原扣减明细、原因和审批记录。
- 已核销券不得按未履约规则重复退回积分。
- 退回积分的**账本落点**（新建 `AVAILABLE` 流水、继承原到期日、原 `CONSUMED` 行不变、原积分已过期时落 `EXPIRED`）见 **§8.1**。
- 会员端券包只按“可用、已核销（已使用）、已过期、已失效”分组。“已失效”包括合规取消、商户无法履约、平台纠错或风控撤回；详情必须展示失效原因、处理时间以及积分是否退回，不使用含义重叠的“已取消 / 已作废”作为并列会员端分组。

### 11.3 转赠

- 积分余额不可转赠。
- 虚拟券是否可转赠由券种配置，默认不可转赠。
- 实名认证、年龄、等级或资格限定券强制不可转赠。
- 转赠不改变券有效期、库存、结算条件、项目归属或来源。
- 转赠必须保留转出人、接收人、时间、券状态和资格校验记录。

## 11A. 积分结算账期与总额收付（骨干规则）

细则见 `docs/merchant-points-settlement-rules-v1.0.md`；本节只登记不得被下游文档覆盖的骨干口径。

### 11A.1 账期参数

- 账期参数由**全国积分结算中心统一配置、审批和版本化**。
- 初始规则：**自然月计费、次月出账、十个工作日异议期、异议期届满后的下一个付账日（付账日为业务参数，全平台统一可配，初始为每月 5 日、15 日、25 日）完成上月收付款**，遇**法定节假日或非银行工作日顺延**（2026-08-06 按 ENUM「积分结算账期」条·实测 L77 同步，**DEC-R8-01**）。
- 参数变更**只影响未来账期**，**不追溯已生成或已封账账单**；**项目和商户不得覆盖**。

### 11A.2 总额分别记账与收付（不得轧差）

- 双方应收应付先**各自按总额分别记账**：**商户应收的兑换补偿**与**平台应收的积分发行费**，**各自全额挂账、各自开票**。
- **一律按各自总额分别收付，不得轧差**（因涉及税务处理）。
- **平台内部各主体之间的应收应付同例。**

### 11A.3 兑付系数与破线审批

- 积分兑换结算单价 ＝ 全国统一积分发行单价 × 全国统一平台**兑付系数**；兑付系数为业务参数，**全平台统一可配，出厂默认 0.7**，**仅用于定价覆盖校验**，不作为商户补偿金额。
- 兑换方案低于项目零售参考价下限或内部结算价下限（破线）时，必须填写**七项**：**原因、目标、期限、数量、缺口、成本承担主体、预算**，由**全国积分结算中心授权岗位审批**；**预算不足不得发券**。
- **破线审批的边界（不适用于倒挂）**：破线审批**只覆盖「低于项目零售参考价下限或内部结算价下限」的定价破线**。**内部结算价低于积分兑换结算单价的倒挂商品，一律不得上架兑换、不得发券**，该**硬闸不可由上述七项破线审批绕过**（ENUM「发券与核销结算」条·实测 L74：「倒挂的商品不得上架兑换」）。

## 12. 跨领域业务流

1. 合格消费完成后，成长值按会员与等级规则入账，消费积分进入 `PENDING`。
2. 退款期内退款时，按原版本重算并取消差额冻结积分。
3. 退款期结束后，积分转为 `AVAILABLE`，同时形成商户积分发行费事实。
4. 会员兑换时扣除积分、预占库存并发券，此时不产生商户补偿。
5. 虚拟券核销后预占转为实际消耗，并把核销事实交给结算域计算商户补偿。
6. 券到期、合规取消或作废时释放预占；只有符合本文条件时退回积分。

## 13. 异常控制与审计证据

- 消费、退款、确认、发券、转赠、核销、退积分和追回必须具备业务幂等性。
- 商户消费缺少有效业态规则、票务缺少对应票务规则，或缺少全国倍率版本、价格、库存、预算、审批时，不得生效，且不得跨规则回落猜算。
- 积分不足、库存不足、预算不足或存在待追回积分时，禁止兑换。
- 已生效规则和已发券记录不得被新配置覆盖。
- 系统不得静默修正积分、库存或状态差异；必须形成可追溯调整记录。
- 审计证据至少包含主体、时间、会员、项目、商户、订单、券、数量、原状态、新状态、规则版本、原因、申请和审批。

## 14. 顺从性验收

1. 同一业态在不同项目使用相同的“每 1 积分所需消费金额”，项目和商户不能覆盖；票务订单只使用已生效票务规则，不读取业态规则。
2. 现金、银行卡、微信、支付宝和储值余额计入有效消费；优惠券减免、平台补贴和商户折扣不计入。
3. 积分加现金兑换整单不产生积分、成长值或有效期刷新。
4. 基础积分、等级加赠积分分别取整、分别记账，余数不跨单累计。
5. 订单锁定业态规则和等级倍率版本；配置变化不追溯。
6. 部分退款按保留的有效消费金额和原版本重算。
7. 正常退款在冻结期内取消积分，不出现已使用积分追偿。
8. 确认后特殊退款不足追回时形成待追回积分，但可用余额不为负、会员不形成现金债务。
9. 只有**单笔达到后台配置最低消费金额**的合格消费刷新尚有效积分；**出厂默认门槛 10 元、出厂默认有效期十二个月（可配置为六个月或三个月），两项均须同时配置上下限**；**缺少有效配置版本时阻断并告警，不得按默认值静默回落**。
10. 发券扣积分并预占库存但不结算；核销才把预占转为消耗并形成补偿事实。
11. 积分不可转赠；券默认不可转赠，资格型券强制不可转赠。
12. 券到期通常不退积分，合规取消、商户无法履约或平台作废时退回。
13. 多人票和多次票按每一有效核销人次分别计算票务积分和成长值，同一人次不重复计算。
14. 同一种券默认可重复兑换，仅在方案配置会员累计次数上限时限制；券核销后进入已核销（已使用）终态并不可再次使用。
15. 会员端券包只分为可用、已核销（已使用）、已过期和已失效，失效原因及积分退回结果可见。

## 15. 对抗性验收

| 反例 | 必须结果 |
|---|---|
| 项目为高价值商户设置更低积分获取门槛 | 阻断；继承全国业态规则。 |
| 商户未绑定业态仍发积分 | 阻断积分能力，不猜测默认值。 |
| 把券减免或平台补贴计入有效消费 | 判为不合规并按实际支付重算。 |
| 两笔不足 1 积分的订单合并余数 | 阻断；每单独立取整。 |
| 退款使用当前新规则重算历史订单 | 阻断；必须使用订单锁定版本。 |
| 退款期内积分提前可用 | 阻断；保持 `PENDING`。 |
| 待追回积分写成负余额或现金欠款 | 判为不合规；使用独立追偿额度。 |
| 登录、签到或充值刷新积分有效期 | 阻断；均非合格消费。 |
| 发券即生成商户补偿 | 判为不合规；核销前补偿为 0。 |
| 重复发券或重复核销 | 幂等拦截，只认一次。 |
| 资格型券配置为可转赠 | 配置不允许生效。 |
| 券到期自动退积分 | 阻断；除已批准例外外不返还。 |

## 16. 完成标准

- 本文完整承接积分获取、冻结、确认、退款、有效期、追回、兑换和虚拟券的产品细化，但不取得高于三个 HTML 的解释权。
- 计算公式、取整、版本锁定和退款重算可由业务样例复现。
- 发券、库存和核销补偿时点无歧义。
- 所有规则、参数、审批、状态和版本均被要求由系统承载。
