## 1. 文档定位

本文承接积分获取、冻结、确认、有效期、扣减、追回、积分商城、兑换订单、虚拟券、转赠与核销的现行业务规则并提供产品细化。与三个最高业务解释权 HTML 不一致时以 HTML 为准；本文新增而 HTML 尚未记载的规则，在用户批准并写入相应 HTML 前不生效。

以下规则的产品细化见：

- 会员身份、成长值、等级和等级倍率资格：`docs/member-and-tier-product-prd-v1.0.md`。
- 积分发行单价、项目价格、兑换下限、商户补偿和账期：`docs/merchant-points-settlement-rules-v1.0.md`。

其他文档可以引用本文作为产品细化资料，但不得据此覆盖三个 HTML。

## 2. 目标与非目标

### 2.1 目标

- 建立全国统一积分余额和逐笔可追溯账本。
- 区分商户消费积分与票务积分：前者按商户所属业态规则计算，后者按票种或票务产品规则计算，并分别锁定订单使用的规则版本。
- 用冻结期保证正常退款发生时积分尚不可使用。
- 明确账户活跃有效期、待追回机制和兑换限制。
- 统一“兑换成功必发虚拟券、发券不结算、核销才补偿”的业务链路。

### 2.2 非目标

- 积分不得用于普通收银抵现。
- 本文不定义通用会员等级门槛或非票务成长值计算；票务成长值只承接与票务积分分账所必需的 HTML 边界。
- 本文不定义商户实际补偿金额或价格下限；账期与收付的**骨干规则**在 §11A 登记，具体计费、开票与税务细则见 `docs/merchant-points-settlement-rules-v1.0.md`。
- 本文不规定代码、接口、数据库或页面实现。

## 3. 统一术语

| 术语 | 定义 |
|---|---|
| 积分 | 会员可在积分商城使用的权益单位，与成长值分别记账。 |
| 业态积分获取规则 | 按商户业态配置、由对应域主管公司审批后按批准版本在全国生效的“每 1 积分所需消费金额”；“全国有效”描述适用范围，不把审批权改交全国平台。 |
| 有效消费金额 | 会员优惠后实际支付且符合本文口径的金额。 |
| 基础积分 | 按有效消费金额和业态规则计算的整数积分。 |
| 等级加赠积分 | 按基础积分和会员等级倍率计算的额外积分。 |
| 营销积分 | 不并入消费基础公式、按活动成本承担关系独立记账的积分。 |
| 待追回积分 | 已确认积分使用后发生特殊退款等事件形成的后续抵扣额度；不是负余额或现金债务。 |
| 积分商城 | 积分唯一允许消费的商城场景。 |
| 兑换订单 | 会员提交纯积分或积分加现金兑换后形成的业务单据。 |
| 虚拟券 | 兑换成功后生成、代表后续商品提取或服务履约资格的电子权益。 |
| 发券 | 扣除积分、预占库存或履约能力并生成虚拟券。 |
| 核销 | 商户实际完成商品交付或服务履约，预占转为实际消耗。 |

## 4. 角色与职责

| 角色 | 职责 |
|---|---|
| 会员 | 查看积分、发起兑换、持有或按券种规则转赠虚拟券。 |
| 全国平台 | 统一规定等级倍率，配置积分有效期和最低刷新金额并审批、版本化；承载经对应域主管公司批准的业态积分获取规则按版本在全国生效，不得改写该业态规则。 |
| 项目 | 维护商户与项目关系、组织积分商城方案，不得覆盖经批准并在全国生效的业态积分获取规则。 |
| 商户 | 绑定有效业态、提交消费与退款事实、履约和核销。**凡纳入会员计划覆盖范围的在营商户，必须参加积分计划并强制发放消费积分**，不得私自关闭发分或修改发放比例（义务清单见 §6.1）。 |
| 活动发起方 | 配置营销积分及成本承担关系，锁定预算。 |
| 全国积分结算中心 | 统一配置全国积分发行单价、全国兑付系数和积分结算账期，并接收已确认积分与已核销券的结算事实；具体费用规则见商户积分结算产品细化文档。 |

## 5. 积分账户与账本

- 全国会员使用一个可用积分余额，不按城市或项目拆成会员可消费子余额。
- 每笔积分必须保留会员、项目、商户、订单、积分类型、数量、发生时间、状态、规则版本和成本承担主体。
- 基础积分、等级加赠积分、营销积分必须分开记账。
- 账本记录不得因余额汇总、项目切换、退款或过期而被覆盖或删除。
- **从消费单据可以反查该单产生的积分与成长值记录**（与积分明细的单据关联**双向可查**）（2026-08-19 补，依据 BSM「明细类型」条 / ENUM「积分明细类型」条现文；DEC-R8-97-21）。
- 积分余额不可转赠、提现或折现。

## 6. 商户消费与票务积分获取规则

### 6.1 业态规则审批与全国生效

- “每 1 积分所需消费金额”是按商户业态配置的业务参数，由该业态对应域主管公司审批；须同时配置上下限（依据 BSM「积分与成长值获取」条、PGM「域主管公司」条及 DEC-R8-93）。
- 获批业态规则按版本在全国生效；“全国有效”是适用范围，不把审批权改交全国平台。项目和商户均不得新增本地覆盖值或自行修改。
- 配置必须包含业态、每 1 积分所需消费金额、该金额的上下限、对应域主管公司审批记录、生效时间和版本。
- 每个商户必须绑定一个有效业态并继承该业态已审批生效的规则。
- 商户缺少有效业态、缺少对应域主管公司审批记录或缺少已生效规则版本时，基础积分不得猜算；系统须阻断该积分计算并告警补齐规则。
- **商户强制参加义务（依据 ENUM「积分与成长值来源」条）**：凡纳入会员计划覆盖范围的在营商户，必须参加积分计划并强制发放消费积分。义务包括：接入会员系统、识别会员、按已审批生效的业态规则发放消费积分与成长值、接受退款冲减与审计、按规则结清积分相关费用。商户不得私自关闭发分，也不得私自修改发放比例；比例变更须由对应域主管公司审批新版本后生效。
- 会员已被正确识别且消费符合规则时，系统自动计算基础积分并先记入 `PENDING`；不得增加商户申请、同意、逐笔确认或内部结算价获批前置。积分转为 `AVAILABLE` 后才形成积分发行费，不在 `PENDING` 阶段收费。
- **责任分界**：业态“每消费多少元产生 1 积分”由对应域主管公司审批；全国积分发行单价、全国兑付系数和积分结算账期由全国积分结算中心负责；等级倍率由全国平台统一规定。不得把这些参数笼统归给同一个主体。
- **本条作为入驻条件之一写入入驻／租赁协议与会员计划协议**。入驻签约环节属**招商与租赁域**，交叉引用 `docs/leasing-acquisition-prd-v1.0.md` §6「线索→正式商户档案（签约转换）」与 §6A「签约后到期/变更/退出衔接」；**协议条款文本、合同变更与违约处置**属**地产全链域**，交叉引用 `docs/real-estate-full-chain-domain-prd-v0.1.md` §2「租赁全生命周期」（合同生命周期、违约金与欠费处置）。本文只登记积分侧的强制义务口径，**不重复定义协议条款**。（2026-08-04 F-FIN 交叉引用更正：原文把协议条款与违约处置整体指向 leasing PRD，而该 PRD 正文无协议条款/违约处置内容）

### 6.2 有效消费金额

有效消费金额是会员优惠后的实际支付金额。

计入：

- 现金；
- 银行卡；
- 微信支付；
- 支付宝；
- 储值余额支付。

不计入：

- 优惠券减免；
- 平台补贴；
- 商户折扣；
- 积分加现金兑换的积分部分；
- 积分加现金兑换的现金部分。

积分加现金兑换整单排除，不属于有效消费，不产生基础积分、等级加赠积分或成长值，也不刷新积分有效期。

### 6.3 票务积分规则

- 票务订单不读取商户所属业态的积分规则。
- 票务系统只提交票务订单、支付、履约、退款、冲正和核销事实；积分域按票种或票务产品已审批生效的积分规则计算票务积分，会员与等级域按独立的票务成长值规则计算成长值。
- 任一票务规则缺失时不得回落到商户业态规则或另一套成长值、积分规则猜算。
- **成本口径**：积分转为可用时，按实际转为可用的积分数与当时生效的全国发行单价确认费用，由原票合同销售方单独承担；单店酒吧为销售酒吧商户，公司票为对应合同销售公司。统一代收与第三方代售不改变归属，不从分域前票款或酒吧分配池扣除，不摊给仅履约商户。收款方为全国积分结算中心；其非独立公司时为顶层平台公司。
- 多人票按实际使用人份、多次票按实际使用次份记账；保留父票、人份、次份及原核销来源。同一人次重复入场、赠饮核销和完整补偿不得重复计分。人次是计算单位，不是独立退款单位；普通退款仍按整张独立门票判断。
- **票务积分归实际使用会员**：每个人份或次份核销成功时，取该时点已提前公布并审批生效的固定积分值，不随会员等级、生日倍率变化，不发给付款人或转出人。规则变更公布适用范围及生效时间，允许票跨切换点；核销锁定本次规则、积分值与等待期。
- 核销后先进入 `PENDING`，满锁定等待期（全国配置，出厂默认24小时，须上下限）且对应票款未退款、无待处理退款申请后才转 `AVAILABLE`。待审核、已批待退、处理中或失败仍需退款时继续等待且不产生发行费；成功退款取消，驳回或撤销并确定不退后仍用原核销时间判断，不重新计时。未使用或到期未用不产生积分，不冻结父订单其他独立票。
- **票务成长值与实际使用行为关联**：只按实际核销的张（人次）计算；多人票每个已核销人份、多次票每次有效核销分别计算，未使用或到期未用的张（人次）不产生成长值。积分规则与成长值规则分别配置，任一结果不得从另一结果推导。

### 6.4 会员识别与积分获取渠道

> 2026-08-07 同步 BSM「积分与成长值获取」条、ENUM「积分与成长值来源」条（DEC-R8-77）。本节只写「怎么认人」，**不改任何分值口径**，填的是 §6.1 商户强制参加义务中「识别会员」一项的落地方式。

- 会员关联微信或支付宝后，在场内用微信或支付宝付款的，**自动累计积分与成长值**。
- POS、现金等其他付款方式，由**收银在收款时现场录入会员号**累计（收银侧步骤见 `docs/bar-business-operations-product-prd-v0.1.md` §9）。
- **会员号即注册手机号，平台不设独立卡号体系**；**收银现场录入会员号就是录入客人手机号，该动作走客人查询专门通道并留痕**（2026-08-19 补，依据 BSM「积分与成长值获取」条 / ENUM「积分与成长值来源」条 / PGM「手机号是查询客人的唯一路径」条现文；DEC-R8-97-29）。
- 此处的关联**只用于付款时识别会员**，**不改变以完成短信验证的手机号作为会员唯一识别标准**的规定。

> **实现现状（2026-10-21 第十一批 TK-04-a，V527）**：①业态规则落 `ticket_reward_config_versions` 新类 `merchant_points`（每产生 1 积分所需有效消费，分；按 `business_format`＝`merchants.merchant_type` 全国生效，值与上下限同录，最终审批人须属该业态在营商户的有效域主管公司，DEC-R8-93）与 `merchant_growth`（每记 1 成长值所需有效消费，分；按业态分别配置，与积分规则独立，审批人须为顶层平台主体），全国参数增商户消费等待期及上下限（`merchant_waiting_hours` 等，与门票等待期分开）；后台「门票积分、成长值与销售责任」页同页录入。②收银结账（`POST /api/v1/bar/bills/{bill_id}/settle`）与服务单确认收款（`POST /api/v1/services/orders/{id}/mark-paid`）可选填 `member_phone`，按注册手机号识别会员并写客人查询留痕（`customer.account.viewed`，记手机号哈希、查询人、是否命中），查无会员即拒 `MEMBER_NOT_FOUND`、不代建会员；未录入时取储值支付短信验证的付款客人，再取链上订单客人。③酒吧账单须结清且所覆盖订单的非撤单明细全部送达才生成 `merchant_consumption_rewards` 快照（完成时点＝最后一项送达时点；仅支付不生成），专项服务单在服务完成时生成（须收款时已识别会员）；有效消费＝账单应付（券抵扣、减免已扣出，小费不在内）－本单退品留款＋本单抵用留款；规则版本与生日倍率按支付成功时点锁定，等级倍率取生成时账户等级；积分记待确认流水（`source_doc_type`＝`bar_bill`/`service_order`，可由单据反查），成长值完成即记；缺积分规则或全国商户等待期时不发积分并记 `merchant.reward.points_blocked` 告警留痕，缺成长值规则不记成长值，二者互不回落。④等待期届满转可用、对应退款门槛、商户积分发行费与客人端/账单端查看（第十一批 TK-04-b，V528）：定时任务（与门票积分同一开关）对等待期已到的待确认奖励逐笔判断——酒吧账单有待审核退品、或退款已生效而应付尚未实际退出（含失败仍需办理）时继续待确认、不产生发行费；已成功退出的退款（储值回卡即时成功，现金类以退款应付经财务统一回写点实付结清为准）按原锁定规则与倍率从有效消费中排除，待确认的取消对应积分、`available_at` 不变（Q38B），退品驳回且确定不退的按原完成时点与原等待期发放；账户冻结或会员非有效状态不释放。转为可用时先抵扣待追回积分再入余额（积分流水 `confirm` 行挂原单据可反查），按转为可用的积分数×释放时生效的全国发行单价形成`merchant_points_issuance_fees`（承担方＝消费商户及其合同主体，收款方＝全国积分结算中心），并入积分月账单但按 `fee_kind`＝`merchant` 与门票积分发行费分开出账、分开挂账，账单明细列来源消费单据。已可用后才成功的退款按同口径从原获分会员扣回，不足部分挂待追回积分（`customer_points_recoveries.merchant_reward_id`，同一笔消费累计一行，沿用追平、小额豁免、注销作废出口），已确认的发行费不改写；成长值按退款后剩余有效消费同口径冲回。客人端 `GET /api/v1/customer/merchant-rewards` 只展示本人结果（商户、来源单号、积分、成长值、状态与等待期），账单端 `GET /api/v1/bar/bills/{bill_id}/rewards`（`bar.order.view`，限本商户、不含客人身份）。专项服务单不存在退款（第十批 TK-22 裁决），只做等待期释放与发行费；微信／支付宝关联自动累计无接口资料，仍未实现。

> **实现现状（2026-10-26 第十七批，操作员裁决补充第 1 条「全部自动冲回」）**：酒吧账单经主管「作废并冲正」（异常账单处置）时，本单商户消费奖励在同一事务内按有效消费为 0 全额冲回，不等原路退款实际退出：待确认积分取消，已可用的从原获分会员扣回、不足挂待追回（`customer_points_recoveries`），成长值同口径冲回并按当前滚动周期成长值重新定级（第十四批第 2 条）；已确认的商户积分发行费不改写。作废账单之后不再生成奖励。

## 7. 消费积分计算

### 7.1 公式

每个订单独立计算：

```text
基础积分 = floor(本单有效消费金额 ÷ 业态每1积分所需消费金额)
等级加赠积分 = floor(基础积分 × (会员等级倍率 - 1))
本单消费积分 = 基础积分 + 等级加赠积分
```

- `floor` 表示向下取整。
- 小数积分和不足 1 积分的消费金额不跨订单累计。
- 等级倍率来自消费时会员有效等级，等级资格见会员与等级产品细化文档。
- **等级倍率 ≥ 1（硬约束）**：倍率小于 1 会使 `等级加赠积分` 为负、本单消费积分**少于**基础积分，与「等级**加赠**」语义相反。**倍率 < 1 的等级规则版本不得生效**；倍率 = 1 时等级加赠积分为 0。本约束与 `docs/member-and-tier-product-prd-v1.0.md` §9、§7.2 同步。
- **等级倍率上下限上线闸**：全国平台为每个等级倍率版本同时配置下限和上限；已配置下限不得低于 1。倍率值、上下限、审批记录、生效时间和版本必须齐全，倍率超出该版本已批准闭区间时拒绝生效，缺少任一上下限的版本不得上线。具体上限数值本轮不定，不得用猜测值或历史值补齐。

### 7.2 成本归属和分账

- 基础积分与等级加赠积分分别记账。
- 两者成本均由发生消费的商户承担。
- **生日加倍的增量积分成本与基础积分同口径，由发生消费的商户承担**（2026-08-19 补，依据 BSM「积分与成长值获取」条 / ENUM「积分与成长值来源」条现文；DEC-R8-97-13）。
- 等级倍率由全国平台统一配置、审批、生效和版本化，商户不得另行约定倍率或倍率上限；“商户不得另行约定倍率上限”不表示全国平台可以省略上下限。缺少全国有效倍率版本、缺少任一上下限或倍率超出已批准闭区间时，不得发放等级加赠积分；基础积分仍按已审批生效的业态规则正常计算。
- 营销活动额外积分单独记账，不并入基础公式，成本按活动发布时锁定的法律主体承担。
- **票务例外**：门票只发固定积分，无等级或生日加成；发行费用由 §6.3 的合同销售方独立承担，不调整其他分账参与方金额。历史“域间拆分前整单预扣、各域共担”口径已被现行 HTML 替代。
- 只有积分转为可用时，基础积分和等级加赠积分才形成相应商户积分发行费。

### 7.3 规则版本锁定

普通商户消费订单必须锁定（票务另按 §6.3 的实际核销时点）：

- 商户所属业态；
- 业态积分规则版本；
- 会员等级倍率版本；
- 特殊固定积分规则版本（如适用）；
- 项目、商户和成本承担主体。
- 生日倍率是否适用以支付成功时点判断并随订单锁定，同时保存适用时点与生日规则版本；8 月 31 日支付、9 月 1 日履约仍按 8 月 31 日支付时点锁定的规则执行。

配置变化不得追溯改变已形成订单的计算结果。

### 7.4 票务产品与商户消费规则边界

- 票种或票务产品只能使用自身已配置、已审批并已生效的固定积分规则，不得套用商户业态公式。
- 商户消费按对应域主管公司已审批、在全国生效的商户所属业态公式计算；项目和商户不得自行新增或改变该规则，全国平台不得替代对应域主管公司审批业态积分获取率。
- 积分规则和成长值规则分别配置，任何一方不得从另一方反推；缺少对应有效规则时该项不计算，不得回落猜算。
- **两种计量机制的分界**：票务积分按实际核销时已公布生效的固定值确定，实际核销是取得资格的必要条件；成长值按独立成长值规则与实际核销人次计算。商户消费仍按消费金额计，不把商户业态公式套给票务订单。

### 7.5 计算示例

示例一：业态规则为每 10 元 1 积分，会员折后实际支付 99 元，等级倍率 1.5。

```text
基础积分 = floor(99 ÷ 10) = 9
等级加赠积分 = floor(9 × (1.5 - 1)) = 4
本单消费积分 = 9 + 4 = 13
```

剩余 9 元不带入下一订单。

示例二：商品公开价 100 元，商户折扣 10 元，优惠券减免 20 元，会员以微信支付 70 元，则有效消费金额为 70 元；折扣和券减免不计入。

示例三：会员以 1,000 积分加 20 元现金兑换虚拟券，整单有效消费金额为 0，不产生消费积分或成长值。

### 7.6 会员积分活动与投放边界

- 会员积分活动状态为草稿、待审批、已生效、已暂停、已结束、已失效；每个版本固化适用范围、出资方、预算、有效期、发放时点和退款回收规则。
- 活动预算必须满足“预算总额＝可用余额＋已预占＋已发放－已回收”；发放前先预占，失败释放，退款按订单锁定的活动版本回收，任何时点不得超出预算。
- 不新增会员点单例送、消费满赠、充值档位赠送、首充赠送或新会员开卡礼；已有新人优惠保持不变。
- 营销后台主动批量发券只能面向全部符合公开活动资格的会员，不支持个人名单、标签反查、消费特征圈选或营销经理个人归属；本人主动积分兑换和套餐随交易赠券不属于定向投放。

## 8. 冻结、确认与退款

### 8.1 状态

| 状态 | 含义 | 是否可用 |
|---|---|---|
| `PENDING` | 消费已记录，关联积分在退款期内冻结。 | 否 |
| `AVAILABLE` | 商户消费已履约且退款期结束，或票务退款期结束且对应票款未退款，积分已确认。 | 是 |
| `CONSUMED` | 已用于积分商城兑换。 | 否 |
| `CANCELLED` | 退款、取消或纠错已撤销该笔积分。 | 否 |
| `EXPIRED` | 超过账户活跃有效期。 | 否 |

待追回积分是独立追偿额度，不以负数写入 `AVAILABLE` 余额。

**退回积分的账本落点**：因商户无法提供券对应的履约能力或者平台原因将券作废，且不能按既有规则把券退回可用组继续使用而**退回积分**时（见 §11.2）——

1. **新建一条 `AVAILABLE` 积分流水**承载退回额度；
2. 该流水**继承原兑换所消耗积分的到期日**，**不因退回而延长有效期**（否则「兑换后再退回」将成为无限续期的后门）；
3. **原 `CONSUMED` 流水不得改写、不得回退为 `AVAILABLE`**——兑换与退回是两个独立事实，各留各的账本行，以保证逐笔可追溯；
4. **原积分在退回时点已过期的**：退回流水**照建但直接落 `EXPIRED`（不可用）**，并留痕「原积分已过期」这一原因，**不得为其重设新的到期日、不得按当前时点重新计算有效期**。

退回流水必须关联原兑换订单、原扣减明细、原因和审批记录（与 §11.2 一致）。

### 8.2 正常确认

- 支付成功后，消费关联积分先进入 `PENDING`；命中生日窗口的结果与适用时点、规则版本一并锁定，后续履约时点不改变已锁定结果。
- 商户消费在履约完成并超过对应业务退款期后转为 `AVAILABLE`。
- 票务积分只按 §6.3 的实际核销、锁定等待期与对应退款状态转为 `AVAILABLE`；未使用、到期未用不发积分。成长值独立按实际核销人次计算。
- 只有 `AVAILABLE` 积分可兑换。
- 只有转为 `AVAILABLE` 的消费积分形成商户积分发行费。
- 退款或取消按原订单锁定规则冲正相应的生日加倍积分，不读取冲正时的新规则。

### 8.3 退款期内退款

- 全额退款取消该订单全部 `PENDING` 积分。
- 票务退款成功后引用原核销发放记录、原使用会员与原分值冲回，不读取退款时新规则或改扣付款人；待确认的取消，已可用的追回，不足部分挂待追回。原成长值独立冲回。此处理不增加退款资格，也不把人次变成可独立退款的整票。
- 商户消费部分退款使用原订单锁定的业态规则和等级倍率版本，按退款后保留的有效消费金额重新计算。
- 原冻结积分与重算结果的差额转为 `CANCELLED`。
- 正常退款发生在冻结期内，因此不存在会员已使用该笔积分的情况。

示例：原有效消费 100 元，每 10 元 1 积分，等级倍率 1.5，原积分为 15。退款后保留有效消费 60 元：

```text
重算基础积分 = floor(60 ÷ 10) = 6
重算等级加赠积分 = floor(6 × 0.5) = 3
保留积分 = 9
取消积分 = 15 - 9 = 6
```

### 8.4 确认后特殊退款

确认后只有特殊退款、拒付、欺诈或系统纠错进入追偿流程：

1. 按原订单版本重算应保留积分。
2. 优先追回尚未使用的关联积分。
3. 不足部分记入待追回积分。
4. 后续新获得积分先自动抵扣待追回积分。**抵扣时点为该笔新积分由 `PENDING` 转 `AVAILABLE` 之时**，**不在 `PENDING` 阶段抵扣**——`PENDING` 积分仍可能因退款期内退款被取消，提前抵扣会造成待追回额度被错误冲减。每次抵扣须逐笔留痕，关联被抵扣的待追回额度与来源积分流水。
5. 待追回积分清偿前禁止兑换。

可用积分余额不得为负，待追回积分不构成会员现金债务。

**待追回积分的四类出口（2026-08-04 第三轮用户裁决 HC-09 / DEC-R6-22 定稿，已写入 ENUM「有效消费与冻结」条）**：待追回额度**只有以下四个出口，除此之外不得以任何其他方式消除**——

1. **追平**：后续新获得积分依次抵扣待追回额度，**抵扣至清零后自动解除兑换限制并留痕**（抵扣时点仍为 `PENDING` → `AVAILABLE` 之时，见上款第 4 条）。
2. **小额豁免**：**不超过豁免线的**待追回额度由**财务豁免并留痕**——豁免线为**业务参数、全平台统一可配、须同时配置上下限，出厂默认 100 积分及以下**。超过豁免线的不得豁免。
3. **不设时效**：未清偿的待追回额度**一直挂账，不因时间流逝自动消灭**；**不得设置自动时效清零或按期归零**。会员长期不消费导致的长期挂账属正常状态，不作处理。
4. **会员注销**：注销时待追回额度**作废登记、不形成现金债权，也不再追偿**（与 `docs/customer-app-miniapp-product-prd-v0.1.md` §3A「注销时积分、券、未核销的票一律清零」并行；作废须留登记痕迹，不得静默删除）。

> 原 C 类登记 AUD C-24「出口未定义」已关闭。小额豁免使用全国已审批并公告生效的配置版本，包含额度及上下限；配置页初始建议 100，未完成配置审批不得以默认值直接执行。财务入口按会员全部待追回总额判断，超过额度不得拆笔办理，等于额度可办理。操作者须获独立财务豁免权限并能处理全部来源项目及商户，不能只选可见部分。确认时重新锁定积分账户、核对总额与配置版本，与后续积分抵扣及注销共用账户锁；页面旧总额或版本变化须重新确认。豁免记录保留操作者、原因、规则版本及逐条原待追回额度，不增加可用积分、不改发行费、不生成现金债务。注销仍按既有作废登记处理。除上述四条外，仍不得由任何岗位手工核销待追回额度。

## 9. 积分有效期

### 9.1 账户活跃有效期

- 积分采用**账户活跃有效期（滚动有效）**：会员在窗口内有过一次合格消费的，其名下积分**全部保持有效、不过期**；窗口内没有任何合格消费的，积分过期。**该窗口为业务参数，全平台统一可配，出厂默认十二个月，可配置为六个月或三个月，须同时配置上下限**（依据 ENUM「积分明细类型」条）。
- 只有**单笔金额达到后台配置的最低消费金额**的有效付费消费，才刷新全部尚未过期积分的有效期。**该最低金额为业务参数，全平台统一可配，出厂默认 10 元，须同时配置上下限**；未达该最低金额的消费不刷新有效期。
- **不设静默回落**：有效期窗口或最低金额**缺少有效配置版本时，不得按任何默认值静默运行**——须阻断相关能力（不执行过期判定、不刷新有效期）并告警，由平台补齐配置后恢复。本文各处出现的「十二个月」「10 元」**均为出厂默认值，实际以生效版本为准**。
- 项目和商户不得降低平台最低金额或设置本地刷新规则。

### 9.2 不刷新事件

以下事件均不刷新积分有效期：

- 注册或登录；
- 签到；
- 生日；
- 营销奖励；
- 积分兑换；
- 储值充值；
- 押金；
- 零元订单；
- 退款订单；
- 积分加现金兑换。

### 9.3 规则变更与过期

- 有效期规则变更必须审批、通知、指定生效时间并版本化。
- 新规则不得追溯缩短会员当前有效期。
- 积分过期后不恢复；之后发生合格消费，只为当时尚有效积分刷新有效期，并为新积分建立有效期。
- 过期处理必须保留积分来源、原到期时间、过期时间和规则版本。

## 10. 积分商城与兑换

### 10.1 唯一使用场景

- 积分只能用于积分商城。
- 酒吧、游乐、餐饮、零售、门票及其他普通收银交易不得直接用积分抵扣现金。
- 商城支持纯积分兑换和积分加现金兑换。
- 兑换定价与下限见商户积分结算产品细化文档。

### 10.2 兑换前置条件

兑换必须同时满足：

- 会员身份允许使用权益；
- 可用积分足够；
- 待追回积分为 0；
- 兑换方案、价格和规则版本有效；
- 库存或履约能力充足；
- 所需预算已锁定；
- 券种资格和适用范围满足；
- **该项目该商品的内部结算价 ≥ 积分兑换结算单价（不倒挂）**——发券前须逐笔校验，倒挂即拒绝发券（依据 ENUM「发券与核销结算」条：「发券前须校验内部结算价不低于积分兑换结算单价、不得倒挂」）。

任一条件不满足时不得发券。

### 10.3 发券

- 每次成功兑换均生成虚拟券，不直接形成已履约订单。
- 发券时正式扣除积分并预占库存或履约能力。
- 发券锁定项目、商户、券种、兑换方案和关联版本。
- 发券不形成商户补偿应收，不与商户结算。
- 重复提交必须由业务幂等控制，只允许成功一次。
- 同一种兑换券默认允许同一会员多次兑换；只有兑换方案明确配置“每会员累计兑换次数上限”时才限制。次数校验以会员、券种、有效方案和累计成功发券记录为准，幂等拦截不等同于累计次数上限。
- **倒挂商品不得上架兑换（硬闸）**：内部结算价低于积分兑换结算单价的商品，**不得上架积分商城兑换方案、不得发券**（ENUM「发券与核销结算」条）。**该闸为硬闸，不得经 §11A.3 的破线审批绕过**——破线审批只处理「兑换方案低于项目零售参考价下限或内部结算价下限」的定价情形，**不授权发布或发售倒挂商品**；已上架商品事后出现倒挂的，须立即下架该兑换方案，已发未核销券按 §11.2 处理。

### 10.4 核销

- 核销表示商户实际完成商品交付或服务履约。
- 核销时预占库存转为实际消耗。
- 只有实际核销或完成履约才形成商户补偿事实。
- 重复核销不得重复扣库存或重复形成补偿。
- 商户补偿计算见商户积分结算产品细化文档。
- 核销或完成履约后，该券转为“已核销（已使用）”，从可用券列表移出但保留在历史记录中；不得再次核销、兑换、转赠或恢复为可用。重复核销必须拒绝且不得重复扣库存或结算。

## 11. 虚拟券

### 11.1 券种要求

每一券种必须明确：

- 履约主体；
- 适用项目、商户、商品或服务；
- 核销条件；
- 有效期；
- 是否允许转赠；
- 是否具有实名、年龄、等级或其他资格限制；
- 到期、取消和作废处理；
- 库存或履约能力来源；
- **履约通道（三类之一，见下）**。

**履约通道三分类（2026-08-07 同步 ENUM「发券与核销结算」条；DEC-R8-79）**：会员积分兑换发放的虚拟券，按履约通道分三类，分别处理——

1. **商户折扣券**：到对应商户抵扣，**不涉及库存**、不预占；
2. **店内实物／服务**：发券时从可用库存预占，到店由店员核销领取时才实扣，**按内部结算价与承接商户结算**，券过期作废释放预占；
3. **平台或外部合作伙伴**：到**平台服务台**或**外部合作伙伴**处核销，按与平台或该外部合作伙伴的**约定结算**。

本三类是**履约通道**的分类，与「收费型／免费型」（出资与结算性质）**各自独立、同时适用**：任一券种在配置时都须**同时确定其履约通道与收费性质**。§10.3 发券、§10.4 核销与 §11.2 关于预占、实扣与补偿的规定**适用于第 2 类**；第 1 类按抵扣处理、**不预占库存**、不产生商户补偿；第 3 类按与平台或该外部合作伙伴的约定结算。第 1、3 类的对账口径须在积分结算对账表中分别体现（§11A）。

### 11.2 到期、取消与作废

- 券到期、取消或作废时释放未核销预占。
- 积分兑换生成的券因客人自身原因取消，或者到期仍未核销的，原兑换所扣积分不退。
- 因商户无法提供该券对应的履约能力或者平台原因将该券作废，且不能按既有规则把券退回可用组继续使用的，原兑换所扣积分必须退回。
- 部分退品的退款只针对客人实付部分，券抵扣部分不折现、不退回。
- 整单因商户原因（缺货、错单、质量问题）取消的，该券退回客人可用组并保留原到期日；这是券核销后不可再次使用规则的唯一例外。
- 客人自愿整单退的，券不退回。
- 退回积分必须关联原兑换订单、原扣减明细、原因和审批记录。
- 已核销券不得按未履约规则重复退回积分。
- 退回积分的**账本落点**（新建 `AVAILABLE` 流水、继承原到期日、原 `CONSUMED` 行不变、原积分已过期时落 `EXPIRED`）见 **§8.1**。
- 会员端券包只按“可用、已核销（已使用）、已过期、已失效”分组。“已失效”包括合规取消、商户无法履约、平台纠错或风控撤回；详情必须展示失效原因、处理时间以及积分是否退回，不使用含义重叠的“已取消 / 已作废”作为并列会员端分组。
  - **实现现状（2026-10-22 第十三批 ROOT-03 B 段 B-voucher-content，V541）**：客人券包每张券带失效原因、积分兑换券作废后实际退回的积分、可否转赠；固定券码不再下发也不再能核销，客人出示按全场统一刷新间隔签发的动态核销码（取新码即撤旧码，过期即废，转赠领取后原持有人的码全部作废；BSM「权益转赠一经完成，原持有人手里的码立即全部作废」），员工端按券编号核销的台账路径不变。

### 11.3 转赠

- 积分余额不可转赠。
- 虚拟券是否可转赠由券种配置，默认不可转赠。
- 实名认证、年龄、等级或资格限定券强制不可转赠。
- 转赠不改变券有效期、库存、结算条件、项目归属或来源。
- 转赠必须保留转出人、接收人、时间、券状态和资格校验记录。
- **实现现状（2026-10-24 第十三批 ROOT-03 B 段复核后裁决）**：券转赠按操作员裁决第十三批第 9 条「和门票一致不冻结（推荐）：发起转赠后原持有人仍可自用或改转他人，先成功的动作为准，其余自动作废」——发起转赠后原持有人仍可出示动态核销码自用，也可再转他人（再次转赠作废前一笔在途）；接收人确认领取、原持有人核销、原持有人改转三者争同一张券的行锁，先成功的为准：核销或改转在先的，在途转赠自动作废，接收人确认领取时 409 `VOUCHER_TRANSFER_VOIDED`「原持有人已使用或已改转他人，本次转赠已失效」；领取在先的，原持有人手里的码随即失效，改转 403 `VOUCHER_TRANSFER_NOT_HOLDER`。原「转赠中不能出示、不能核销」的冻结（`VOUCHER_TRANSFERRING`）去掉。发起与确认领取照门票转赠走幂等写：同一请求编号重提只回放第一次的结果（不作废前一笔、不多建一笔、不再发短信），成功与失败按接口契约留痕（`voucher_transfer.created` / `create_failed`、`claimed` / `claim_failed`；复核修复 2026-10-24）。

## 11A. 积分结算账期与总额收付（骨干规则）

细则见 `docs/merchant-points-settlement-rules-v1.0.md`；本节只登记不得被下游文档覆盖的骨干口径。

### 11A.1 账期参数

- 账期参数由**全国积分结算中心统一配置、审批和版本化**。
- 初始规则：**自然月计费、次月出账、十个工作日异议期、异议期届满后的下一个付账日（付账日为业务参数，全平台统一可配，初始为每月 5 日、15 日、25 日）完成上月收付款**，遇**法定节假日或非银行工作日顺延**（2026-08-06 按 ENUM「积分结算账期」条 同步，**DEC-R8-01**）。
- **完成时限目标**：**积分与商户的结算目标为账期结束后一个月以内完成**；**具体天数为业务参数，由全国积分结算中心统一配置、审批和版本化，须同时配置上下限**（依据 BSM「影响结算的规则由各自责任主体在系统中配置、审批和版本化」条）。该时限是**完成目标**，不构成独立的账期口径；收付款的触发时点仍按本节「**异议期届满后的下一个付账日**」执行，两者不得并列为两套账期规则。
- **出账日闸门**：**出账日须配置为使本账期存在满足顺序的付账日，否则拒绝保存**（比照 **DEC-R8-01** 已为付账日建立的同构闸门：「三个付账日中至少须有一个能满足该顺序，一个都不能满足的配置一律拒绝保存」）。
- 参数变更**只影响未来账期**，**不追溯已生成或已封账账单**；**项目和商户不得覆盖**。

### 11A.2 总额分别记账与收付（不得轧差）

- 双方应收应付先**各自按总额分别记账**：**商户应收的兑换补偿**与**平台应收的积分发行费**，**各自全额挂账、各自开票**。
- **一律按各自总额分别收付，不得轧差**（因涉及税务处理）。
- **平台内部各主体之间的应收应付同例。**

### 11A.3 兑付系数与破线审批

- 积分兑换结算单价 ＝ 全国统一积分发行单价 × 全国统一平台**兑付系数**；兑付系数由全国积分结算中心统一配置（业务参数，**全平台统一可配，出厂默认 0.7，须同时配置上下限**），**仅用于定价覆盖校验**，不作为商户补偿金额。每个兑付系数版本必须包含已批准的下限、上限、参数值、生效时间和版本；参数值超出已批准闭区间时拒绝生效，缺少任一上下限时不得上线。`0.7` 只作为出厂默认值写入完整配置版本，不等于上限、下限，也不得在缺少有效配置或上下限时静默回落使用；具体上下限数值本轮不定。
- 兑换方案低于项目零售参考价下限或内部结算价下限（破线）时，必须填写**七项**：**原因、目标、期限、数量、缺口、成本承担主体、预算**，由**全国积分结算中心授权岗位审批**；**预算不足不得发券**。
- **破线审批的边界（不适用于倒挂）**：破线审批**只覆盖「低于项目零售参考价下限或内部结算价下限」的定价破线**。**内部结算价低于积分兑换结算单价的倒挂商品，一律不得上架兑换、不得发券**，该**硬闸不可由上述七项破线审批绕过**（ENUM「发券与核销结算」条：「倒挂的商品不得上架兑换」）。

## 12. 跨领域业务流

1. 商户消费支付成功后，消费积分进入 `PENDING`；履约完成时，成长值按会员与等级规则入账。
2. 门票实际核销成功后，按当次已公告生效的固定积分规则锁定快照，为实际使用会员建立 `PENDING` 积分；票务成长值独立按实际核销人次入账。
3. 退款期内退款时，按原版本重算并取消差额冻结积分。
4. 商户消费履约完成且退款期结束时，积分转为 `AVAILABLE`，同时形成商户积分发行费事实。
5. 票务实际核销后按锁定等待期及对应退款状态转为 `AVAILABLE`，发行成本依 §6.3、§7.2 由原票合同销售方单独承担，不改变其他参与方分账。
6. 会员兑换时扣除积分、预占库存并发券，此时不产生商户补偿。
7. 虚拟券核销后预占转为实际消耗，并把核销事实交给结算域计算商户补偿。
8. 券到期、取消或作废时释放预占；客人自身原因取消或到期未核销不退积分，商户或平台原因且不能恢复券为可用时必须退积分。

## 13. 异常控制与审计证据

- 消费、退款、确认、发券、转赠、核销、退积分和追回必须具备业务幂等性。
- 商户消费缺少对应域主管公司已审批生效的业态规则时，基础积分不得猜算；票务缺少对应票务规则时，票务积分不得猜算。缺少全国等级倍率版本或其任一上下限时，只阻断等级加赠积分，不阻断已有有效业态规则下的基础积分。缺少兑付系数有效版本或其任一上下限、价格、库存、预算或审批时，阻断相应兑换能力；各项均不得跨规则或按出厂默认值静默回落猜算。
- 积分不足、库存不足、预算不足或存在待追回积分时，禁止兑换。
- 已生效规则和已发券记录不得被新配置覆盖。
- 系统不得静默修正积分、库存或状态差异；必须形成可追溯调整记录。
- 审计证据至少包含主体、时间、会员、项目、商户、订单、券、数量、原状态、新状态、规则版本、原因、申请和审批。
- 会员注销时积分和券一律清零；待追回积分按 §8.4 作废登记，不形成现金债权。
- 积分相关事项不发送短信。

## 14. 顺从性验收

1. “每 1 积分所需消费金额”由对应域主管公司审批并按批准版本在全国生效；同一业态在不同项目使用同一有效版本，项目和商户不能覆盖，全国平台不能替代审批；票务订单只使用已生效票务规则，不读取业态规则。
2. 现金、银行卡、微信、支付宝和储值余额计入有效消费；优惠券减免、平台补贴和商户折扣不计入。
3. 积分加现金兑换整单不产生积分、成长值或有效期刷新。
4. 基础积分、等级加赠积分分别取整、分别记账，余数不跨单累计。
5. 订单锁定业态规则和等级倍率版本；配置变化不追溯。
6. 部分退款按保留的有效消费金额和原版本重算。
7. 正常退款在冻结期内取消积分，不出现已使用积分追偿。
8. 确认后特殊退款不足追回时形成待追回积分，但可用余额不为负、会员不形成现金债务。
9. 只有**单笔达到后台配置最低消费金额**的合格消费刷新尚有效积分；**出厂默认门槛 10 元、出厂默认有效期十二个月（可配置为六个月或三个月），两项均须同时配置上下限**；**缺少有效配置版本时阻断并告警，不得按默认值静默回落**。
10. 发券扣积分并预占库存但不结算；核销才把预占转为消耗并形成补偿事实。
11. 积分不可转赠；券默认不可转赠，资格型券强制不可转赠。
12. 积分兑换券因客人自身原因取消或到期未核销时不退积分；商户无法履约或平台作废且不能恢复券为可用时必须退积分，退回积分继承原到期日。
13. 票务积分和成长值归实际使用会员，按各自独立规则计算；固定积分取核销时已公布生效版本并等待确认，未使用或到期未用不发积分。相同原票、人份、次份不重复计算，退款引用原发放记录冲回。
14. 同一种券默认可重复兑换，仅在方案配置会员累计次数上限时限制；券核销后进入已核销（已使用）终态并不可再次使用。
15. 会员端券包只分为可用、已核销（已使用）、已过期和已失效，失效原因及积分退回结果可见。
16. 生日积分资格按支付成功时点锁定：8 月 31 日支付、9 月 1 日履约仍使用支付时点规则；积分支付后先为 `PENDING`，退款或取消按原订单锁定的适用时点与规则版本冲正。
17. 会员已被正确识别且消费符合业态规则时，基础积分自动计算并进入 `PENDING`；商户未另行申请或确认、未配置内部结算价，均不得阻断基础积分，只有转为 `AVAILABLE` 才形成积分发行费。
18. 等级倍率版本必须同时具有上下限，倍率不得低于 1 且不得超出已批准闭区间；缺少任一上下限时，等级加赠积分不发放，基础积分不受影响。
19. 兑付系数版本必须同时具有上下限；`0.7` 只是出厂默认值，不是边界，缺少任一上下限或参数越界时不得发布兑换方案或发券。

## 15. 对抗性验收

| 反例 | 必须结果 |
|---|---|
| 全国平台未经对应域主管公司审批，为某业态或高价值商户设置另一积分获取门槛 | 阻断；只能使用对应域主管公司已审批、在全国生效的业态规则。 |
| 商户未绑定业态仍发积分 | 阻断积分能力，不猜测默认值。 |
| 把券减免或平台补贴计入有效消费 | 判为不合规并按实际支付重算。 |
| 两笔不足 1 积分的订单合并余数 | 阻断；每单独立取整。 |
| 退款使用当前新规则重算历史订单 | 阻断；必须使用订单锁定版本。 |
| 退款期内积分提前可用 | 阻断；保持 `PENDING`。 |
| 待追回积分写成负余额或现金欠款 | 判为不合规；使用独立追偿额度。 |
| 登录、签到或充值刷新积分有效期 | 阻断；均非合格消费。 |
| 发券即生成商户补偿 | 判为不合规；核销前补偿为 0。 |
| 重复发券或重复核销 | 幂等拦截，只认一次。 |
| 资格型券配置为可转赠 | 配置不允许生效。 |
| 券到期自动退积分 | 阻断；除已批准例外外不返还。 |
| 符合业态规则的消费因商户未另行申请、同意或逐笔确认而不发基础积分 | 判为不合规；完成会员识别后自动计算并进入 `PENDING`。 |
| 商户没有内部结算价，因此阻断基础积分 | 判为不合规；内部结算价只约束需要该价格结算的权益或券。 |
| 等级倍率版本只有下限、没有上限，或倍率超出已批准闭区间 | 版本不得生效；不发等级加赠积分，基础积分照常计算。 |
| 兑付系数仍使用 0.7，但配置版本没有上限或下限 | 不得上线或按 0.7 静默运行；补齐审批后的上下限和有效版本。 |
