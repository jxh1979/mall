# P2-F 独立 Python AI 服务边界契约 V0.1

## 1. 定位

P2-F 评估未来是否引入独立 Python AI 服务，用于替代或增强当前 Java 内置规则处理器。当前结论：生产主路径继续使用 Java 内置规则处理器；独立 Python AI 服务暂缓正式编码，只保留架构边界和进入条件。

> 本段规则已归口至 `docs/scope-wide-coding-rule-canonical-V0.01.md` §B-24，本文不再重复记载。
## 3. 未来服务边界

| 边界项 | 推荐口径 |
| --- | --- |
| 调用方式 | Java 后端异步提交任务，Python 服务返回结果 |
| 数据传输 | 只传最小必要字段和脱敏文本/附件引用 |
| 结果写入 | 结果回写 AI 质检任务/结果表，不直接改业务主表 |
| 失败处理 | 超时、失败、低置信度均进入人工复核 |
| 模型治理 | 记录 provider、model_version、prompt/version、confidence |
| 安全 | Python 服务不得持有生产数据库写权限 |
| 部署 | 独立进程/容器，独立日志、监控、限流和熔断 |

## 4. 进入正式编码条件

- Java 规则处理器无法满足明确业务场景。
- 已有可验证数据集、样本标注和验收指标。
- 已明确模型供应商或本地模型方案。
- 已定义 SLA、超时、降级、人工复核策略。
- 已完成数据合规、安全审查和生产部署方案。
