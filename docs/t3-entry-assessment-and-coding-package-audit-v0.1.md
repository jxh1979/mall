# T3 入口评估与编码包审计 V0.1

机器标记：T3_ENTRY_AUDIT_READY
机器标记：decision=do_not_start_t3_control_or_python_ai_yet
机器标记：allowed_next=T3-A_READONLY_ANALYTICS

## 1. 审计结论

T3-0 编码包已建立，可以作为下一阶段 T3 工作的入口。但当前结论不是“全面进入 T3 编码”，而是：

- 可以进入 T3-A 只读经营分析深化。
- 可以在供应商联调临近时进入 T3-B SDK/mock 深化。
- 不允许进入 T3-C 机器人/视频/设备真实控制闭环。
- 不允许进入 T3-D 独立 Python AI 服务。

## 2. 审计依据

- P2 全量完成审计已确认 P2-A/B/C/D 完成，P2-E/F 仅边界收口。
- T3 进入评估已确认不建议直接写 T3 控制或 AI 服务。
- 160 编码保护基线已建立，完整验证和正式提交只认 160 仓库。
- 旧 TypeScript/Fastify/SQLite 原型已物理移除，正式后端仍为 Java 21 + Spring Boot 4.x + PostgreSQL + Flyway。

## 4. 对抗式发现

| 编号 | 发现 | 风险 | 收口 |
|---|---|---|---|
| T3-F1 | T3 容易把只读分析和生产控制混在一起 | P0 | T3-A 只读，T3-C 控制闭环阻断 |
| T3-F2 | 供应商未到位时容易伪造真实接入 | P0 | 供应商就绪矩阵和安全闸口阻断 |
| T3-F3 | 独立 Python AI 服务会引入新运行时和合规风险 | P1 | T3-D 仅在模型/SLA/合规资料到位后启动 |
| T3-F4 | 集团级分析可能突破主体数据边界 | P1 | T3 文档要求主体边界、数据范围和审计 |
| T3-F5 | SDK/mock 示例可能误用真实密钥 | P1 | 明确 mock 不得包含真实生产密钥和真实身份数据 |

## 5. 建议下一步

推荐下一步只做 `T3-A 经营分析只读深化` 的独立开发计划。计划生成前不要新增 T3 Controller、Flyway 表或 Web 页面。

T3-A 计划应优先复用 P2-D 指标快照和现有 analytics 只读接口。如果发现现有数据不足，先补只读测试和只读接口，不要新增控制写接口。

## 6. 验收标准

| 场景 | Given | When | Then |
|---|---|---|---|
| T3-0 包完整 | 接手人读取 T3 入口 | 执行 `npm run verify:t3-coding-package` | 必须通过 |
| 开始 T3-A | 产品要求继续 T3 | 生成开发计划 | 计划必须声明只读、不控制、不接真实供应商、不引入 Python AI 服务 |
| 尝试 T3-C | 供应商资料未到位 | 评审开发计划 | 必须阻断 |
| 尝试 T3-D | 模型/SLA/合规资料未到位 | 评审开发计划 | 必须阻断 |
