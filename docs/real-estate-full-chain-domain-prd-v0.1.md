## 0. 定位与边界

- 综合体 = **地产 + 娱乐** 双层：娱乐运营（票务/酒吧/游乐/供应链/财务/留痕）此前已建透；地产层（招商/租赁/物业/楼宇设备/能耗/巡检）叠加其上做「管理层」。
- 数据隔离边界 = 综合体（项目）级，沿用现行 scope（org/project/merchant），见 `data-isolation-and-tenant-scope-security-spec-v0.1.md`。
- **术语澄清**：隔离用的 `project_id` 表示综合体项目维度；代码里的 `projects` 表是业态经营单元／场馆，不等同城市项目公司。平台、城市项目公司、域主管公司和商户通过项目、经营域、合同及主体绑定关系协作，不建立固定四层隶属链；一家公司可以服务多个项目，一个项目也可由多家公司共同经营。每个城市项目公司同时承担本城市资产公司职责，只负责资产物业、招商租赁、直接管理的第三方商户及自身人员设备。
- 本文覆盖 6 个地产子域；娱乐域不在本文范围。

## 2. 租赁全生命周期

- **授权依据**：平台治理地图 #contract（多级审批流 + 续租/退租/变更 + 租金账单）、业务枚举速查表 §十（合同变更类型 / 退租结算状态 / 合同审批流节点 / 租金账单类型 / 铺位租赁状态）；承接 `gap-analysis §7B.1/§7B.2/§7B.4`（已升正式条目）。
- **核心能力**：
  - 合同可配审批流：草稿→业务/财务/法务同阶段并行会签（都过才进下一阶段）→总经理终审→生效，任一节点可驳回退回起草；生效固化收益规则快照供票务/酒吧/游乐/结算引用。（2026-06-26 裁决#1：审批以业务系统地图「分组并行会签」为准，原「逐级」口径已纠正。）
  - 全生命周期变更：续租、退租（保证金抵扣/欠费追缴/争议）、租金/经营范围变更、提前终止，每次留审批与原因；不支持转租（`contract_changes` 类型不含转租），换租户须先退租再重新招商。（V314/#30/#31：`contract_changes` 类型扩至 8 类，新增 `scope_grant`/`location_change`。）
  - **超范围下单申请审批（V314/#30，2026-07-19 拍板）**：商户下单（酒吧/票务）被合同经营范围（`rent_terms.allowedCategories`）拦下后，不再当场拦死，可就该品类提交 `scope_grant` 申请（须填**原因**），走与新签同一套**分组并行会签链**（`contract.approve.*`）；终审通过则**授予该商户该品类临时/永久经营许可**（permanent 追加 `allowedCategories`、temporary 追加 `rent_terms.scopeGrants` 带 `validUntil`，下单侧 guard 读未过期者放行）、驳回则不予下单。申请单即 `contract_changes(type=scope_grant)`，全程审批留痕；权限 `contract.scope_request.raise`。
  - **变更子合同（V314/#31，2026-07-19 拍板）**：同一商户**仅变更经营位置或调整经营面积**（含扩大面积/新增位置）时，**不重开全新合同**，而是基于原合同派生一份有继承关系的「变更子合同」——继承承租主体/收费口径等关键条款、`rent_terms.parentContractId` 记录父合同、直接生效（变更已过审批链），原合同置 `amended`（退出计费/到期作业，保持商户单一生效合同不变量）；押金随变更**同步调整**（扩大/新增→补收、缩小→退差额，走保证金台账，**退押金遵循"运营手动确认才落账"口径**——子合同记 `depositAdjustment` 待办，由运营经保证金台账动作落账）；子合同与原合同经 `parentContractId` 关联可追溯（`GET /contracts/{id}/amendments`）。租金账单不自动重排（与既有面积变更不重排行为一致，需调整由运营用租金挂账端点处理）。
  - **主体绑定（当前实现模型）**：商户四类主体当前绑定在 `business_entity_bindings`（每商户 active 唯一，是“后续可拆”的落点）；合同签署时在 `contracts.*_subject_id` 固化该合同主体快照，与商户当前绑定可不一致。
  - 按租金规则（固定/每平米/营业额抽成/物业费/保证金/递增/免租期）生成周期性应收账单，逾期账龄与提醒。
  - 铺位平面图 + 租赁状态着色看板。**（当前实现模型）**：代码里 `spaces.status` 仅 `active`/`unavailable`（V203）；“空置/洽谈中/已租/即将到期/已退租/不可租”为看板派生视图，未落为数据库状态枚举。
  - **经营范围拦截（2026-07-19 现行）**：合同可约定并勾选商户**允许经营的品类**，作为下单侧经营范围校验依据；商户下单若超出合同勾选的经营品类，**在下单当场即被拦截**（把基础准入「超合同范围先卡住」口径落到具体下单动作，避免商户超范围经营）。允许经营品类由合同约定、后台可配。被拦截后商户可提交申请（须填原因）进入审批，审批通过则放行该笔、驳回则不予下单。
- **现有承接**：合同准入 + 到期预警（V028 contract_compliance_expiry）、合同空间（V080 contract_spaces）、铺位多边形（V023/V052）、物业费固定计费（V150）；`gap-analysis §7.4` 已给 merchant_contracts / contract_approval_flows / contract_rent_rules / contract_key_dates 等表设计。**审批流/续租退租办理/租金账单引擎已由 V162 合同域重建落地（原「未落表」为过期标注，2026-07-02 回写）。**
- **待深挖**：强制审批阈值、电子签章供应商、租金抽成比例细化。（审批会签规则=分组并行会签、退租结算与保证金抵扣口径、铺位状态枚举集合 已随 V162 落地并由业务系统地图定稿，不再列待深挖。）
