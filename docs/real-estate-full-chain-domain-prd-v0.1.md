## 0. 定位与边界

- 综合体 = **地产 + 娱乐** 双层：娱乐运营（票务/酒吧/游乐/供应链/财务/留痕）此前已建透；地产层（招商/租赁/物业/楼宇设备/能耗/巡检）叠加其上做「管理层」。
- 数据隔离边界 = 综合体（项目）级，沿用现行 scope（org/project/merchant），见 `data-isolation-and-tenant-scope-security-spec-v0.1.md`。
- **术语澄清**：隔离用的 `project_id` 表示综合体项目维度；代码里的 `projects` 表是业态经营单元／场馆，不等同城市项目公司。平台、城市项目公司、域主管公司和商户通过项目、经营域、合同及主体绑定关系协作，不建立固定四层隶属链；一家公司可以服务多个项目，一个项目也可由多家公司共同经营。每个城市项目公司同时承担本城市资产公司职责，只负责资产物业、招商租赁、直接管理的第三方商户及自身人员设备。
- 本文覆盖 6 个地产子域；娱乐域不在本文范围。

## 2. 租赁全生命周期

- **授权依据**：平台治理地图 #contract（多级审批流 + 续租/退租/变更 + 租金账单）、业务枚举速查表 §十（合同变更类型 / 退租结算状态 / 合同审批流节点 / 租金账单类型 / 铺位租赁状态）；承接 `gap-analysis §7B.1/§7B.2/§7B.4`（已升正式条目）。
- **核心能力**：
  - 合同可配审批流，按**全平台统一的审批模型**执行：草稿提交时**指定这条主线的最终审批人**（默认总经理），系统按组织层级**逐级自动补全**从起草人到该最终审批人之间的全部直接上级节点；**业务、财务、法务作为平行的相关部门线**，各指定该部门的最终审批人并同样逐级自动补全至该部门**预设的最低起点层级**；**主线与各条平行线都通过合同才生效**，任一节点可驳回、整单退回起草；三类流程模板的阶段数与审批岗位可配、可以不同；超时未处理自动提醒并升级到上一级、不得默认通过。生效固化收益规则快照供票务/酒吧/游乐/结算引用。（**2026-08-04 用户裁决**：统一审批模型＝指定最终审批人＋逐级自动补全＋平行相关部门线各指定最终审批人并补全至该部门最低起点层级；**2026-06-26 裁决#1「以分组并行会签为准」就此作废**。）
  - 全生命周期变更：续租、退租（押金抵扣/欠费追缴/争议）、租金/经营范围变更、提前终止，每次留审批与原因；不支持转租（`contract_changes` 类型不含转租），换租户须先退租再重新招商。（V314/#30/#31：`contract_changes` 类型扩至 8 类，新增 `scope_grant`/`location_change`。）
  - **退租结算与押金退还（2026-08-04 对齐 BSM L1203「变更与退租」／ENUM L182「退租结算状态」）**：退租、合同到期、提前终止三种情况**统一走结算**并落到财务台账，一次算清押金怎么处置、有没有违约金、还有没有没结清的欠费；各种终止结算都要**经过多级审批（涉及财务、运营等多个部门共同审核）**，**审批全部通过后系统按算好的结算清单自动落账，不再单设手动确认入口**。押金的退还**不在审批通过时立即执行**，而是在**最后一个审批完成之日起满 30 日后**才执行（业务参数，按项目可配，出厂默认 30 日）；这段时间用于让退租日之前的能耗费、物业费等按期出账的费用**全部形成应收并从押金中结清**，期间新出账的费用**自动并入该次退租结算、不另立新单**。同一份合同的退租结算**只算一次、不重复出账**。退租状态分待结算、押金抵扣中、欠费追缴中、已结清；**退租结算存在争议的，无限期挂起，直至诉讼或仲裁有结果后再行处理**。
  - **押金治理（2026-08-04 对齐 BSM L1199「签约与合同」）**：押金**收取月数全平台统一**（业务参数，**全平台统一可配**，出厂默认三个月，须同时配置上下限）。系统按该商户**以往的月均全部费用**（含房租、物业费、水费电费能源费等全部费用）测算其押金**尚能支撑几个月**，押金即将不足以覆盖欠费时即**启动清退**；**欠缴超过约定月数的一律清退、以押金清偿**（业务参数，按项目可配，出厂默认两个月，须同时配置上下限）。**押金不得用于日常抵扣欠费，只有清退时押金才能抵扣欠费与违约金**；平时发现商户违规需要处罚的，**开出缴费要求，不缴即形成欠缴**。商户欠费的处置手段——包括提起诉讼、停止营业、停止供水供电等——**一律在合同中约定**。
  - **装修报批与起租口径（2026-08-04 对齐 BSM L1199「签约与合同」）**：商户装修须**先行报批**——上传设计图纸、报建文件与消防等合规文件，**经批准后方可开工**；装修的施工时段、材料进场方式等另订管理规定。**合同中约定的交付日即为起租日**；**装修截止日由合同约定、商户须在该日之前完成**；**铺位一般按毛坯交付**。合同约定的**租金递增幅度、免租期、交付日（即起租日）、装修截止日**均须**录入系统供系统自动计算账目之用，系统只据以计算、不对约定本身作判断**。
  - **营业额抽成口径（全平台统一、不得逐户另议；2026-08-04 对齐 BSM L1199「签约与合同」／ENUM L186「营业额抽成模式」）**：营业额 ＝ 该商户当期在本综合体内**含税实收成交总额** − 当期**已成功的退款金额** − 由**该商户以外的出资方**承担的赠送与补贴。不论收款走平台还是走商户自有渠道**均计入**；商户**代收代付的第三方款项不计入**；按**开台或下单时点所属的营业日**归属账期；该账期发生商品退款的，**在退款发生的当期生成冲正，不回改历史月份**。凡**已计收过门票综合服务费的部分**——包括通票或券核销划归本商户的部分，以及单店门票的票款——**一律不再计入抽成基数，同一笔钱不两头收费**；**未计收服务费的商户其已完成结算的部分计入**。**阶梯比例一律超额累进**；**「保底与抽成取高」按自然月逐月比较、不跨月合并**。**第三方收银未按约定回流的**，按**合同保底额**与该商户在后台配置的**参照期内最高月营业额孰高计租**（业务参数，**按合同逐份可配**，出厂默认近三个月），并**按合同计违约金**；所用**参照期随合同版本固化在账单上**。抽成模式含：保底与抽成取高、固定比例、阶梯比例、保底加抽成叠加。
  - **营业额抽成账单的出账时序（2026-08-04 对齐 ENUM L186「营业额抽成模式」）**：
    1. **出账时点**：营业额抽成账单**在该账期的薪资月结完成、且服务费的实际发放数与扣留数定数之后**才出账——月结与服务费数未定格前不得出账。
    2. **一次出准**：账单**一次出准，不使用预估数、不在下期补差**（与「退款在退款发生的当期生成冲正、不回改历史月份」并行适用：冲正是新账期的正常业务，不是对已出账单的补差）。
    3. **出账日与付账日可配**：出账日与付账日**由后台配置**（业务参数，**按项目可配**），**不预设具体日期**。
    4. **顺序约束**：配置须满足「**月结定格 → 账单出账 → 异议期届满 → 付账日**」的先后顺序；**违反该顺序的配置一律拒绝保存**（保存时校验，不做静默纠正）。异议期的起算、长度与届满口径见 `merchant-portal-zone-prd-v0.1.md` §3「异议期口径」（BSM L1403「给商户」条），两处不重复正文。
  - **超范围下单申请审批（V314/#30，2026-07-19 拍板）**：商户下单（酒吧/票务）被合同经营范围（`rent_terms.allowedCategories`）拦下后，不再当场拦死，可就该品类提交 `scope_grant` 申请（须填**原因**），走与新签同一套**统一审批链**（`contract.approve.*`；2026-08-04 用户裁决：指定主线最终审批人＋逐级自动补全，业务/财务/法务为平行相关部门线）；终审通过则**授予该商户该品类临时/永久经营许可**（permanent 追加 `allowedCategories`、temporary 追加 `rent_terms.scopeGrants` 带 `validUntil`，下单侧 guard 读未过期者放行）、驳回则不予下单。申请单即 `contract_changes(type=scope_grant)`，全程审批留痕；权限 `contract.scope_request.raise`。
  - **变更子合同（V314/#31，2026-07-19 拍板）**：同一商户**仅变更经营位置或调整经营面积**（含扩大面积/新增位置）时，**不重开全新合同**，而是基于原合同派生一份有继承关系的「变更子合同」——继承承租主体/收费口径等关键条款、`rent_terms.parentContractId` 记录父合同、直接生效（变更已过审批链），原合同置 `amended`（退出计费/到期作业，保持商户单一生效合同不变量）；押金随变更**同步调整**（扩大/新增→补收、缩小→退差额，走押金台账；子合同记 `depositAdjustment` 待办）。**（2026-08-04 口径纠正）原「退押金遵循"运营手动确认才落账"口径——由运营经押金台账动作落账」已过期作废**：退租、合同到期、提前终止统一走结算并经多级多部门审批，**审批全部通过后系统按算好的结算清单自动落账，不再单设手动确认入口**；押金退还的执行时点另按本节「退租结算与押金退还」的满 30 日口径处理。子合同与原合同经 `parentContractId` 关联可追溯（`GET /contracts/{id}/amendments`）。租金账单不自动重排（与既有面积变更不重排行为一致，需调整由运营用租金挂账端点处理）。
  - **主体绑定（当前实现模型）**：商户四类主体当前绑定在 `business_entity_bindings`（每商户 active 唯一，是“后续可拆”的落点）；合同签署时在 `contracts.*_subject_id` 固化该合同主体快照，与商户当前绑定可不一致。
  - 按租金规则（固定/每平米/营业额抽成/物业费/押金/递增/免租期）生成周期性应收账单，逾期账龄与提醒。
  - 铺位平面图 + 租赁状态着色看板（对齐 BSM L1205「铺位看板」／ENUM L188「铺位租赁状态」）：铺位租赁状态分空置、洽谈中、已租、即将到期、已退租、不可租，**按距到期天数着色**；**分类、颜色和提前天数按综合体后台可配**（业务参数，按综合体可配；其中**铺位租赁状态的分类属于业务分类定义，不做后台增删**）。**（当前实现模型）**：代码里 `spaces.status` 仅 `active`/`unavailable`（V203）；“空置/洽谈中/已租/即将到期/已退租/不可租”为看板派生视图，未落为数据库状态枚举。**（2026-08-04 落地状态更正）租赁状态看板已落地**——页面 ADM-LEASE-002「租赁状态看板」（`/admin/leasing/rental-status`，`GET /api/v1/contracts/space-rental-status`），覆盖铺位状态 + 距到期天数 + 出租率汇总 + 即将到期着色 + 铺位下钻；原「待建」标注过期作废（见 §7）。
  - **经营范围拦截（2026-07-19 现行）**：合同可约定并勾选商户**允许经营的品类**，作为下单侧经营范围校验依据；商户下单若超出合同勾选的经营品类，**在下单当场即被拦截**（把基础准入「超合同范围先卡住」口径落到具体下单动作，避免商户超范围经营）。允许经营品类由合同约定、后台可配。被拦截后商户可提交申请（须填原因）进入审批，审批通过则放行该笔、驳回则不予下单。
- **现有承接**：合同准入 + 到期预警（V028 contract_compliance_expiry）、合同空间（V080 contract_spaces）、铺位多边形（V023/V052）、物业费固定计费（V150）；`gap-analysis §7.4` 已给 merchant_contracts / contract_approval_flows / contract_rent_rules / contract_key_dates 等表设计。**审批流/续租退租办理/租金账单引擎已由 V162 合同域重建落地（原「未落表」为过期标注，2026-07-02 回写）。**
- **待深挖**：强制审批阈值、电子签章供应商、租金抽成比例细化。（审批规则＝全平台统一审批模型（指定主线最终审批人＋逐级自动补全，平行相关部门线各指定该部门最终审批人并补全至该部门最低起点层级；2026-08-04 用户裁决，原「分组并行会签」作废）、退租结算与押金抵扣口径、铺位状态枚举集合 已随 V162 落地并由业务系统地图定稿，不再列待深挖。）

## 3. 物业服务工单
