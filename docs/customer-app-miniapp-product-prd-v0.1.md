## 1. 文档定位

客人端包括 **App 和小程序，两者同步建设**，给客人自己购票、预定/订台、查询订单与权益、看积分、出示验票二维码、礼物兑换。客人端不做现场业务操作（核销/点酒由员工端负责）。

## 2. 两端一套口径（核心约束）

- App 与小程序**同步建设、同一手机号关联同一身份**。
- 订单、票、权益、二维码、积分摘要、等级、订台/定金状态**两端完全一致**；瞬时不一致以后端最新为准、可手动刷新。

## 3. 主要功能

- 查看综合体介绍、营业时间、活动公告、票务入口。
- 查看票种、套餐、通票、游乐项目和酒吧规则。**购票前须以门票守则的形式向客人告知该票的规则**，包括能否退款、有效期、年龄限制与可使用范围。
- 通过官方 App/小程序购票、预定、确认订单、查看支付结果。**客人付款成功后必须出票，不得出现付款成功而出票失败的情形**，系统须从设计上避免此种情况发生；支付渠道会校验出票状态，确因出票失败的款项自动原路退回。
- **订台需支付定金**（App、小程序均可订台）；**订台页面须写明该卡座适用的最低消费金额与服务费比例**。
- 查询第三方渠道（美团/大众点评/抖音）购票后的票、权益和核销状态。
- **单店门票自助购买**：**单个酒吧的单店门票允许客人在自己手机上的综合体官方小程序或 App 自助购买**（2026-08-07 补，依据 BSM「门票主路径是客人通过官方 App/小程序或第三方平台自助购买」条；REGX-01）。
- 查看我的订单、我的票、我的权益和使用记录。
- 查看会员积分摘要、等级、积分明细、礼物目录、自助兑换、虚拟券与兑换记录；客户端只展示对应系统返回的状态，不自行推导等级、积分可用性或结算结果。
- 同一种兑换券默认允许同一会员多次兑换；仅当兑换方案配置“每会员累计兑换次数上限”时限制，重复请求的幂等拦截不等同于累计次数上限。
- 我的券包按“可用、已核销（已使用）、已过期、已失效”分组。券核销后从可用列表移出并保留历史，不得再次核销、兑换、转赠或恢复为可用；已失效详情展示失效原因、处理时间及积分是否退回。**可用券只有在券种允许转赠时才显示转赠入口**——券种未开放转赠的，可用券详情不出现转赠按钮（依据 BSM「我的券包」条；虚拟券默认不可转赠、资格类券强制不可转赠，见 ENUM「重复兑换与转赠」条 与 `docs/points-and-voucher-product-prd-v1.0.md` §11.3）。
- 展示验票二维码，供现场工作人员核销。
- **我的存酒**：查看本人名下全部存酒、到期日与动态取酒码。**存酒只能在存入的那家酒吧取用，不提供跨店取酒或跨店转移库存**；本页为**跨店汇总展示**，**每条记录标明所属酒吧**，**取酒须到该酒吧办理**（2026-08-19 补，依据 BSM「我的存酒」条 / ENUM「客人存酒有效期与转存」条现文；DEC-R8-97-26）。
- **我的余额**：查看本人储值卡余额，含**本金与赠送金分列**。**同时提供逐笔记录**（2026-08-19 补，依据 BSM「我的余额」条现文；DEC-R8-97-21）：**每笔充值**记时间、金额、本金与赠送金拆分、支付通路；**每笔扣款**记商户、扣减的本金与赠送金各多少；**每笔退款与回冲**含回冲顺序结果。**通用卡与商户级卡分列展示。**（实现现状 2026-10-17 CG-06a：`GET /api/v1/customer/stored-value/accounts` 与逐笔记录接口返回 `principal_cent / bonus_cent`，钱包页账户与每笔记录按本金／赠送金分列，并显示调整事由。）**储值卡余额不可转赠、不可过户，只能由本人账户消费**；**余额不设有效期、长期有效，出口只有本人消费、退卡、账户注销三条**（依据 BSM「储值」条 / ENUM「储值卡类型与收款主体」条现文；DEC-R8-97-12、DEC-R8-98-02）。
- **投诉与反馈**：客人可在官方 App、小程序提交投诉，支持文字留言、照片、视频与语音；也可通过企业微信等方式联系客服提交。
- **账户注销**：入口与规则见 §3A。
- **订卡邀请函**：订卡客人可在 App/小程序查看自己的订卡邀请函二维码（注明酒吧、卡座、可进人数），转发给朋友；细则见 §3B。
- **停车缴费**（BSM「连接客人端，客人在官方App/小程序缴费并查看消」）：出口扫码或在 App/小程序内按车牌（无牌车按入口领取的临时码）查在场车辆的入场时间、停车费、已缴与应缴，付款后显示离场宽限截止，须在宽限时限内离场；不做车牌绑定无感支付。实现现状（HP-P01 第一组）：客人端「停车缴费」页，出口二维码带项目与车牌／临时码直达；`/api/v1/customer/parking/*`，试算规则与下发给停车系统的一致，收款主体为城市项目公司。实现现状（HP-P01 第二组）：页面显示本日消费抵免（可用／已使用／已撤销／未达门槛、已累计的酒吧与商户有效消费、门槛与可抵分钟，门票不计入；`GET /api/v1/customer/parking/credits`）；查费时先扣免费时长再扣可用抵免，显示抵免前停车费与抵免金额，抵到 0 元时由客人点「使用抵免离场」记 0 元已缴并显示离场宽限截止；同一客人每日一次。

## 3A. 账户注销

- 客人可以**自行申请注销账户**。
- 发起注销时，系统须提醒其名下**尚有存酒与储值卡余额**；客人可以选择不取存酒、放弃余额，径行注销。
- 放弃的存酒按**存酒到期规则**转为所在酒吧的**自有库存资产**。
- 放弃的储值卡余额归**发卡主体**：通用卡归长沙项目公司，商户级卡归发卡商户。
- 注销后：客人的**姓名、手机号、人脸、证件等个人信息一律删除**；**积分、券、未核销的票一律清零**。
- **待追回积分作废登记（2026-08-04 第三轮用户裁决 HC-09 / DEC-R6-22）**：注销时该会员名下的**待追回积分额度一律作废并留登记痕迹**——**不形成现金债权、也不再向其追偿**，不得静默删除（作废记录须可回溯额度、形成原因与注销时点）。完整出口规则见 `docs/points-and-voucher-product-prd-v1.0.md` §8.4。
- **消费记录、支付流水、退款记录等钱账留存**，但**脱去个人标识、改以不可反查的编号记录**，以保证历史账目仍然对得平。
- 个人信息的**查询与导出按来源判定**：属该商户的客户的，该商户**可以查询、可以导出，但不得删除**。
- 已注销会员的手机号**可以重新注册**，新账户与原账户之间不建立任何关联；与平台主动关闭（已关闭，手机号不得再注册）明确区分，见 `docs/member-and-tier-product-prd-v1.0.md` §10.1。

## 3B. 订卡邀请函

- 邀请函上的人分**两种身份**：**开卡人**（订下这个卡座的人）与**被邀请人**（接受邀请占用名额的人）。
- 开卡人可在 App/小程序查看订卡邀请函二维码（注明酒吧、卡座、可进人数），转发给朋友。
- 朋友在 App/小程序**确认接受**后占一个名额；该名额**自动关联到接受人本人的动态入场码**，到店出示**本人的动态入场码**入场。
- **入场必须核销、不存在免核销入场的情形**：被邀请人到店同样须完成**该酒吧的入场核销**——不论入场资格来自邀请函（卡座免通票入场名额）、通票还是单张门票，一律须完成该店的入场核销；该名额**只授予所预定卡座对应的那一家酒吧的入场资格，不含任何赠酒或酒水权益**，要进入其他酒吧须另行购买该酒吧的门票或通票（依据 ENUM「权益类型」条）。
- **邀请函二维码只用于转发与接受，本身不作为入场凭证**；邀请函二维码带防伪标记，被复制或篡改（卡座、可进人数）即无法接受。
- 开卡人可以在 App/小程序上看到**已接受邀请的名单与各自是否已入场**，并可把**尚未入场**的被邀请人移出邀请函、收回其名额；名额释放后可再邀请他人。
- 被邀请人**一旦完成核销入场，开卡人不得再将其移出，其名额也不再释放**。
- **每一次邀请、接受、移出都记录操作人与时间。**
- 已接受但尚未入场成员数＋已入场成员数不超过卡座可进人数。
- 转台时，原台已发出但尚未接受的邀请、已接受但尚未入场的成员和已入场成员全部随台迁移到目标台，尚未接受的邀请继续有效且不占名额；超出目标台可邀请人数时阻断转台，只能由开卡人先明确移出足够的未入场成员，已入场成员不得移出、已占名额不得释放。
- 并台时，各独立台或合并台组已经发出的邀请继续有效并保留原台来源记录，已有的已接受成员和已入场成员一并进入新的合并台。
- 并台期间新发出的邀请及由这些邀请形成的已接受成员、已入场成员，在首次拆台前由授权人员逐一分配到当前合并台所含某一张原台并留痕；已入场成员只调整所属原台，不得被移出，已占名额不得释放。
- 分配完成后，按拆台后每个独立原台或合并台组的可邀请人数分别校验“已接受但尚未入场成员数＋已入场成员数”；任一结果超额即整体阻断，系统不得自动分配、自动移出成员或释放名额。

## 4. 登录与关键规则

- 登录支持手机号短信验证码与微信；创建会员身份时必须以手机号完成短信验证、填写生日、满足平台年龄要求，并同意当前会员条款和隐私条款。条件全部满足即自动创建 `ACTIVE` 会员，否则注册失败且不创建身份；已存在手机号直接登录或关联原会员；`CLOSED`（已关闭，平台主动）状态手机号拒绝再次注册，已注销（客人自行发起）手机号可以重新注册且新账户与原账户不建立任何关联。微信身份不能替代手机号唯一识别标准。
- 客人账户与员工/商户账号体系**完全隔离**。
- **事前告知义务**：**凡与客人有关的规则一律在其消费之前告知**——购票时在购票规则（门票守则）中写明，订卡时在订卡规则中写明，其余同理。
- **订台定金状态**（七态）：未支付、免收（员工代订）、已支付、**达标已原路退回**、已退还、已没收、已超时释放；定金按固定额或按低消比例计。**定金不抵扣消费、也不计入最低消费累计进度；该台位累计消费达到适用最低消费后，定金按原支付路径全额退回**（2026-08-04 第三轮用户裁决 UD-13 / DEC-R6-05）。
  - **「已没收」含两种情形**：①**超时未到店或超时取消**；②客人到店但未满足最低消费。<!-- 改（2026-08-19）：依据 ENUM「订台定金状态」条现文（DEC-R8-98-01）——原「客人爽约」措辞与「客人自助订台不记爽约」相抵 -->
  - 两种情形**均按爽约发生当日所属营业日归属账期**。**员工代订的记一笔爽约到经手员工名下；客人自助订台超时未到店的只按规则没收定金，不记客人爽约**（2026-08-19 补，依据 BSM「订台定金与到店时限」条现文；DEC-R8-98-01、DEC-R8-97-R1-04）。
- 采集证件、人脸、支付账号、精确位置等**敏感信息前先单独取得同意**，并留同意版本、时间和范围。
- **门票主路径为客人本人自助购买**。少量到店服务场景可由授权服务人员在**售票一体机**上辅助客人下单：
  - 该「授权」不是客人在 App/小程序里授权某员工，而是由**管理后台门票系统权限**控制——即只有被后台授予「一体机售票」权限的服务人员，才能在一体机上进入辅助购票；未授权人员无此入口。辅助购票全程留操作人、时间、订单留痕。
  - 辅助购票**仅限售票一体机**这一现场设备。**工作人员平板一律不得代客购票**（与终端权限总表「平板不代客购票」一致，非例外）；两者口径不冲突：一体机=授权服务人员可辅助下单的现场售票终端，平板=不承载代客购票能力。
  - 二维码原始值不存在手机本地，只在线核验。
- 第三方团购渠道**未接入前相关入口置灰、不展示伪造数据**。

- 订单/票/权益/退款单状态：见票务 PRD 与业务枚举速查表 §一。
- 订卡邀请函：未签发、已签发、（成员）已确认接受 / 已入场 / 已取消。

## 7. 验收要点

- App 与小程序同一身份下订单/票/权益/积分/订台状态一致，刷新后收敛。
- 订台必须先支付定金才占位。
- 敏感信息采集前有单独同意并留痕。
- 订卡邀请函名额：已接受但尚未入场成员数＋已入场成员数 ≤ 卡座可进人数，超出拒绝。
- 转台后三类邀请与成员全部随台迁移，尚未接受的邀请继续有效且不占名额；按目标台名额校验，超额时整体阻断，已入场成员不得移出或释放名额。
- 并台邀请保留原台来源；并台期间新增邀请及成员在首次拆台前须由授权人员逐一分配到原台并留痕，不得由系统自动分配。
- 拆台后任一独立原台或剩余合并台组超额即整体阻断，不得自动移出成员或释放已占名额；一次全部拆开须在全部归属分配和逐台名额校验通过后一次性成功，否则整体失败。
- 发生再次转台、并台、拆台或任何邀请、成员、订单、付款、退款变化后，不得按旧快照撤销转台；转台前任一原台已被其他会话预订或开台时同样阻断。
- 第三方渠道未接入时入口置灰、无伪造数据。
