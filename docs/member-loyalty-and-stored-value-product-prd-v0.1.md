## 1. 文档定位

本文档按业务动作拆解会员忠诚度与储值能力，回答“消费怎么变积分、积分怎么算等级、积分怎么兑换、签到生日怎么奖励、客人怎么充值消费余额、怎么开通付费会员”。会员体系与票务核销、酒吧消费、礼品库存、财务对账连通。

客人账户与员工/商户账号体系完全隔离（见客人端 PRD）。

## 2. 目标

- 把客人的每一笔消费按后台规则转成会员积分与会员等级成长。
- 用“两本账”分别管理会员等级与可兑换积分，互不串扰。
- 支持积分兑换**虚拟券**（券再核销领取实物/折扣/权益），兑换当时不扣库存、券核销领取实物时才按库存约束扣减。
- 支持连续签到、生日加倍等忠诚度玩法。
- 支持客人充值余额、消费扣余额（储值预付卡）。

## 3. 积分两本账（核心口径）

会员积分分两本账，互不影响：

| 账 | 用途 | 增减规则 |
|---|---|---|
| **成长积分** | 算会员等级 | 消费确认（pending→confirmed）时与可用积分**同时增加**、金额同源；**只增不减**、不受兑换影响；仅到期清减后才可能导致等级下调 |
| **可用积分** | 兑换消耗 | 消费确认时随成长积分**同时增加**；兑换时**仅扣可用积分**、成长积分不动；扣减**不影响**会员等级 |

- 会员等级：按累计成长积分达门槛**自动升级**；档位与门槛以后台规则为准；成长积分仅在到期清减后才可能下调等级。
- 入账时机：一笔消费从待入账转为已确认（pending→confirmed）时，**可用积分与成长积分同时按同一入账金额增加**；兑换消耗**只扣可用积分**、成长积分保持不变。
- 到期清减：成长积分按自然年清零，或按后台配置的有效天数清零。

## 4. 积分获取

- **有消费就给**：买票入场、订卡、酒吧消费等都计积分。
- 计分方式（后台可配，可组合）：按消费金额 / 按核销张数（购票一次送固定值）/ 按打卡签到（一次给固定值）/ 按生日加赠 / 按活动。
- 获取渠道：会员关联微信/支付宝后，在场内用微信/支付宝付款自动累计积分；POS、现金等其它付款方式可现场录入会员号累计。
- **按核销张数确认**：购票积分按实际已核销张数比例确认（核销几张算几张，未核销/过期/退款不计）；退款按已确认份额冲减。
- 积分明细类型：获取、扣减、兑换消耗、过期、调整；每笔关联触发它的业务单据。

## 5. 积分兑换（虚拟券模型，2026-07-18 现行）

- 积分只兑**虚拟券**、不直接兑实物；**兑换当时不减可售库存**——实物/服务券在发券当场从可用库存**预占（冻结）一件**、不减总库存，发券数量受可用库存约束以防超发（折扣券不涉及库存、不预占）。
- 券分三类核销：
  - ①**商户折扣券**：到对应商户抵扣。
  - ②**店内实物或服务**：发券时从可用库存预占，到店由店员核销领取时**把预占转为实际出库**、按内部结算价与承接商户结算；**券过期或作废则释放预占、放回可用库存**。（预占机制防止券超发实物库存。）
  - ③**平台或外部合作伙伴**：到平台服务台或外部合作伙伴处核销。
- 客人「**我的券包**」按『可用 / 已核销 / 已过期』分组查看名下所有券；**每张可用的券可点开（或有「使用」按钮），进入可核销使用或转赠该券的界面**。
- 券可设有效期、**过期不退**；**券支持转赠他人**——**券是否可转让在后台生成券种时可配，默认可转让，关闭则该券种发出的券不可转让**。
- 换实物的券若实物缺货，可退回成积分（兑换时即向客人说明）。
- **券对应的内部成本价对客人和店员均不可见**，仅后台被授权角色可见。
- 兑换发放有状态（待发放、已发放、已取消、异常）。
- 区分口径：**积分本身仍不支持会员间转赠**（积分绑定本人）；可转赠的是兑出的**券**，二者不同。

## 6. 忠诚度玩法

- **连续签到**：客人每日签到记连续天数，按连续天数阶梯奖励积分；断签重置。
- **生日加倍**：生日当天或生日月消费积分加倍（与等级倍率叠加）。

## 7. 储值与付费会员

> **[已废止 2026-07-18]** 「付费会员订阅」已彻底废除（端点/表/服务/OpenAPI 全下线，迁移 V290 DROP 两表）；**储值预付卡/余额**现行有效。付费维度由储值预付卡承接，不再有付费会员订阅。

### 7.1 卡类型与资金归属（权威 HTML）

- 客人可充值到余额、消费时扣余额；**充值必须支付成功才入账、不凭空加余额**；账户可冻结/解冻；余额不可为负。
- 储值卡分两类：① **综合体通用卡**（综合体内各商户通用）；② **商户级卡**（仅发卡商户，不可跨店）。
- 消费时按客人**指定的某一张卡**扣减，不自动跨卡。
- 商户级卡充值资金默认归发卡商户预收（也可后台改为平台统一收取、消费时结算给商户）；退卡规则按卡类型与后台配置。

### 7.2 本金 / 赠送金双科目（DEC-SV-LEDGER-001，2026-07-28）

- 每笔成功充值入账必须拆分为两科目（若该次无赠送则赠送金为 0）：
  - **本金（principal）**：客人实付进入储值的部分
  - **赠送金（gift）**：活动/规则赠送部分
- **赠送额度可配**：对本金赠送多少（固定额、比例、阶梯、活动档）一律后台可配，禁止写死；无活动则赠送金=0。
- 账户侧必须保留本金余额、赠送金余额及来源/活动引用，便于对账与冲正。
- 展示：客人可见总可用余额；后台/对账必须能拆开本金与赠送金。

### 7.3 消费扣款顺序（DEC-SV-SPEND-ORDER-001）

- 扣款顺序**可配**。
- **默认：先本金，后赠送金**（用户 2026-07-28 确认，覆盖审计稿「先赠后本」建议）。
- 单次消费可拆分多科目流水；任一科目不足时按顺序用下一科目；两科目合计不足则拒绝或按支付合单策略（与收银 PRD 对齐），**不得静默透支**。

### 7.4 退款 / 冲正与混退（DEC-SV-REFUND-001，本金中心默认）

> 用户本轮明确了分科、赠送可配、扣款顺序、禁止迁移；**退现规则**按本金中心模型落默认口径，若需改为按比例分摊或赠送金可退现，另开裁决覆盖本节。

- **可退现金默认仅限本金未消耗部分**（按本金科目流水与剩余本金余额）。
- **赠送金默认不退现金**；退款/部分退时：
  1. 先按原消费扣款逆序或按可追溯分摊，恢复/调整科目；
  2. 应退现金只从**本金**出；
  3. 未使用赠送金按活动规则**作废或收回**（可配），不得擅自转为可提现。
- 部分退、整单退、储值支付与其它支付混付时：储值段按上款处理；其它支付方式退回走原支付通道规则。
- 所有阈值、是否允许「赠送金退现」开关、作废时点：**可配**（DEC-CFG-ALL-NUMERIC-001）。

### 7.5 账户注销（DEC-SV-CLOSE-001）

- 注销前必须处理：未完成订单占用、冻结金额、在途退款。
- 可退：剩余**本金**按退卡/原路或配置退回策略出金。
- 剩余**赠送金**：默认清零/作废（可配活动例外），不兑现金。
- 注销后账户不可再入账；全程留痕。

### 7.6 余额迁移（DEC-SV-NO-MIGRATE-001）

- **禁止**会员储值余额在账户间迁移（含本金与赠送金、通用卡与商户卡之间、会员 A→B）。
- 需要资金转移时：走合法退本金 + 重新充值，或经单独合规产品（若未来引入须新裁决，不得默认打开迁移）。

### 7.7 与积分的边界

- 储值本金/赠送金 **不是** 消费积分或成长值。
- 积分规则见 `member-points-tier-and-clearing-prd-v1.0.md`；储值支付是否参与发分按积分 PRD 与业态规则，不在本节改写。

## 9. 状态枚举（业务口径，最终以后台配置为准）

- 兑换发放：待发放、已发放、已取消、异常。
- 券状态（我的券包分组）：可用、已核销、已过期。
- 券类型：商户折扣券、店内实物或服务券、平台或外部合作伙伴券。
- 储值账户：active（正常）、frozen（冻结）、closed（关闭）。
- 储值流水：充值、消费、退款、调整。
- 付费会员：active（有效）、expired（到期）、cancelled（取消）。
- 积分明细：获取、扣减、兑换消耗、过期、调整。
- 积分过期：成长积分按自然年清零，或按后台配置有效天数清零。

- **已确认默认**：V-12 家族——连续 **12 个月**内至少一次合格消费，**全部未使用消费积分整池续期**。

- **结构锁定**：首期整池续期；不分批过期与整池双轨并行。
- 详细以业务决策日志 `DEC-VALIDITY-001` 为准。

### 会员等级加赠与活动加赠（2026-07-28 / DEC-TIER-MULT-001）

- **已确认**：各会员等级有后台可配**加赠率**；在商户/业态基础发分结果之上计算等级加赠积分。
- **活动加赠**与等级加赠相互独立，活动不替代会员等级加赠。
- 会员端只展示统一消费积分；后台分来源与费用承担方记账。
- 等级加赠成本与商户基础发分成本均由**商户规则承担方**承担（可配）；活动加赠仍由活动预算承担，与等级加赠独立。
- 详细以业务决策日志 `DEC-TIER-MULT-001` 为准。

### 积分/成长值到账与冻结（2026-07-28 / DEC-EARN-EVENT-001）

- **已确认**：消费确认入账时计算消费积分与成长值。
- **默认**：两者均先**冻结**，待该笔消费**退货周期**结束后解冻为可用/有效。
- **例外**：酒吧、游乐等**即时消费、无退货周期**业态——确认后**立即到账可用**（不冻结）。
- 冻结期、即消白名单后台可配。
- 详细以业务决策日志 `DEC-EARN-EVENT-001` 为准。

### 退款时积分与成长值冲减（2026-07-28 / DEC-REFUND-POINTS-001）

- 详细以业务决策日志 `DEC-REFUND-POINTS-001` 为准。

### 积分兑换商户虚拟券的承接时点（2026-07-28 / POINTS-VOUCHER-ACCRUAL-002）
