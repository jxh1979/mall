# 储值产品 PRD V0.06（会员与积分职责已拆分）

日期：2026-10-20

状态：现行储值业务文档

## 1. 文档定位

本文只负责储值卡、储值本金、赠送金、消费扣款、退款、注销和余额迁移边界。

会员身份、成长值、等级、积分和虚拟券由以下 PRD 细化；三份业务 HTML 仍拥有最终解释权：

- `docs/member-and-tier-product-prd-v1.0.md`
- `docs/points-and-voucher-product-prd-v1.0.md`
- `docs/merchant-points-settlement-rules-v1.0.md`

连续签到和生日权益的边界见 `docs/stored-value-membership-checkin-birthday-prd-v0.1.md`。

## 2. 目标与边界

- 储值余额只能来自真实充值、赠送规则和可追溯退款回冲。
- 储值账户、资金责任和退款规则属于储值域，不属于会员或积分域。
- 会员系统可以接收“储值余额已实际支付”的消费结果，但不拥有储值资金。
- 本文不定义成长值、积分、等级、兑换券或商户积分结算。

## 3. 付费会员订阅已废止

付费会员订阅已于 2026-07-18 废止，不属于现行能力。全国会员身份免费，付费商品、储值卡或权益包不得被重新解释为付费会员身份或会员等级。

历史付费会员资料只用于审计，不得恢复为现行业务规则。

## 4. 储值卡类型与资金归属

- 客人可以充值到储值余额，充值必须支付成功才入账，不得凭空增加余额。
- 储值卡分为两类：
  1. **综合体通用卡**：综合体内各商户通用；
  2. **商户级卡**：只能在发卡商户消费、不可跨店。

### 4.1 综合体通用卡：发行与收款主体

- 通用卡的**发行与收款主体为长沙项目公司**：充值资金由长沙项目公司统一收取并作为**预收款挂账**，**余额管理与退款均由长沙项目公司负责**。
- 长沙项目公司应当就通用卡余额的**实际消费**向各业态的经营主体**直接付款结算**，**按三个付账日结清**。
- 该项付款只是按各业态既定规则**兑付客人已付的钱**，**不构成对该业态定价、票务或结算规则的管理权**。
- **储值卡的消费扣款顺序、赠送金的性质与退卡口径，须在客人充值之前告知。**

### 4.2 扣款顺序（写死，不可配置）

- 通用卡的消费扣款顺序**写死为先扣本金、后扣赠送金，不可配置**。
- **唯一例外为商户级卡**：其扣款顺序由**发卡商户自定**，由**平台运营代为录入后台**，商户不自行改动。

### 4.3 退款回冲顺序

- 储值卡消费后发生退款的，退回该卡余额，并**按扣款的相反顺序回冲**：**先回冲该笔消费中已扣的赠送金，赠送金回冲完毕后再回冲本金**。

### 4.4 退卡与销户

- **退卡只退未消费的本金**；**赠送金不退现**，未使用部分按活动规则作废或收回。
- **销户时先解除全部占用与冻结，再退剩余本金，赠送金清零。**

### 4.5 营业额与抽成口径

- **储值卡余额等同于现金。**
- **充值本身是预收款，不计入任何商户的营业额。**
- 客人在商户处**实际消费**时，才按**消费发生的营业日**计入该商户的**营业额与营业额抽成基数**。

### 4.6 分账继承

- 通用卡余额等同于现金：客人**用它购买什么，就适用该项业务原有的分账与结算规则**——购买通票按通票规则与娱乐平台公司结算，购买游乐与游乐公司结算，购买演出与传媒公司结算。

### 4.7 通路费口径

- **储值卡充值时即产生通路费**，按该笔充值**实际使用的支付通路记录金额与费率**。
- 在商户处消费商品或服务的，按该商户给客人的**成交价格、扣除该笔消费所对应的通路费**后与该商户结算，**不另扣任何比例**。
- 同一张卡由**两个以上通路**充值的，每笔充值分别记录实际支付通路、充值金额和当时固化的费率；消费时按该笔消费所对应的充值金额占比计算。
- **通道费以每笔充值支付成功时平台与该支付通路的生效合同费率为准，随该笔充值一并固化**；该笔充值对应的余额无论何时消费，均按其固化费率计扣，平台与渠道合同换期不影响已充值余额的通道费计算。

### 4.8 赠送成本承担（通用卡）

- 通用卡的**充值赠送金额与赠送权益的成本一律由长沙项目公司承担**，**不得从商户结算款中扣除、不得摊给商户**。
- 通用卡赠送比例可配（业务参数，按项目可配），但该比例须同时具备自身已批准的下限与上限并落在闭区间内；缺少任一边界、边界未经批准或比例越界时，对应赠送规则不得发布或启用。本文不预设具体区间。

### 4.9 商户级卡

- **充值资金归发卡商户预收，平台不代收、不介入该笔资金的归属**；退款规则由发卡商户自行负责。
- 商户级卡是否可退、退多少比例由发卡商户自设规则（可设为不可退）；综合体通用卡**未消费本金默认全额可退**，**赠送金不退现**、未使用部分按活动规则作废或收回（与 §4.4 一致；2026-08-04 用户裁决澄清，原「默认全额可退」易被误读为含赠送金）。
- 商户级卡同样可以设赠送，每笔充值一样拆为本金与赠送金两段分别记账；**赠送比例由发卡商户提出、由平台运营代为录入后台，商户不自行改动**。该比例须同时具备商户级卡自身已批准的下限与上限并落在闭区间内；缺少任一边界、边界未经批准或比例越界时，平台不得发布或启用该赠送规则。不得拿通用卡的比例区间代替商户级卡区间，本文不预设具体数值。
- 该笔**赠送金的资金与成本全部归发卡商户承担**，平台不介入、不代垫、不从平台侧结算款中扣除。
- **退出公告义务**：发卡商户**退租、合同终止或被清退前**，必须提前公告告知持卡消费者本商户即将结束租赁关系，并同时给出该卡在剩余期间的使用条件与退款条件，含五项：**可用到哪天、能否退、退多少比例、怎么退、找谁退**。公告须在**客人手机应用、小程序和该商户的商场店面三处同时公示**；公示期不少于后台配置的天数（业务参数，全平台统一可配，须同时配置上下限），缺少任一上下限时不得上线。

### 4.10 通用规则

- **每笔充值固化当时的收款主体、发行主体、各通路的通道费率和退款规则版本。**
- 消费时**按客人指定的某一张卡扣减，不自动跨卡**。
- **商户员工只能管理本商户发行的储值卡。**
- **每笔充值分别记录两个时间**：**下单时间**是客人提交这笔充值的时刻，**支付时间**是这笔钱支付成功的时刻；两个时间各记各的，不能拿下单时间当支付时间用，没付成功的支付时间就空着。

## 5. 本金与赠送金双科目

每笔成功充值必须拆分为：

- 本金：客人实际支付进入储值的金额；
- 赠送金：活动或规则赠送的金额，没有赠送时为 0。

控制要求：

- 固定额、比例、阶梯或活动档的赠送规则必须由系统配置并版本化，禁止写死（本条只针对**赠送规则**；**消费扣款顺序**按 §4.2／§6 写死，不属于可配项）。其中赠送比例须按 §4.8／§4.9 分别使用通用卡或商户级卡自身已批准的上下限；缺边界、未批准或越界的比例版本不得发布或启用。
- 账户必须分别保存本金余额、赠送金余额、来源和活动引用。
- 客人可以查看总可用余额；后台和对账必须能拆分本金与赠送金。
- 客人端“我的余额”必须按本金／赠送金、通用卡／商户级卡分列，并逐笔展示充值、扣款、退款和回冲明细。
- **实现现状（2026-10-17 CG-06a）**：V444 起 `customer_stored_value_accounts.principal_cent / bonus_cent`（余额＝两段之和）与 `customer_stored_value_transactions.principal_cent / bonus_cent`（带方向）两段分别记账；充值入账时本金＝实付，赠送金＝实付 × 项目赠送比例（`stored_value_bonus_policies`：按项目配置，值与上下限同在、取值须落在闭区间内，未配置的项目不赠送；仅综合体通用卡，商户级卡赠送口径待裁决）；客人端 `我的余额` 账户与逐笔记录按本金／赠送金分列。活动来源引用、规则版本化、运营端三维台账尚未落地。
- **运营端储值台账（2026-08-19 补，依据 BSM「储值」条 / ENUM「储值卡类型与收款主体」条现文；DEC-R8-97-21）**：**运营端提供储值台账，可按客人、商户、期间查询逐笔明细与余额构成**——三个查询维度均为必备能力。
- 余额不得为负。

## 6. 消费扣款顺序

- **综合体通用卡的扣款顺序写死为先扣本金、后扣赠送金，不可配置。**
- **唯一例外为商户级卡**：扣款顺序由发卡商户自定，由平台运营代为录入后台。
- 扣款顺序须在客人充值之前告知。
- 单次消费可以形成多科目流水；当前科目不足时按有效顺序使用下一科目。
- 两科目合计不足时拒绝储值扣款或按收银合单规则处理，不得静默透支。
- 每次扣款必须具备幂等性并关联原消费订单。
- **实现现状（2026-10-17 CG-06a）**：通用卡消费先扣本金、后扣赠送金（代码写死）；商户级卡按 `stored_value_merchant_refund_rules.consume_order`（principal_first / bonus_first，由平台运营经商户储值卡配置代录）扣减；消费流水记录扣减的本金与赠送金各多少。

## 7. 退款、冲正与混合支付退款

- **退卡只退未消费的本金**；赠送金不退现。
- 退款或部分退款时，退回该卡余额，并**按扣款的相反顺序回冲**：**先回冲该笔消费中已扣的赠送金，赠送金回冲完毕后再回冲本金**；不使用其他分摊口径。
- 应退现金只从本金科目产生。
- **赠送金在持卡期间不设有效期、不因活动期结束而作废**（DEC-R8-98-02 用户裁决；依据 BSM「储值」条现文「余额不设有效期、长期有效」）；**作废或收回只发生在退卡与账户注销两个出口**——**退卡时赠送金不退现、未使用部分按活动规则作废或收回**（§4.4），**销户时赠送金清零**（§9）；任何情形下都**不得擅自转为可提现金额**。<!-- 改（2026-08-19）：删除持卡期内「按活动有效规则作废」分支，该分支与 D12「余额不设有效期、出口只有三条」相抵 -->
- 储值与其他支付方式混合支付时，储值段按本文处理，其他支付段按原支付通道规则退回。
- **实现现状（2026-10-17 CG-06a）**：退卡（线上退款与柜台退款）只退未消费本金——退款额超过本金即 409 `STORED_VALUE_PRINCIPAL_INSUFFICIENT`；销户（close_account 且本金退清）时未使用赠送金作废并留一条 `adjust` 流水、卡置 closed。**消费退款回冲到卡的路径（先回冲赠送金再回冲本金）在代码中尚不存在**（酒吧账单与票务订单的储值支付均无退回卡余额的实现），本次只在消费流水上留存两段扣减额供回冲使用；回冲顺序待回冲路径实现时落地（见 CG-06a PR 待裁决）。
- **实现现状（2026-10-20 第十批 TK-19 / TK-20 / TK-21 及复核修复，覆盖上条「回冲路径尚不存在」的旧登记）**：通用卡每笔充值按支付通路与支付成功时固化的费率分批保存剩余本金；消费需扣本金时按消费前各批剩余本金比例分摊并逐批按原费率计通路费；消费退款回原消费卡，先回冲赠送金、后回冲本金，各段累计不超原扣，通用卡本金按原分摊比例恢复到原批次；卡已关闭（或商户卡账户关闭待退期间）收到消费退款时本金登记待退本人、赠送金作废，不加回卡、不恢复批次；酒吧账单退款 / 退品与票务退款的储值部分回原卡，退品驳回按原回冲额扣回并冲减该笔消费的已回冲累计；**综合体通用卡退卡一次退还全部剩余本金、赠送金清零、卡关闭，不支持只退一部分**（操作员裁决 2026-10-20 第三轮第 7 条）。
- 各类阈值必须由系统配置、审批并版本化；**赠送金不设持卡期内的作废时点，也不存在可配置的作废时点参数**（DEC-R8-98-02）；**赠送金不退现与回冲顺序为固定口径，不得由配置改写**。

## 8. 冻结与账户状态

| 状态 | 含义 |
|---|---|
| `ACTIVE` | 可按规则充值、消费和退款。 |
| `FROZEN` | 暂停消费；解冻、退款或调整按授权流程处理。 |
| `CLOSED` | 账户已关闭，不再允许新入账。 |

- 账户冻结、解冻、退款和调整必须留痕。
- 账号处于封禁、黑名单或注销限制时，储值账户按适用规则停止使用。
- 客人端只读展示余额与流水，不得绕过后台状态控制。

## 9. 账户注销

注销前必须处理：

- 未完成订单占用；
- 冻结金额；
- 在途退款。

注销处理：

- **销户时先解除全部占用与冻结，再退剩余本金；赠送金清零。**
- 剩余本金按退卡、原路或系统有效配置退回。
- 客人选择放弃储值卡余额径行注销的，放弃余额归发卡主体：通用卡归长沙项目公司，商户级卡归发卡商户。
- 注销后账户不得再入账。
- 全流程保留申请、审批、金额、科目、原因和时间。
- **账户关闭（列入黑名单）的储值处置**（BSM「储值」：「出口只有本人消费、退卡、账户注销、账户关闭四条……账户关闭的，储值本金退还本人」）：CG-06b 实现现状（2026-10-17）：平台拉黑客人账号（`POST /api/v1/customer-accounts/{customer_id}/blacklist`，即关闭账户）后，`CustomerService.blacklistCustomer` 同事务调用 `StoredValueService.closeGeneralCardsOnAccountClosure`：该客人名下每张综合体通用卡的未消费本金全额沿线上退款出账路径退还本人（退款打款登记到 `finance_refunds`，退款执行主体＝长沙项目公司），未使用赠送金作废留 `adjust` 流水，卡置 closed；商户级卡不动、由发卡商户按自设规则到店办理（柜台退卡路径保持可用）；重复拉黑不重复退。系统发起的退款不受客人黑名单闸拦截。客人自助注销（`/api/v1/customer/deregister`）目前只改账户状态，未退剩余本金、未清零积分与券、未处理未核销票（见 CG-06b PR 待裁决）。

- **实现现状（2026-10-20 第十批 TK-21 及复核修复）**：账户关闭（拉黑）/ 注销时，通用卡未消费本金登记退还本人的退款事项；商户级卡按发卡商户规则登记发卡商户名下的待退本金事项、卡冻结，该事项**只能由发卡商户柜台退卡结清**，财务退款执行与结果确认一律拒绝；生成事项后通知发卡主体获授权人员——商户卡发给该发卡商户内持储值退款权限的员工，通用卡发给长沙项目公司持财务退款执行权限的员工（有手机号才发）；客人可在注销预览中看到各卡本金 / 赠送金并选择放弃余额径行注销。

## 10. 余额迁移

- 禁止会员储值余额在账户间迁移。
- 禁止本金或赠送金在综合体通用卡与商户卡之间迁移。
- 禁止会员 A 向会员 B 转移储值余额。
- 需要资金转移时，只能合法退回本金后重新充值，或由未来另行批准的合规产品承接；不得默认开启迁移。

- **不可转赠、不可过户（2026-08-19 补，依据 BSM「储值」条 / ENUM「储值卡类型与收款主体」条现文；DEC-R8-97-12）**：**储值卡余额不可转赠、不可过户，只能由本人账户消费。**
- **不设有效期（同上依据）**：**余额不设有效期、长期有效**——本金与赠送金同此口径，**赠送金在持卡期间不因活动期结束而作废**（DEC-R8-98-02 用户裁决）。
- **出口只有三条（同上依据）**：**本人消费、退卡、账户注销**，各按既有规则执行（退卡见 §4.4／§7，注销见 §9）。


## 11. 与会员积分的边界

- 储值本金和赠送金不是积分或成长值。
- 会员使用储值余额完成实际支付时，该支付结果是否计入有效消费，由 `docs/points-and-voucher-product-prd-v1.0.md` 定义。
- 储值充值本身不产生积分或成长值，也不刷新积分有效期。
- 储值退款不直接修改积分规则；消费订单退款事实交由积分域按原订单版本处理。

## 12. 系统化与审计证据

卡类型、资金归属、赠送规则、科目、扣款顺序、退现规则、账户状态、审批、生效时间和版本必须由系统承载，不以线下表格或口头决定代替；赠送比例版本还须留存其卡类型、已批准下限、已批准上限、实际取值、审批记录与拒绝原因，通用卡和商户级卡不得共用同一条边界记录。

每笔充值、消费、退款、冲正、冻结、解冻和注销至少保留会员、账户、项目、商户、订单、金额、科目、原状态、新状态、规则版本、处理主体和时间。

**运营端储值台账（2026-08-19 补，依据 BSM「储值」条现文；DEC-R8-97-21）**：**运营端提供储值台账，可按客人、商户、期间查询逐笔明细与余额构成**；客人端逐笔展示口径见 `customer-app-miniapp-product-prd-v0.1.md` §3。

- 储值充值到账与储值消费扣款属于客人金额变动，系统须发送短信；该类短信不得按类或按条关闭。积分相关事项不发送短信。
- 公共经营大屏不得展示可识别个人的储值余额、充值情况或个人排行榜，只能展示匿名、聚合或非个人经营信息。

## 13. 验收标准

1. 充值未支付成功时不增加本金或赠送金。
2. 本金和赠送金分别记账；通用卡扣款顺序写死先本金后赠送金、不可配置，仅商户级卡由发卡商户自定并由平台运营代录。
3. 赠送金不退现，退款按扣款相反顺序回冲（先赠送金后本金），余额不得为负。
4. 商户级卡不能跨商户使用，单次消费不自动跨卡；商户员工只能管理本商户发行的储值卡。
5. 余额不能在卡、账户或会员之间迁移。
6. 储值充值不产生积分、成长值或积分有效期刷新；充值是预收款、不计任何商户营业额，实际消费才按消费营业日计入该商户营业额与抽成基数。
7. 通用卡充值资金由长沙项目公司收取并挂预收款，赠送成本由长沙项目公司承担、不得摊给商户；商户级卡充值资金归发卡商户预收，平台不代收。
8. 商户级卡发卡商户退租、合同终止或被清退前，已在客人手机应用、小程序与商场店面三处同时公示五项退出信息，且公示期不少于配置天数；公示期缺少已批准下限或上限时不得上线。
9. 本文不再定义会员等级、积分获取、虚拟券或积分结算。
10. 通用卡与商户级卡赠送比例分别使用各自已批准的上下限；缺少任一边界、边界未经批准或比例越界时，对应赠送规则不得发布或启用。阻断不改变两类卡的收款与成本主体、扣款顺序或退款回冲规则，也不得以另一类卡的区间替代。
