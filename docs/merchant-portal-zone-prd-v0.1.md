# 商户侧与商户专区产品口径 PRD V0.22

> 版本：V0.22 ｜ 最后更新：2026-10-29 ｜ 状态：现行 PRD
> 业务最终解释权：三份业务 HTML。本文同时记录当前实现；当前页面、接口或终端不足时，标为实现差距，不能据此缩小 HTML 的商户侧能力。

## 1. 定位与终端

商户侧不是平台后台，也不是只读小窗口。商户在自己的合同、空间、业务和权限范围内完整使用相关功能，但不能看平台全局或其他商户数据。

HTML 明列两类商户终端：

1. 商户网页门户。
2. 商户手机应用。

当前商户网页门户为复用 Web 管理壳的 `/admin/merchant-zone/*` 商户网页专区，并用 `accountForms: ["merchant"]` 隔离商户形态账号。商户手机应用已落地（第十八批 J 段第 25 条，2026-10-29）：`apps/merchant-app` 用 Capacitor 8.5.3 原生壳（Android、iPhone）以商户手机应用模式挂 `apps/web` 的同一后台外壳与页面，不另写页面；只许商户账号登录（带商户归属、且不是平台账号或外包机构账号，否则 403 `MERCHANT_APP_ACCOUNT_REQUIRED`），登录端由会话决定为 `merchant_app`，总开关、模块开关与灰度按会话判，改报网页门户或 Web 的终端码也绕不过；页面范围按 BSM「商户 App」字面（「在授权业务范围内移动处理本商户经营、对账、结算和看板」），比商户网页门户少供应/库存与员工——库存与经销、账号权限、人事与员工车辆（ADM-MER-009）在 App 里不显示，直链进入提示「此功能请在商户网页门户办理」、不发该页请求。复用现有前端壳只是当前实现方式，不代表商户侧在业务上属于平台后台。

酒吧系统和游乐/乐园系统还须保留未来各自独立成为单独系统并对外提供的能力；当前复用平台壳不改变该边界。

商户网页门户和商户手机应用均适用统一的终端开关、权限、数据范围、访问拒绝留痕和兜底关闭规则。

## 2. 账号、权限与数据边界

- 当前商户网页专区使用带 `merchant_id` 归属的既有账号体系，页面只对商户形态账号显示。
- 后端以当前账号的 merchant scope 过滤账单、工单、对账、合同、分红和费用接收人；跨商户读写拒绝并留痕。
- 商户侧在授权业务范围内全开放；“完整使用”不等于自动拥有全部权限，仍受合同、空间、业务范围、岗位权限和终端开关共同约束。
- 商户的客人属于该商户；商户可查看本商户客人的全部对接信息，但不得查看其他商户客人或平台全局数据。
- 未获价格权限的商户人员，即使业务计算使用了内部结算价，也不得查看或修改该价格。
- 查看、导出、修改分别授权；查看权不自动包含导出权，修改权也不代表可以绕过审批让价格或合同直接生效。
- 后台、商户专区和员工手机端的在线页面都带可反向推算账号、设备和打开时间的暗纹。敏感页文字不可选中、不可复制，不提供另存和打印；打开敏感页本身须留痕。商户专区与后台同一外壳，页面暗纹与敏感页防护随外壳生效（第 23 条 23-R2、23-R5，敏感页清单见平台治理 PRD §15A.3）；商户专区各页没有必须强制脱敏的两类内容，不是敏感页（费用通知接收人手机号按 DEC-R8-40 不属清单内项），商户账号能打开的敏感页同样受保护。商户手机应用用同一外壳，暗纹与敏感页防护照样生效；暗纹与导出密码里的设备编号按第十八批裁决 19（操作员选「同网页端发编号（推荐）」：第一次登录时系统发一个设备编号，存进 App 的系统安全存储并在后台登记，暗纹和导出密码用它；卸载重装或清除应用数据算新设备）：首次登录由系统发 `WB`＋12 位编号，登录成功后登记在 `browser_devices`（与网页端同表，不发浏览器编号 Cookie），随登录响应 `device_id` 下发；App 把它与访问令牌一起存进系统安全存储，下次登录与续期带回，编号即该会话设备编号；退出登录与会话过期只清令牌、编号保留；新装或清除应用数据后先清空安全存储（iPhone 卸载不清钥匙串，靠安装标记判断），Android 关闭系统自动备份，即成新设备（平台治理 PRD §15A.2「实现现状（第 25 条 25-R2）」）。

### 3.3 账单类型十二项、费用总表与综合账单

固定租金、每平米租金、营业额抽成租金、物业费、能源费、会员系统服务费、积分发行费、押金、违约金、工单用料费（商户承担）、违规罚款、车位月租（ENUM「租金/账单类型」，ENUM:256）。电损、水损成本统一纳入物业费，不再单独收取电损费、水损费（ENUM:199）。

费用总表须列明全部费用名目、计费基数、承担方与本期金额；综合账单须把当期各名目汇总成一张账单，使商户一次看清全部应付（BSM:1323）。第十八批 E 段第 21 条落地：ADM-MER-003 页上方「费用总表」「当期综合账单」两块，放在账单列表之外、没有账单时也显示；`GET /api/v1/merchant-portal/fee-statement?month=YYYY-MM`，权限 `merchant.billing.view`，无商户归属 403 `MERCHANT_SCOPE_REQUIRED`，月份非法 400 `VALIDATION_FAILED`；只读，不新建收费。

- 费用总表：上述十二项加门票综合服务费（BSM:1713、BSM:755）、停车抵免成本（BSM:1445）共十四个名目，每行名目、计费基数（只抄 HTML 原句，HTML 没写的违规罚款留空）、承担方（本商户）、本期金额。会员系统服务费、工单用料费（商户承担）、违规罚款当前没有出账路径，本期金额显示「本期未出账」，页面不伪造数据；其余名目当期没有出账为 0。
- 本期＝计费自然月（BSM:1673「自然月计费、次月出账」、BSM:1688），页面可选月份，缺省北京时间当月。月份依次取内部应付计划的计费月、物业费计费单的期、应收台账账期、到期日所在月，一律取冲正链最早那张原行的（冲正行、重述行沿原行指向一直追到原行），冲正与重述跟原行同月、计入净额；门票综合服务费计费月已付清后退票只挂的应退，按所属计费月从该名目扣除（BSM:755「重算原计费月服务费总额」），金额、已付、未付都按净额，未付可为负。
- 取数只来自应收应付台账已出账的应收：往来对方是本商户（积分发行费的往来对方是销售主体，按台账 merchant_id）；merchant_id 是本商户但往来对方是公司的（如派驻提成拨付）不计入。合同租金按所属合同收租方式归名：只收固定租金的按计租方式归固定租金或每平米租金，纯提成、保底与抽成取高、保底加抽成叠加一律归营业额抽成租金（ENUM:257），金额照原值、不拆分。通路费、销售渠道费由支付通路与第三方售票平台收取（BSM:749），商户处罚只扣健康分，均不列。
- 综合账单列当期各名目的金额、已付、未付与合计；名目目录之外的本商户应收（如存酒退出承接垫付追收、通票分账追收、手工录入）在综合账单照列，名目用台账来源中文名，使商户一次看清全部应付。

## 4. 工单边界

商户服务工单与设施/物业工单分表承载，两句 HTML 同时适用：

- 商户服务工单：V022 `merchant_service_work_orders`。商户在商户专区自助发起报修 `repair`、保洁 `cleaning`、投诉 `complaint` 和其他服务请求 `service`，并查看进度（第十八批 K 段第 93 条 93-R1：类型闭集按裁决 D-12、D-13 改为这四类，V582 工单表与处理时限表两处 CHECK 同改；整改不归商户自助）。HTML 七态为已提交、已派单、处理中、待商户确认、已处理待关闭、已关闭、已取消；当前代码值为 `created/assigned/processing/pending_merchant/resolved/closed/cancelled`，专区页面把第五态 `resolved` 显示为“已解决”，与 HTML“已处理待关闭”尚未对齐。超时自动升级并标记。实现现状（第十八批 I 段第 77 条）：处理时限按「工单类型×优先级」在后台 ADM-MER-001「处理时限」配置（`GET/PUT /api/v1/merchant-service/work-order-policies`，持 `merchant.service_work_order.assign`、平台口径，商户与外包账号 403；V577 `merchant_service_work_order_policies` 只有处理时限、不预置出厂值），建单时截止时间＝建单时刻＋处理时限，请求体不再给截止时间，未配置的组合不设截止时间、不升级（77-R3）；定时作业升级标记的同时，给持派单权限 `merchant.service_work_order.assign`、有员工档案、派单码可触及该商户任一经营项目（主项目或追加的经营项目，裁决 M737-iter7）的平台员工各发一条系统通知，商户账号与外包账号不收（77-R2）。后台 ADM-MER-001 只派单、处理、关闭并配置处理时限，不代商户建单（第 93 条 93-R2）。读与处理（第 93 条 93-R3，BSM:1385「工单由客户关怀部负责处理」）：平台管理员看全部（D-032）；商户账号只见本商户；其余非外包平台员工只见、只能处理入口权限码可触及项目内经营的商户（主项目或追加的经营项目，含可跨项目角色勾选的项目，裁决 M737-iter7）的工单，越范围 403 `CROSS_PROJECT_FORBIDDEN`；外包账号 403；建单仍只由商户账号在商户专区发起。
- 设施/物业工单：V166 `facility_work_orders`。平台发起的整改与巡检、巡检异常、设备告警以及现场工作人员报的单落设施/物业工单（可带商户编号），按设施工单状态和验收分支处理；商户专区自助提的单不进这张表（裁决 D-13）。

两类工单不合并主表、不互相映射状态；看板分行对照。整改与巡检类工单由平台发起（BSM:1385），商户不能自助提整改。设施/物业工单的响应时限与处理时限须对商户公开；商户服务工单没有“首次响应”环节，不显示响应指标，也不拿别的数字冒充，超时仍自动升级并标记。

## 5. 证照、资质、保险和合同日期

- 合同到期、续约及其他合同所在地日期判断，以合同对应门店/点位的当地时间为准，不使用服务器默认时区。
- 到期预警按证照类型可配，出厂默认提前三个月，必须同时配置上下限；预警同时送达商户侧。
- 商户在商户专区查看本商户全部证照到期情况。
- 证照或资质到期后，只能申请一个后台可配时长的宽限期；宽限期按证照类型可配且有上下限，经最高权限审批后生效。
- 宽限期内可继续经营但每日提醒；超过宽限期仍未更新的一律阻断，不得再次延长。

第十八批 E 段第 22 条落地（V568）：

- 按证照类型配置（ADM-COMP-001「按证照类型配置宽限期与预警提前量」，`GET /api/v1/compliance/item-type-configs`、`PUT /api/v1/compliance/item-type-configs/{item_type}`）：全平台统一、九类各一行；宽限天数与预警提前月数各自「值、下限、上限」同时填写或同时留空，0 ≤ 下限 ≤ 值 ≤ 上限；预警未配置按出厂提前 3 个月；宽限期 HTML 未给出厂值，不预置，未配置的类型不能申请；保险不适用宽限期（宽限句只写「证照或资质」）。商户账号即便持 `compliance.expiry_item.manage` 也不能改（403 `PLATFORM_SCOPE_REQUIRED`）。
- 预警与送达：每日 08:00（北京时间）自动扫描全平台证照，扫描日不早于「有效期止减该类型提前月数」即生成到期预警，过了有效期止生成已到期提醒，提醒文字为中文；提醒行带商户编号，商户在 ADM-MER-010 可查看即送达，不发短信（BSM:1597 商户短信清单没有证照）。合同关键日期的提醒窗口不变。
- 宽限期：商户对本商户已到期的证照或资质申请（`POST /api/v1/compliance/expiry-items/{id}/grace-requests`，权限 `compliance.grace_period.request`），从到期次日起算、申请时固化截止日＝有效期止＋该类型宽限天数，提交即进统一审批的最高权限策略，批准才生效；在审期间照旧阻断，驳回的可再申请；本次到期已获批的不得再申请，超过截止日不得再申请。宽限期内资质到期阻断（准入闸 `qualification_abnormal`）放行，并每日生成一条宽限期提醒；超过宽限期仍未更新的照旧阻断。到期与截止判断一律按北京日历日。
- 续期登记（ADM-COMP-001 证照行内「登记续期」，`POST /api/v1/compliance/expiry-items/{id}/renewal`）：新的有效期止必须晚于原值；登记后不再按原到期阻断，原宽限申请随之清空，新到期可重新申请；「我的证照」的「即将到期」只认本次有效期止的到期预警，原有效期的预警只留在预警记录里。

当前 `LocalZone.ID` 固定为 `Asia/Shanghai`，只承载当前单地合同日期判断，尚未满足跨地区合同日期规则。

## 6. 商户异议

### 6.1 通用规则

- 商户投诉与异议和客人投诉并入同一通道，由客户关怀部统一受理。
- 商户只能对数字提出异议，包括漏算、少算、多算；不得对规则本身提出异议，规则以合同约定为准。
- 提出异议期间付款义务不暂停，先按原值付款；异议成立后多退少补。
- 独立酒吧商户异议由客户关怀部协调，经内部工单流转至相关部门并形成完整闭环。处理时限按项目可配，出厂默认二十个工作日，必须配置上下限；处理期间按原有效数值结算，结论生效后按差额补退。

### 6.2 异议期

- BSM「给商户」所定的异议期只适用于房租、水电、物业、结算金额出账与调整、押金、违约金、分红七类非积分商户账单；积分结算账单的账期与异议期由全国积分结算中心统一规定，两者互不包含。
- 上述七类账单的异议期自账单在商户专区可查看之日的次日起算；长度按项目可配，出厂默认十个工作日，须同时配置上下限。营业额抽成账单另按其专门条款配置异议期长度并同时配置上下限，同样从账单在商户专区可查看之日的次日起算，不继承十个工作日的出厂默认值；其他未被 HTML 指定适用范围的账单不得自行套用该默认值。
- 短信和商户手机应用推送只是提醒；无论是否发送、发送是否成功，都不影响异议期的起算与届满。
- 只有商户专区在项目时区一个完整自然日全天不可用，该日才不计入；部分时段不可用不顺延。
- 商户未登录不顺延；首页未读账单提醒不因异议期届满而消失。实现（第十八批 K 段第 92 条）：未读账单＝我的账单当期综合账单所列本商户台账行、我的对账「门票分账」里已可查看且应付本商户的往来、我的分红里审批通过（含已发放）的分红单；商户在商户专区看过即记已读，按商户记（同商户任一账号看过即算），登录不算读，不设任何按时间消失（`GET /api/v1/merchant-portal/unread-bills`，页面见 §8）。
- 押金退还不受三个付账日与账单异议期约束；商户对退租结算金额的异议在退租审批流程中提出并解决。押金退还以退租结算算账完成为准，且不早于等待期届满；等待期自最后一个审批完成日起算，按项目可配，出厂默认三十日并须同时配置上下限，用于让退租日之前按期出账的能耗费、物业费等全部形成应收并从押金中结清；期间新出账费用自动并入同一次退租结算，不另立新单。同一合同退租结算只算一次、不重复出账。商户对退租结算金额提异议后，结算单进「有争议」挂起、最后审批不得通过，主管裁决（写结论留痕）后回待结算继续审批；主管裁决后商户可在「我的对账」该结算单上点「不接受裁决」（必填理由），结算单进「有争议，诉讼/仲裁」无限期挂起，诉讼或仲裁有结果后由主管在后台录入结果继续审批（2026-10-18 裁决第 5、6 条）。算账晚于等待期完成的，顺延至算账完成日支付，顺延原因和预计时间须在商户专区对商户可见。「我的对账」结算单列「预计退押金日期」（＝押金退还应付到期日），顺延时同列另显示顺延原因与预计支付日期；未落账的结算单显示「-」（HP-C06）。

## 7. 导出与敏感页面

商户侧不是一律禁止导出：HTML 明确商户查询和导出属于本商户的客户信息不脱敏。所有商户导出仍必须满足：

1. 导出单独授权，查看权不自动带出导出权。
2. 每次导出留痕，记录导出人、时间、设备、内容范围和筛选条件；记录永久保存。
3. 文件一律带密码和暗纹，不可复制、不可编辑；可编辑版本另行申请并经最高权限审批。
4. 除“本商户客户信息”例外外，其他个人信息和敏感经营数据按 HTML 自动判定并强制脱敏，导出人不得关闭或规避。

当前商户专区六页没有完整导出功能。该事实只能标为当前实现差距，不能写成永久业务禁令。
