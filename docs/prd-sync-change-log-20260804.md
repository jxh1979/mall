# PRD 同步变更台账（2026-08-04）

## 0. 本轮同步的目的

本轮同步的目的是把各份 PRD 的业务口径**对齐三份业务 HTML @97240c7b**，消除 PRD 与唯一事实源之间的缺失与冲突，使 PRD 不再出现比 HTML 更旧、更松或相互矛盾的口径。

本文件是本轮 PRD 同步的**逐条变更台账**：每一条被修改的 PRD 内容都在此登记修改前、修改后、依据来源与处理规则，供 Fable 5 验收与后续审计逐条核对。

## 1. 事实源优先级

1. **三份业务 HTML（唯一事实源，最高优先级）**
   - 业务系统地图 `docs/business-system-map-for-operations-v0.1.html`（下称 **BSM**）
   - 平台治理地图 `docs/platform-governance-map-for-operations-v0.1.html`（下称 **PGM**）
   - 业务枚举速查 `docs/business-enum-quick-reference-v0.1.html`（下称 **ENUM**）
2. HTML 历史台账 / 业务裁决记录（如 `business-decision-log`、DEC-Rx-xx 裁决编号）
3. Git 历史（用于确认变更时点与来源，不单独构成业务依据）
4. PRD、开发设计、OpenAPI、迁移与代码（**均不得覆盖 HTML**）

铁律：三份 HTML 在本轮中**只读**，是修改依据本身，不得因 PRD 同步而被改动。HTML 未记载的新规则须经用户批准并写入 HTML 后方可生效。

## 2. 四类处理规则

| 编号 | 情况 | 处理方式 |
|---|---|---|
| 情况 1 | **HTML 有、PRD 无** | 按 HTML 口径在 PRD 补写，标注依据行号 |
| 情况 2 | **HTML 与 PRD 冲突** | **以 HTML 覆盖 PRD**，改写 PRD 表述 |
| 情况 3-A | **PRD 有、HTML 无，且有据可删** | 有明确台账/裁决支持删除的，删除并登记依据 |
| 情况 3-B | **PRD 有、HTML 无，且无据** | **不动**，登记为待用户裁决事项，不得自行删改 |

本批（第 1 批：治理/终端组）不涉及情况 3-B。

**CL 编号说明**：第 1、2 批与返工台账使用 `CL-xx` 连续编号；**第 3、4、5 批因并行实施，分别采用 `B3-` / `B4-` / `B5-` 前缀独立编号，与 `CL-` 序列并行有效**，两套编号均为本台账的正式条目，不存在从属或替代关系。收尾修复回到 `CL-` 序列（CL-43 起）。
