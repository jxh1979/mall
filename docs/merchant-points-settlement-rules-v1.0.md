# 商户积分结算规则 V1.0

日期：2026-08-01
状态：现行权威文档
上位设计：`docs/superpowers/specs/2026-07-28-member-points-settlement-redesign-design.md`

## 1. 文档定位

本文是商户参与义务、积分发行费、会员系统服务费、营销费用、项目价格、兑换定价、核销补偿、账单、收付款、冲正和税务凭证要求的唯一完整业务定义。

以下规则由其他权威文档定义：

- 会员身份、成长值与等级：`docs/member-and-tier-product-prd-v1.0.md`。
- 积分产生、冻结、有效期、兑换流程与虚拟券：`docs/points-and-voucher-product-prd-v1.0.md`。

其他文档只能引用本文，不得复制形成第二套商户积分结算规则。

## 2. 目标与非目标

### 2.1 目标

- 明确全国积分结算中心、项目、商户与营销活动成本承担主体的职责。
- 统一商户应付和结算中心应付的双向总额记账。
- 建立项目级零售参考价和项目级内部结算价。
- 用双下限约束纯积分和积分加现金兑换方案。
- 明确发券不结算、核销才补偿。
- 形成可审计的自然月账单、跨月冲正和税务凭证链路。

### 2.2 非目标

- 不定义积分获取公式、积分冻结或会员等级门槛。
- 不把全国积分结算中心定义为商品或服务转售方。
- 不用本文替代合同、会计判断或税务专业判断。
- 不规定代码、接口、数据库或页面实现。

## 3. 统一术语

| 术语 | 定义 |
|---|---|
| 全国积分结算中心 | 与商户统一签约、收付款并执行积分结算的法律主体。 |
| 项目 | 价格、活动和经营数据的独立核算维度，不等同于结算法律主体。 |
| 商户 | 直接向会员销售商品或服务并负责履约的经营主体。 |
| 积分发行单价 | 商户对每一枚已确认积分向全国积分结算中心支付的单价。 |
| 积分兑换结算单价 | 积分发行单价乘平台兑付系数，只用于兑换定价覆盖校验。 |
| 零售参考价 | 同一项目、同一 SKU 在过去滚动 30 天的最低有效实际成交价。 |
| 内部结算价 | 项目与商户就兑换 SKU 约定、实际核销后用于计算商户补偿的项目级价格。 |
| 会员现金支付额 | 积分加现金兑换中由会员直接支付给履约商户的现金金额。 |
| 商户补偿 | 虚拟券实际核销后，全国积分结算中心按锁定规则应付商户的金额。 |
| 营销活动成本承担主体 | 活动发布时被系统锁定并承担活动费用的具体法律主体。 |
| 双向总额记账 | 先分别记录各方完整应收应付，再按合同判断是否净额支付。 |

## 4. 主体与职责

### 4.1 全国积分结算中心

- 作为统一签约和积分结算法律主体管理商户合同。
- 统一配置积分发行单价和平台兑付系数。
- 汇总查看并审计各项目价格，但不得把项目价格合并成全国统一价格。
- 审批低于兑换下限的特殊方案。
- 生成和结算商户账单，保存应收应付、冲正与税务凭证关联。

### 4.2 项目

- 作为价格、活动和经营数据的独立核算维度。
- 独立维护本项目零售参考价数据和内部结算价目录。
- 发起或承接积分兑换方案与营销活动。
- 不得覆盖全国积分发行单价、兑付系数或业态积分获取规则。

### 4.3 商户

- 在平台指定覆盖范围内识别会员并按平台规则发放基础积分和成长值。
- 接受退款、对账和审计，不得自行关闭会员积分能力或改变基础规则。
- 是否提供积分兑换 SKU 由项目另行配置和审批。
- 直接向会员销售商品或服务并负责履约。
- 全国积分结算中心不是商户商品或服务的转售方。

### 4.4 营销活动主体

活动发起方和成本承担方可以不同。成本承担主体可以是：

- 商户；
- 项目发起平台及其法律主体，例如娱乐平台公司、资产公司；
- 全国平台；
- 其他登记赞助主体。

## 5. 商户参与与合同边界

- 平台指定覆盖范围内的商户必须参与会员积分体系。
- 商户合同必须包含适用范围、积分发行费、最高等级倍率、会员系统服务费模式、生效期、结算和争议规则。
- 商户是否提供兑换 SKU 不影响其在覆盖范围内发放基础积分和成长值的义务。
- 商户不能在合同有效期内单方关闭或改变平台基础规则。
- 超过合同最高等级倍率前必须先完成合同变更并使新版本生效。

## 6. 双向总额记账

### 6.1 商户应付

系统分别记录：

- 已确认基础积分的积分发行费；
- 等级倍率增加的积分成本；
- 会员系统服务费；
- 明确由商户承担的营销活动费用；
- 商户承担的特殊补贴和调整项。

### 6.2 结算中心应付

系统分别记录：

- 已核销兑换券的商户补偿；
- 明确由结算中心承担的平台补贴；
- 明确由结算中心承担的调整项。

### 6.3 其他主体应收应付

营销活动或特殊补贴涉及其他法律主体时，系统按锁定的成本承担关系分别生成该主体的应收或应付。

### 6.4 禁止先净额化

- 各方应收、应付必须完整展示，不得先抵销后只保存净额。
- 月末只有合同明确授权时才计算净现金收付款。
- 旧的“净积分数量清算”废止；积分数量不是现金结算净额的替代物。

## 7. 积分发行费与会员系统服务费

### 7.1 积分发行单价

- 积分发行单价由全国积分结算中心统一配置。
- 同一有效版本不允许商户使用不同单价。
- 单价必须审批、指定生效时间并版本化，不追溯已确认积分。
- 只有消费积分转为可用后才形成积分发行费；冻结积分不收费。

### 7.2 会员系统服务费

- 会员系统服务费单独收取，使用独立账单行。
- 每份商户合同只能选择以下一种模式：
  1. 按有效会员消费金额的一定比例；
  2. 固定月费。
- 两种模式不得同时生效。
- 初期可以配置为 0；即使为 0，系统仍保存计费模式、计费依据、生效期和版本。

## 8. 项目级零售参考价

### 8.1 计算范围

- 零售参考价按项目隔离。
- 只使用同一项目、同一 SKU 的有效实际成交数据。
- 其他项目和项目外公开或非公开渠道均不参与计算。
- 同一 SKU 在不同项目可以形成不同零售参考价。

### 8.2 有效实际成交

- 有效实际成交指已完成、未被取消或作废的有价交易。
- 金额使用会员实际应付金额。
- 全额退款交易排除。
- 部分退款按最终保留数量和金额参与计算。

### 8.3 滚动 30 天最低价

- 系统自动取当前时点向前滚动 30 天内的最低有效实际成交价。
- 系统保存项目、SKU、订单、成交时间、成交状态、金额和计算快照。
- 零售参考价不得被直接手工覆盖。
- 数据纠错必须通过可审计的纠错流程重新计算。

### 8.4 新 SKU

- 新 SKU 尚无有效成交数据时，使用本项目首发公开销售价。
- 首发公开销售价必须在系统中审批后临时生效。
- 项目内产生有效实际成交记录后，系统自动切换为滚动 30 天最低成交价。

## 9. 项目级内部结算价

- 每个项目拥有独立的“内部结算价管理”页面、价格目录、审批记录和版本。
- 内部结算价不是全国统一价格。
- 同一商户或 SKU 在不同项目可以使用不同内部结算价，互不覆盖。
- 兑换 SKU 只能关联本项目已审批生效的内部结算价，不得跨项目引用。
- SKU 不得重复录入一份内部结算价；只保存对本项目价格目录版本的关联。
- 价格变更必须生成新版本、指定生效时间并保留历史版本。
- 虚拟券发放时锁定项目和内部结算价版本。

## 10. 兑换基础参数

### 10.1 平台参数

- 积分发行单价由全国积分结算中心统一配置。
- 平台兑付系数由全国积分结算中心统一配置，未配置时为 0.7。
- 两项参数均必须审批、指定生效时间并版本化。
- 新版本不追溯已发券记录。

```text
积分兑换结算单价 = 积分发行单价 × 平台兑付系数
```

积分兑换结算单价只用于验证兑换方案是否覆盖内部结算成本，不直接替代内部结算价，也不是商户实际补偿公式。

### 10.2 版本锁定

发券时锁定：

- 项目和 SKU；
- 零售参考价计算快照；
- 内部结算价版本；
- 积分发行单价版本；
- 平台兑付系数版本；
- 兑换方案；
- 成本承担关系。

## 11. 纯积分兑换

纯积分兑换只配置兑换积分数，不存在会员现金支付额。

```text
零售下限积分 = ceil(零售参考价 ÷ 积分发行单价)
结算下限积分 = ceil(内部结算价 ÷ 积分兑换结算单价)
最低兑换积分 = max(零售下限积分, 结算下限积分)
```

`ceil` 表示向上取整。普通方案的兑换积分数不得低于最低兑换积分。

示例：零售参考价 100 元，内部结算价 70 元，积分发行单价 0.1 元，平台兑付系数 0.7：

```text
积分兑换结算单价 = 0.1 × 0.7 = 0.07 元
零售下限积分 = ceil(100 ÷ 0.1) = 1000
结算下限积分 = ceil(70 ÷ 0.07) = 1000
最低兑换积分 = 1000
```

## 12. 积分加现金兑换

### 12.1 三项约束

积分加现金兑换必须同时满足：

```text
积分数 × 积分发行单价 + 会员现金支付额 >= 零售参考价
积分数 × 积分兑换结算单价 + 会员现金支付额 >= 内部结算价
会员现金支付额 <= 内部结算价
```

会员现金由会员直接支付给履约商户。

### 12.2 实际补偿

虚拟券核销后：

```text
结算中心应付商户补偿 = max(0, 锁定内部结算价 - 会员现金支付额)
```

商户从会员和结算中心取得的合计金额不得超过锁定内部结算价。

示例：锁定内部结算价 70 元，会员向商户支付现金 20 元，则核销后结算中心补偿 50 元。若会员现金支付额为 70 元，则补偿为 0。会员现金支付额不得超过 70 元。

### 12.3 非有效消费

积分加现金兑换整单不属于有效消费，不产生积分或成长值，也不刷新积分有效期。

## 13. 特殊审批

兑换方案可以在特殊审批后低于零售下限、结算下限或同时低于两项下限。

申请必须在系统中填写：

- 原因；
- 业务目标；
- 适用期限；
- 数量上限；
- 预计缺口；
- 申请人；
- 成本承担主体；
- 预算来源。

控制要求：

- 申请人与审批人分离。
- 由全国积分结算中心授权岗位审批。
- 低于结算下限时，活动发起方或其他明确主体必须锁定补贴预算。
- 预算不足时禁止发券。
- 全国积分结算中心不默认承担未指明的价格缺口。
- 审批必须锁定适用方案、项目、SKU、期限、数量和版本，不能作为永久空白豁免。

## 14. 发券、核销与补偿时点

- 发券时扣除积分、预占库存或履约能力并锁定全部版本。
- 发券不形成商户补偿应收，不与商户结算。
- 实际核销或完成履约时，预占转为实际消耗。
- 只有核销成功才生成商户补偿并进入结算账期。
- 券到期、合规取消或作废时释放未核销预占；积分是否返还由积分与虚拟券权威文档定义。
- 重复发券或重复核销不得重复记账或补偿。

## 15. 营销活动成本

### 15.1 发布前配置

每个活动必须在系统中绑定：

- 发起项目；
- 发起平台及其法律主体；
- 成本承担主体；
- 预算；
- 费用科目；
- 有效期；
- 审批记录。

### 15.2 多主体分摊

- 同一活动允许多个法律主体联合承担成本。
- 支持固定金额分摊或比例分摊。
- 比例合计必须为 100%。
- 固定金额合计必须覆盖活动预算。
- 各承担主体分别锁定预算。
- 任一必要预算不足时，活动不得发布或继续发放对应权益。

### 15.3 变更与超预算

- 活动发布时锁定分摊规则。
- 生效后变更必须走调整审批，只对后续业务生效。
- 系统按法律主体分别生成应收、应付、对账和税务凭证。
- 不得把多主体费用合并为无法追责的“项目费用”。
- 超预算费用不得自动转嫁给商户或其他参与方；必须暂停发放或完成追加预算审批。

## 16. 账单与收付款

### 16.1 账期

- 采用自然月账期。
- 商户每日可核对积分发行费、服务费、活动费用、核销补偿和调整明细。
- 次月生成上月月账单。
- 异议期为 5 个工作日；逾期未提出异议视为确认并封账。
- 每月 15 日统一完成上月净额收付款；遇法定节假日或非银行工作日顺延至下一工作日。

### 16.2 账单结构

账单至少分别展示：

- 商户应付各项总额；
- 结算中心应付各项总额；
- 其他法律主体应收应付；
- 调整和冲正；
- 合同授权下的净现金收付款；
- 关联订单、积分明细、券核销、活动、合同和价格版本。

## 17. 跨月退款与冲正

- 已封账历史账单不可修改或重开。
- 跨月退款、撤销或调整在发生月生成独立冲正单。
- 冲正单必须关联原订单、原结算明细、原月账单和原发票。
- 结算调整状态与发票红冲状态分别跟踪。
- 不得用修改历史账单代替当期冲正或税务处理。

## 18. 税务合规

- 一般计税和简易计税项目的扣减按业务发生时有效的中国增值税法律法规执行。
- 已开具发票后发生销售退回、折让、服务中止或开票错误时，按适用规则作废或开具红字发票。
- 数电发票红冲是否需要对方确认，按蓝字发票的用途确认和入账状态执行。
- 税率、税目、发票对象和流程必须依据交易实质、合同及届时有效规则在系统中配置，不在本文硬编码。
- 系统保存蓝字发票、红字确认、红字发票、进销项调整和冲正单之间的完整关联。
- 税务处理不能反向改变已封账历史账单；通过当期冲正和税务凭证关联反映。

现行官方依据入口：

- [《中华人民共和国增值税法》](https://www.npc.gov.cn/npc/c2/c30834/202412/t20241225_442015.html)，自 2026 年 1 月 1 日起施行。
- [《中华人民共和国增值税法实施条例》](https://fgk.chinatax.gov.cn/zcfgk/c100010/c5246349/content.html)，自 2026 年 1 月 1 日起施行。
- [《国家税务总局关于推广应用全面数字化电子发票的公告》](https://fgk.chinatax.gov.cn/zcfgk/c100012/c5236067/content.html)，国家税务总局公告 2024 年第 11 号。

## 19. 全面系统化要求

以下对象必须全部由系统承载：

- 积分发行单价和兑付系数；
- 项目零售参考价快照和内部结算价版本；
- 兑换方案和特殊审批；
- 合同、服务费模式和最高等级倍率；
- 营销费用、成本承担关系和预算；
- 发券版本锁定、核销补偿和库存状态；
- 应收应付、账单、收付款、冲正和争议；
- 发票、红冲及其关联；
- 申请、审批、生效时间和历史版本。

规则文件定义业务要求，但不能替代系统能力；不得依赖线下表格、口头决定或人工绕过。

## 20. 顺从性验收

1. 同一 SKU 在两个项目可以形成不同零售参考价和内部结算价，且不能跨项目引用。
2. 零售参考价只取同一项目、同一 SKU 滚动 30 天最低有效实际成交价，不含其他项目或外部渠道。
3. 新 SKU 在有效成交前使用经审批的本项目首发公开价，形成成交后自动切换。
4. 积分发行单价全国统一；积分兑换结算单价按统一兑付系数计算，默认系数 0.7。
5. 纯积分兑换同时满足零售下限和结算下限。
6. 积分加现金兑换同时满足零售覆盖、结算覆盖和现金不超过内部结算价。
7. 核销后补偿等于内部结算价减会员现金支付额且不小于 0。
8. 特殊方案低于下限时具备完整原因、期限、数量、缺口、成本承担和预算，并由结算中心审批。
9. 发券不产生商户补偿，核销才产生。
10. 商户应付与结算中心应付先按总额展示，只在合同授权下计算净现金付款。
11. 服务费按比例或固定月费二选一，可配置为 0 但仍保存版本。
12. 多个营销成本承担方按固定金额或比例分摊，比例合计 100%，预算分别锁定。
13. 自然月封账后历史账单不可修改，跨月退款在发生月冲正。
14. 发票红冲和结算冲正分别跟踪并完整关联。

## 21. 对抗性验收

| 反例 | 必须结果 |
|---|---|
| 全国中心把各项目内部结算价合成统一价格 | 阻断；价格保持项目独立。 |
| 项目把外部电商最低价纳入零售参考价 | 排除；只使用项目内成交。 |
| 直接手工降低零售参考价 | 阻断；通过数据纠错重新计算。 |
| SKU 关联其他项目内部结算价 | 阻断配置生效。 |
| 商户配置独立积分发行单价 | 阻断；使用全国统一版本。 |
| 纯积分数只满足零售下限、不满足结算下限 | 普通方案不得发布。 |
| 积分加现金中现金超过内部结算价 | 阻断方案。 |
| 特殊审批不写预算或成本承担方 | 不得批准或发券。 |
| 发券当日生成商户补偿 | 判为不合规并撤销错误账项。 |
| 同一活动多个比例合计为 90% 或 110% | 阻断发布。 |
| 超预算自动转嫁给商户 | 阻断；暂停或追加预算审批。 |
| 同一合同同时收比例服务费和固定月费 | 阻断计费配置。 |
| 月末只保存净额、看不到双方总额 | 判为不合规，必须恢复总额账项。 |
| 跨月退款回写上月封账账单 | 阻断；在发生月生成关联冲正。 |

## 22. 完成标准

- 商户参与、价格、费用、兑换下限、补偿、账单和税务边界只有本文一个完整定义。
- 纯积分与积分加现金公式可复算，项目归属和版本可追溯。
- 商户、结算中心和营销主体的成本责任清晰、守恒且不被静默转嫁。
- 所有规则、数据、参数、审批和版本均被要求由系统承载。
