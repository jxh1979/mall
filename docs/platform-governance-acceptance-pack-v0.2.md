# 平台治理层产品验收清单 V0.1

## 1. 文档定位

本文档用于验收平台治理层产品设计是否已经达到“可进入后续原型和编码拆解”的程度。

本文档不是开发测试用例，不是接口验收，不是数据库验收，而是产品设计验收清单。它用于检查《平台治理层 PRD》《页面清单》《字段字典》《关键流程图》《低保真原型说明》之间是否一致、完整、可执行。

## 2. 验收范围

本验收清单覆盖平台治理层 P0，包括：

- 综合体项目
- 空间对象（项目、楼层、区域、点位、商铺、卡座、吧台位、游乐入口、库房、设备点位）
- 业态
- 商户/运营主体
- 合同与合作关系
- 合同准入规则
- 员工注册审批、私人手机 App、设备凭证绑定和职级（"NFC 绑定"按 D8 改为"设备凭证绑定"，2026-06-07 收口，finding decision-land-1）
- 员工/岗位/班次
- 企业设备
- 角色权限与数据权限
- 终端开关
- 平台基础留痕
- 全局金额精度、涉税例外与非涉税尾差责任
- 合同本地 AI 待人工确认建议与合同所在地日期判断
- 外部经销商主体、合同价格、库存、付款出库、退货开票与资金治理

不验收票务定价、酒吧点单、游乐排队、第三方真实接口、财务深度结算、除本包合同辅助提示外的其他 AI 分析和编码实现；AI 不得自动替代合同台账、审批、阻断或放行。

## 2A. 现行 HTML 增量必过验收

| 验收项 | 必过标准 | HTML 依据 |
|---|---|---|
| 金额精度与税务例外 | 除涉税金额外，计算、存储、显示均四舍五入到分；涉税结果按业务发生时有效的国家财税、主管机关及专业系统规则形成并保留结果、依据和规则版本，不被平台统一舍入改写；多方非涉税尾差单独留痕并由实际结算责任主体承担，跨域组合通票尾差由娱乐平台公司承担 | PGM「全局原则 · 金额精度与税务例外」 |

| 经销商准入与隔离 | 企业主体、合同、开票和银行资料全部审核通过后才可启用独立经销商 Web 门户；经销商与商户、供应商分别建档并隔离账号、权限和数据；停用立即终止会话和系统对接授权，保留已完成订单及审计记录 | PGM/BSM 外部经销商治理、业务枚举速查表中的经销商状态与停用撤权现文 |

| 经销退货、开票与资金 | 签收后按最终未退金额申请电子发票；退货、退款、全额红冲/重开按 HTML 执行；销售主体收款开票，货款不计门店商户营业额或抽成，计销售主体自身收入与分红净利润；运费单列并依法开票 | PGM/BSM 外部经销商治理、ENUM 经销取消退货开票/资金归属条 |
| 经销职责分离 | 合同价格编辑与审批不得同人；订单审核、到账核验和仓库出库不得由同一人完成全链；退货验收与退款执行分离 | PGM/BSM 外部经销商治理、业务枚举速查表中的经销职责分离现文 |

## 5. 关键流程验收

| 流程 | 必须能回答的问题 | 验收标准 |
|---|---|---|
| 项目初始化 | 这个综合体项目是谁负责、是否可用 | 能记录项目状态（ENUM 六态）。【已废止/不得回灌】项目状态控制后续对象绑定 |
| 空间配置 | 业务发生在哪里、点位是否可用 | 可记录空间状态；【已废止/不得回灌】以空间状态门控合同、经营或设备绑定 |
| 商户入驻 | 谁在经营、商户是否有资格经营 | 商户状态能影响合同和经营范围 |
| 合同生效 | 凭什么经营、期限和合作模式是什么 | 合同状态能影响经营范围绑定 |
| 经营范围绑定 | 商户在哪里经营、经营什么业态 | 商户、空间、业态、合同关系一致 |
| 合同准入 | 当前业务是否允许继续 | 超合同范围、超空间范围、过期、资质异常、权限不足时先阻断；前四类可升级审批并留下原因和责任人，权限不足不设放行通道、只能换有权限的人办理；七类红线不因审批而放行，第①②③类不提供任何开放入口，第④⑤⑥类仅最高权限持授权 U 盘密钥逐笔放行；第⑦类普通退款只限票种规则明确允许、活动或场次取消、平台或履约方无法提供服务、重复扣款、法律法规要求五种情形，五种理由之外的未核销票只能由最高权限持授权 U 盘密钥逐笔放行，不解除已开始核销后的退款禁止；通票安全例外是客人出现重大情绪不稳定、安全问题或其他必要问题，经夜班值班经理及以上批准免除其通票费用，即使已核销也可退款 |
| 员工注册 | 员工身份如何可信建立 | 公司自有员工本人通过私人手机 App 注册、提交资料后后台审批；商户员工由商户代提交、经对应域公司批准后账号生效，自营商户员工走公司自有员工路径；设备凭证绑定（手机专属的设备标识；Keystore 公钥/不可逆设备指纹属未立法实现证据，不得升为必过）、破解/篡改/异常环境检测与失效复核、职级权限和公司工作手机对应关系清楚（"NFC绑定"按 D8 改为"设备凭证绑定"，2026-06-07 收口） |
| 员工排班 | 谁在什么时间、什么区域负责 | 员工、岗位、班次、区域关系清楚 |
| 设备领还 | 谁拿了什么设备、什么时候归还 | 设备状态和责任链清楚 |
| 权限授权 | 谁能看什么、操作什么 | 功能权限可配置；数据默认按项目隔离，项目与商户隔离不提供后台设置项 |
| 终端开关 | 哪个端、哪个商户、哪个模块能不能用 | 关闭后端或模块不可用，打开后仍受功能权限、数据可见边界和设备状态控制 |
| 操作留痕 | 谁改了什么、为什么改、结果如何 | 关键动作可追溯、可复核、不可直接删除 |

## 6. 页面原型验收

| 页面 | 验收标准 |
|---|---|
| 治理总览 | 能看到核心指标、待处理事项、状态分布和最近留痕 |
| 综合体项目 | 能查看项目列表、详情、状态、关联对象和留痕 |
| 空间区域 | 能管理由项目、楼层、区域、点位、商铺、卡座、吧台位、游乐入口、库房、设备点位组成的空间树，以及面积、用途、状态、负责人、所属商户；可记录绑定关系。铺位号不是必过字段。游乐容量只按单个项目的实时在玩人数控制，不再按场次/时段或点位/设备另设容量 |
| 业态管理 | 能查看六值业态词表与说明；每个商户必须归入一种业态。第三方接入是外部系统子系统，不是业态字段 |
| 商户管理 | 能管理商户主体、联系人、资质、业态、经营范围和状态 |
| 合同管理 | 能管理合同编号、合作模式、期限、附件、结算口径摘要和状态 |
| 合同准入规则 | 能管理合同核心摘要、允许范围、高级审批级别和拦截记录，并只读查看系统固定的准入处理顺序；超合同范围、超空间范围、过期、资质异常先阻断，再按层级升级审批并留原因和责任人，权限不足不设放行通道、只能换有权限的人办理；七类红线按本包 §4/§5 口径不得由普通审批放行 |
| 员工注册审批 | 能审核公司自有员工本人通过私人手机 App 提交的注册资料；能接收商户代员工提交的申请并由对应域公司批准，自营商户员工走公司自有员工路径；管理设备凭证绑定、破解/篡改/异常环境检测与失效复核、公司工作手机绑定，换机先解绑旧手机再绑定新手机（"NFC绑定"按 D8 改为"设备凭证绑定"，2026-06-07 收口，finding decision-land-1/compliance-land-8） |
| 员工岗位 | 能管理员工、岗位、所属主体、责任区域和状态 |
| 班次排班 | 能管理班次日期、时间、员工、岗位、区域和异常说明 |
| 设备台账 | 能管理设备编号、类型、所属主体、使用区域和状态 |

## 8. 边界验收

平台治理层必须保持以下边界：

- 不做票务定价和权益规则细节，只提供商户、空间、业态和权限基础。
- 不做酒吧点单和库存细节，只提供酒吧商户、空间、员工、设备和权限基础。
- 不做游乐场次经营细节，只提供游乐项目归属、空间、岗位和责任基础。
- 不做餐饮零售 POS，只提供第三方商户归属、合同和接入基础。
- 不做真实机器人、监控、企业微信系统，只保留服务商和点位归属基础。
- 不做财务深度结算，只记录合同合作模式和结算口径摘要。
- 不做完整人力资源与薪资核算系统；治理层仍须验收提成实时计算后进入工资单月结、依法代扣个人所得税并通过银行发放，不允许现金现抽。
- 不允许员工私人手机承接现场核销、点单、放行、结算或补录。
- 不做编码、接口、数据库和技术实现。

## 9. 可进入下一阶段标准

平台治理层产品设计可进入下一阶段的条件：

1. 五份核心设计文档齐全。
2. P0 模块在五份文档中均有覆盖。
3. 页面、字段、流程、状态没有明显冲突。
4. 每个页面能对应至少一个业务流程或对象。
5. 每个关键流程能找到对应页面和字段。
6. 每个状态在页面和字段中都有统一表达。
7. 原开放问题已经集中收口为执行口径、实施输入或后续排期。
8. 文档没有混入编码实现。
