# 平台治理层产品验收清单 V0.1

## 1. 文档定位

本文档用于验收平台治理层产品设计是否已经达到“可进入后续原型和编码拆解”的程度。

本文档不是开发测试用例，不是接口验收，不是数据库验收，而是产品设计验收清单。它用于检查《平台治理层 PRD》《页面清单》《字段字典》《关键流程图》《低保真原型说明》之间是否一致、完整、可执行。

## 2. 验收范围

本验收清单覆盖平台治理层 P0，包括：

- 综合体项目
- 空间/楼层/区域/点位
- 业态
- 商户/运营主体
- 合同与合作关系
- 合同准入规则
- 员工注册审批、私人手机 App、设备凭证绑定和职级（"NFC 绑定"按 D8 改为"设备凭证绑定"，2026-06-07 收口，finding decision-land-1）
- 员工/岗位/班次
- 企业设备
- 角色权限与数据权限
- 终端开关
- 平台基础留痕

不验收票务定价、酒吧点单、游乐排队、第三方真实接口、财务深度结算、AI 分析和编码实现。

## 5. 关键流程验收

| 流程 | 必须能回答的问题 | 验收标准 |
|---|---|---|
| 项目初始化 | 这个综合体项目是谁负责、是否可用 | 项目状态能控制后续对象绑定 |
| 空间配置 | 业务发生在哪里、点位是否可用 | 空间状态能影响经营绑定和设备绑定 |
| 商户入驻 | 谁在经营、商户是否有资格经营 | 商户状态能影响合同和经营范围 |
| 合同生效 | 凭什么经营、期限和合作模式是什么 | 合同状态能影响经营范围绑定 |
| 经营范围绑定 | 商户在哪里经营、经营什么业态 | 商户、空间、业态、合同关系一致 |
| 合同准入 | 当前业务是否允许继续 | 业务超出合同、空间、业态、有效期时能阻断或升级审批 |
| 员工注册 | 员工身份如何可信建立 | 私人手机注册、设备凭证绑定（设备公钥/不可逆设备指纹）、Root检测、职级权限和公司工作手机对应关系清楚（"NFC绑定"按 D8 改为"设备凭证绑定"，2026-06-07 收口） |
| 员工排班 | 谁在什么时间、什么区域负责 | 员工、岗位、班次、区域关系清楚 |
| 设备领还 | 谁拿了什么设备、什么时候归还 | 设备状态和责任链清楚 |
| 权限授权 | 谁能看什么、操作什么 | 功能权限和数据范围可分离 |
| 终端开关 | 哪个端、哪个商户、哪个模块能不能用 | 关闭后端或模块不可用，打开后仍受权限和数据范围控制 |
| 操作留痕 | 谁改了什么、为什么改、结果如何 | 关键动作可追溯、可复核、不可直接删除 |

## 8. 边界验收

平台治理层必须保持以下边界：

- 不做票务定价和权益规则细节，只提供商户、空间、业态和权限基础。
- 不做酒吧点单和库存细节，只提供酒吧商户、空间、员工、设备和权限基础。
- 不做游乐场次经营细节，只提供游乐项目归属、空间、岗位和责任基础。
- 不做餐饮零售 POS，只提供第三方商户归属、合同和接入基础。
- 不做真实机器人、监控、企业微信系统，只保留服务商和点位归属基础。
- 不做财务深度结算，只记录合同合作模式和结算口径摘要。
- 不做完整 HR 和薪资核算，只记录职级、权限级别和薪资口径摘要。
- 不允许员工私人手机承接现场核销、点单、放行、结算或补录。
- 不做编码、接口、数据库和技术实现。

## 9. 可进入下一阶段标准

平台治理层产品设计可进入下一阶段的条件：

1. 五份核心设计文档齐全。
2. P0 模块在五份文档中均有覆盖。
3. 页面、字段、流程、状态没有明显冲突。
4. 每个页面能对应至少一个业务流程或对象。
5. 每个关键流程能找到对应页面和字段。
6. 每个状态在页面和字段中都有统一表达。
7. 原开放问题已经集中收口为执行口径、实施输入或后续排期。
8. 文档没有混入编码实现。

## 10. 本版结论

本验收清单用于后续审计和修缮平台治理层产品设计文档。只有通过本清单后，平台治理层才算完成产品侧 P0 收口，可以进入视觉原型、开发任务拆解或 160 编码阶段。

> 修订说明（2026-06-07，status-6）：本清单不再做"全绿即通过"的一次性自评。模块覆盖、状态一致性以第 4 节、第 7 节如实标注为准，未闭合项集中见第 10A 节。
>
> 修订说明（2026-06-08 产品流复核）：G7 集团视图已按用户口径收口为“需要但优先级不高”，默认 P2；P0 只预留 `project_id` 和跨项目汇总口径，不再阻塞平台治理 P0 收口。
