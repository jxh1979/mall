# 娱乐综合体管理系统总体拆分

> 2026-07-04 逻辑一致性修订：§3.1 多商户与组织管理系统补名词四层脚注。

## 1. 系统定位

本系统不是单一票务系统，也不是单一酒吧或游乐设施系统，而是面向娱乐综合体的统一经营、协同、留痕、结算和风控平台。

系统需要支持以下业务特征：

- 综合体平台方统一管理园区、商户、票务、会员、结算、风控和数据。
- 酒吧、游乐设施、餐饮、零售、机器人等可以由不同第三方公司独立运营。
- 票务和权益可以统一售卖，但权益归属、核销、成本、结算和数据权限必须按商户隔离。
- 餐饮、零售、机器人优先使用成熟第三方系统，本系统负责对接、留痕、对账和分析。
- 所有人、货、票、钱、设备、服务、沟通行为尽量自动留痕；自动无法完成时，使用受控人工补录。
- 员工工作必须使用企业统一配发管理手机和企业微信，工作行为、客户沟通和服务过程进入统一审计与分析。

## 2. 总体分层

| 层级 | 子系统 | 核心作用 |
|---|---|---|
| 平台治理层 | 多商户管理、权限管理、员工管理、企业设备管理、开放平台、安全鉴权、基础配置 | 定义谁经营、谁操作、谁能看、谁负责、谁能调用 |
| 业务经营层 | 票务通票、订单支付、会员、酒吧经营、游乐运营、营销活动 | 支撑日常经营和游客消费 |
| 第三方集成层 | 餐饮对接、零售对接、机器人对接、监控对接、企业微信对接、设备对接、API/SDK开放能力 | 接入外部系统并统一沉淀事件 |
| 证据审计层 | 事件中心、视频证据、人工补录、风控预警、员工行为审计 | 做全链路留痕和风险控制 |
| 数据决策层 | 经营看板、商户分析、客户需求分析、服务质量分析、财务分析 | 支撑管理决策 |

## 3. 一级子系统清单

### 3.1 多商户与组织管理系统

> 名词四层脚注：本节「组织/商户主体/项目公司/SPV」为业务概念分层（业务：平台 → 项目公司 → 管理公司·SPV → 商户）；DB 层**无 `organizations`/`org_type` 表**，四层主体统一落 `business_entities`，用 `entity_role`（文本，无 CHECK）区分角色。`projects` 表是**业态场馆**（venue_type），非「项目公司」。见 merchant-space-contract-model-v0.1 §5。

负责管理平台方、酒吧公司、游乐公司、餐饮商户、零售商户、机器人服务商、设备服务商等不同主体。

| 模块 | 功能 | 能力 |
|---|---|---|
| 商户主体管理 | 维护公司主体、合同主体、经营资质 | 支持多公司、多品牌、多门店 |
| 商户业态管理 | 标记酒吧、游乐、餐饮、零售、服务商等业态 | 不同业态启用不同功能 |
| 门店/项目管理 | 管理酒吧门店、游乐项目、餐厅、零售店 | 支持场地、区域、楼层、点位 |
| 合同与经营关系 | 记录租赁、联营、分成、保底等关系 | 支撑结算规则 |
| 商户数据权限 | 商户只能查看自己的订单、核销、库存、结算 | 平台可查看全局 |
| 商户接口权限 | 控制第三方系统可访问哪些接口和数据 | 防止数据越权 |

### 3.2 权限、账号与岗位系统

负责所有后台、移动端、商户端、核销端、设备端的账号和权限。

| 模块 | 功能 | 能力 |
|---|---|---|
| 员工账号 | 创建平台员工、商户员工、第三方人员账号 | 支持手机号、工号、企业微信身份 |
| 角色权限 | 管理员、财务、运营、店长、库管、核销员、服务员 | 按角色控制菜单和数据 |
| 岗位权限 | 不同岗位拥有不同操作范围 | 例如吧台可点单但不能改库存成本 |
| 区域权限 | 控制员工只能操作指定区域或门店 | 适合大型场地 |
| 操作审计 | 记录登录、查看、修改、审批、导出行为 | 管理者查看敏感数据也要留痕 |
| 临时授权 | 主管临时授权处理异常 | 到期自动失效 |

### 3.3 企业设备与管理手机系统

负责公司统一配发手机、手持机、扫码设备等工作设备的领用、归还、绑定和管控。

| 模块 | 功能 | 能力 |
|---|---|---|
| 设备台账 | 手机、扫码枪、手持机、平板、NFC设备登记 | 记录编号、IMEI、型号、状态 |
| 设备领用 | 上班扫码/NFC领取公司设备 | 绑定员工、班次、岗位、区域 |
| 设备归还 | 下班退还设备并检查同步状态 | 检查电量、损坏、未同步事件 |
| 应用管控 | 只允许使用预装业务 App、企业微信和系统必要软件 | 不允许安装其他软件，可接入 MDM 能力 |
| 网站白名单 | 工作手机只允许访问后台配置的白名单网站 | 非白名单访问写入风险事件 |
| 设备定位 | 工作期间记录设备所在区域 | 支持异常离场提醒 |
| 设备异常 | 丢失、损坏、未归还、越权登录 | 自动生成事件和工单 |
| 交接班检查 | 下班前检查订单、聊天、核销、补录是否完成 | 防止漏交接 |

### 3.4 统一票务、通票与权益系统

负责平台统一票务策略、通票设计、权益拆分、核销规则和权益归属。门票主路径由客人通过官方 App/小程序或第三方渠道自助购买；少量到店服务场景由授权服务人员在售票型一体机上辅助购票，员工平板不承担门票销售。

| 模块 | 功能 | 能力 |
|---|---|---|
| 票种管理 | 单日票、夜场票、酒吧票、游乐票、活动票 | 支持有效期、库存、价格 |
| 通票管理 | 多权益组合票 | 一张票可包含多个商户权益 |
| 权益项管理 | 入园、酒吧入场、酒水兑换、游乐次数、餐饮券、零售券 | 每个权益独立归属 |
| 权益归属 | 绑定平台或具体商户 | 防止酒吧和游乐混账 |
| 核销规则 | 一次核销、多次核销、限时核销、按项目扣次 | 支持二维码、NFC、闸机 |
| 库存与容量 | 控制每日票量、场次容量、项目容量 | 防止超卖和超容量 |
| 渠道售票 | 官方 App/小程序、美团、大众点评、抖音（**P0 首批仅这三家团购回流**）；携程/旅行社等为 **P1+ 渠道预留** | 平台承接渠道订单、票码、支付/退款和对账结果 |
| 票务异常 | 重复核销、过期票、退票争议、黑名单 | 进入风控中心 |

### 3.5 统一订单、支付、退款与结算系统

负责所有交易流水、支付、退款、分账、对账和财务结算。

| 模块 | 功能 | 能力 |
|---|---|---|
| 订单中心 | 管理票务订单、酒吧订单、权益订单、套餐订单 | 统一订单编号 |
| 支付中心 | 微信、支付宝、银行卡、现金、企业转账 | 支持混合支付 |
| 退款管理 | 原路退款、部分退款、人工退款、审批退款 | 退款全流程留痕 |
| 分账规则 | 按比例、固定金额、按核销、按保底、按合同 | 适配不同商户合作模式 |
| 对账中心 | 支付流水、订单流水、核销流水、第三方流水比对 | 发现差异自动预警 |
| 商户结算 | 日结、周结、月结、活动结算 | 生成结算单 |
| 发票管理 | 开票申请、开票状态、发票抬头 | 可后期对接开票平台 |
| 财务审计 | 调账、冲正、补款、扣款 | 审批和操作留痕 |

### 3.6 统一会员与游客系统

负责游客身份、会员等级、权益、画像和客户关系。

| 模块 | 功能 | 能力 |
|---|---|---|
| 游客账号 | 手机号、微信、身份证实名可选 | 形成统一游客ID |
| 会员等级 | 普通、银卡、金卡、黑卡等 | 支持折扣和权益 |
| 会员权益 | 优先入场、生日礼、酒水券、游乐券 | 可配置发放规则 |
| 积分系统 | 消费积分、签到积分、活动积分 | 支持兑换 |
| 客户标签 | 酒吧偏好、游乐偏好、消费能力、投诉风险 | 支撑营销和服务 |
| 客户生命周期 | 新客、复购、沉睡、流失、高价值 | 支撑运营 |
| 客户隐私 | 手机号、证件、消费信息脱敏；企业微信工作会话原文按权限查看并留痕 | 控制查看权限 |

### 3.7 酒吧经营管理系统

负责酒吧独立经营，不与游乐设施混淆。酒吧可以是第三方运营，但可以接入平台规则、票务、结算和留痕。

| 模块 | 功能 | 能力 |
|---|---|---|
| 酒吧入场 | 酒吧通票、活动票、派对票核销 | 支持独立容量控制 |
| 桌台/卡座 | 预订、开台、转台、并台、低消、服务费 | 支持桌台平面图 |
| 客人点单 | 扫码点单、服务员点单、桌台挂账 | 绑定桌台和服务员 |
| 吧台点单 | 散客吧台点酒、现场补单 | 支持快速收银 |
| 酒水商品 | 瓶卖、杯卖、套餐、赠饮、活动酒 | 支持不同销售规则 |
| 简餐商品 | 小吃、果盘、冷食、热食 | 可对接厨房或第三方餐饮 |
| 存酒管理 | 存酒、取酒、剩余量、有效期、转赠、作废 | 存酒独立于可售库存 |
| 酒水库存 | 可售库存、吧台库存、已售未取、报损、盘亏 | 细分库存状态 |
| 库房管理 | 入库、出库、调拨、盘点、报损、批次、保质期 | 支持总库和吧台小库 |
| 物料管理 | 果料、冰块、杯具、纸巾、吸管、清洁用品 | 支持耗材领用和盘点 |
| 配方/BOM | 鸡尾酒配方、简餐配方、自动扣料 | 支持成本核算 |
| 酒吧报表 | 销售、毛利、库存、低消达成、存酒余额 | 商户和平台分权限查看 |

### 3.8 游乐设施运营系统

负责主题游乐项目的独立运营，支持第三方游乐公司承租或联营。

| 模块 | 功能 | 能力 |
|---|---|---|
| 项目资料 | 项目名称、类型、位置、说明、限制条件 | 支持身高、年龄、健康限制 |
| 开放时间 | 日历、时段、临时关闭、节假日规则 | 与票务容量联动 |
| 场次管理 | 固定场次、滚动入场、预约场次 | 控制单场容量 |
| 排队预约 | 普通排队、预约排队、快速通道 | 提升游客体验 |
| 项目核销 | 通票权益扣次、单项目票核销 | 支持扫码、NFC、闸机 |
| 设备状态 | 正常、暂停、维护、故障、关闭 | 状态变更留痕 |
| 安全巡检 | 开园检查、闭园检查、设备巡检 | 支持图片、签名、视频关联 |
| 事故记录 | 游客受伤、设备异常、投诉争议 | 进入风控和工单 |
| 道具耗材 | 手环、雨衣、3D眼镜、道具、备件 | 可轻量管理 |
| 游乐结算 | 按票、按核销、按分成、按保底结算 | 与商户合同绑定 |
| 游乐报表 | 客流、排队时长、核销量、设备利用率 | 支撑运营优化 |

### 3.9 餐饮第三方对接系统

餐饮不自研完整POS，优先对接成熟第三方，本系统负责统一入口、券核销、数据同步、对账和留痕。

| 模块 | 功能 | 能力 |
|---|---|---|
| 餐饮商户档案 | 餐厅、档口、品牌、营业时间 | 绑定商户主体 |
| 第三方POS对接 | 同步订单、支付、退款、券核销 | API或文件同步 |
| 餐饮券管理 | 代金券、套餐券、兑换券 | 可放入通票权益 |
| 核销回传 | 第三方核销后回传平台 | 形成统一权益事件 |
| 对账结算 | 餐饮订单与平台券、支付流水比对 | 差异预警 |
| 留痕关联 | 餐饮订单关联员工、桌号、监控片段、机器人任务 | 支撑争议处理 |

### 3.10 零售第三方对接系统

零售不自研完整POS，优先对接成熟零售系统，本系统负责统一会员、券、订单同步、对账和留痕。

| 模块 | 功能 | 能力 |
|---|---|---|
| 零售商户档案 | 门店、品牌、收银点 | 绑定商户主体 |
| 商品同步 | 同步商品、SKU、价格、分类 | 可只读 |
| 销售同步 | 同步订单、退款、支付方式 | 支撑统一经营分析 |
| 零售券核销 | 代金券、折扣券、兑换券 | 与平台权益打通 |
| 库存同步 | 可选同步库存和缺货状态 | 管理层查看 |
| 对账结算 | 按门店、商品、活动、支付方式对账 | 支撑商户结算 |
| 留痕关联 | 订单、收银员、摄像头、会员、优惠券关联 | 支撑审计 |

### 3.11 机器人第三方对接系统

机器人不自研，本系统负责创建或接收配送任务、追踪状态、绑定证据和处理异常。

| 模块 | 功能 | 能力 |
|---|---|---|
| 服务商管理 | 机器人供应商、接口密钥、设备编号 | 管理对接方 |
| 任务中心 | 送酒、送餐、补货、取存酒、送物料 | 统一任务编号 |
| 任务下发 | 向机器人平台发送任务 | 支持取货点和送达点 |
| 状态回传 | 已接单、取货中、配送中、已到达、已签收、异常 | 全流程留痕 |
| 取货校验 | 二维码、NFC、货架标签、员工确认 | 防止取错 |
| 交付确认 | 员工扫码、客人确认、NFC碰一碰 | 形成签收证据 |
| 异常处理 | 超时、故障、货损、无人接收 | 转人工工单 |
| 视频绑定 | 自动关联取货点、路径点、交付点视频 | 支撑争议复盘 |

### 3.12 视频监控与证据中心

负责把监控系统和业务事件绑定，不一定保存所有视频原文件，但保存索引、片段、截图和证据链。

| 模块 | 功能 | 能力 |
|---|---|---|
| 摄像头点位 | 摄像头编号、位置、覆盖区域 | 与场地地图绑定 |
| 视频平台对接 | 对接第三方监控平台 | 获取录像索引、截图、片段链接 |
| 事件视频绑定 | 将订单、核销、出库、配送、投诉绑定视频 | 按时间地点自动匹配 |
| 关键截图 | 自动截取关键节点图片 | 降低视频存储成本 |
| 视频调阅权限 | 控制谁能看、看多久、能否下载 | 防止滥用 |
| 调阅审计 | 管理者查看视频也留痕 | 合规要求 |
| 证据包 | 争议事件一键汇总业务记录、聊天、视频、图片 | 便于处理投诉和责任认定 |

### 3.13 企业微信与客户沟通分析系统

负责企业微信客户会话接入、服务分析、客户需求提取和违规风险识别。

| 模块 | 功能 | 能力 |
|---|---|---|
| 企业微信账号绑定 | 员工企业微信与系统账号绑定 | 与管理手机和班次关联 |
| 客户会话同步 | 每天自动同步所有员工企业微信工作聊天内容 | 使用企业微信已有会话能力，平台统一存储、质检和审计 |
| 客户需求识别 | 识别订卡座、包场、生日、存酒、投诉等需求 | 自动打标签 |
| 敏感词监控 | 私单、私收款、辱骂、违规承诺、诱导加私人微信、非白名单链接 | 风险预警 |
| 服务质量分析 | 响应速度、解决率、客诉倾向、语气风险 | 员工绩效参考 |
| 客诉工单 | 高风险会话自动生成工单 | 主管跟进 |
| 会话查看权限 | 按岗位、商户、客户归属控制查看 | 管理者查看也留痕 |
| 数据脱敏 | 手机号、支付信息、证件信息脱敏；企业微信会话不脱敏原文仅限最小授权 + 审批的取证/质检场景，普通展示按权限脱敏，查看写审计<!-- 修订说明（2026-06-08 三轮收口）：会话原文留存非永久——留存期限可配置，到期归档/销毁/匿名化（按 A7/合规 C3、data-risk §11.5）；2026-06-08 复核补充不脱敏原文的最小授权边界。依据 finding residual-scan-3/4、A7/C3 --> | 降低隐私风险并保留质检依据 |

### 3.14 全链路事件留痕中心

负责把所有系统动作统一沉淀为标准事件，是审计、风控、分析的底座。

| 模块 | 功能 | 能力 |
|---|---|---|
| 事件模型 | 定义人员、游客、票务、物料、设备、沟通、财务等事件 | 统一格式 |
| 事件采集 | 接收自有系统、第三方系统、设备、人工补录事件 | 支持接口、消息队列、批量导入 |
| 事件关联 | 关联员工、游客、订单、票、商户、设备、地点、视频 | 形成证据链 |
| 事件查询 | 按人、时间、地点、订单、设备、商户查询 | 快速复盘 |
| 事件风险标记 | 正常、提醒、可疑、高风险 | 供风控中心使用 |
| 事件归档 | 按类型设置保存周期 | 控制成本和合规 |
| 事件不可篡改 | 关键事件只允许追加，不允许物理删除 | 保留历史 |

### 3.15 人工补录与审批系统

当自动留痕无法完成时，用受控人工补录补齐证据。

| 模块 | 功能 | 能力 |
|---|---|---|
| 补录类型 | 物料异常、设备异常、客户投诉、库存差异、核销异常 | 分类管理 |
| 必填模板 | 按补录类型要求填写不同字段 | 降低随意性 |
| 附件证据 | 图片、视频、签名、定位、聊天截图 | 支撑复核 |
| 审批流程 | 员工提交、主管复核、财务或平台确认 | 分级审批 |
| 超时补录 | 超过规定时间需更高权限审批 | 防止事后造假 |
| 修改留痕 | 补录内容修改保留版本历史 | 不允许无痕修改 |
| 高频预警 | 某员工、某商户、某设备频繁补录自动预警 | 进入风控 |

### 3.16 风控预警与合规审计系统

负责识别异常行为、异常交易、异常沟通、异常库存和安全风险。

| 模块 | 功能 | 能力 |
|---|---|---|
| 票务风控 | 重复核销、异常退票、黄牛风险、超频购买 | 保护票务收入 |
| 财务风控 | 支付差异、退款异常、分账异常、手工调账 | 保护资金安全 |
| 库存风控 | 盘亏、报损过高、高价值酒水异常、存酒异常 | 保护资产 |
| 员工风控 | 私单、私收款、越权操作、异常补录、异常定位 | 管理员工行为 |
| 沟通风控 | 敏感词、投诉倾向、违规承诺、诱导私聊 | 服务监管 |
| 设备风控 | 管理手机未归还、设备离线、扫码设备异常 | 保障运行 |
| 安全风控 | 园区容量、酒吧容量、游乐设备故障、事故事件 | 保障现场安全 |
| 风险处置 | 预警、工单、冻结、审批、复核、归档 | 闭环处理 |

### 3.17 营销活动系统

### 3.19 开放平台与安全鉴权系统

负责把系统内的数据、能力、事件和业务流程标准化为第三方可调用的API、Webhook、SDK和接口文档，同时保证所有调用都经过强鉴权、动态授权、调用审计和风险控制。

| 模块 | 功能 | 能力 |
|---|---|---|
| 开放应用管理 | 为第三方创建应用、账号、密钥、权限范围 | 每个第三方独立身份 |
| API目录 | 开放票务、核销、订单、商户、事件、库存、机器人、视频等接口 | 支持版本管理 |
| 接口文档中心 | 自动生成第三方调用文档、字段说明、错误码、示例 | 方便第三方接入 |
| SDK管理 | 提供Java、Node.js、Python、PHP等SDK | 降低接入成本 |
| 动态鉴权 | 账号密码、动态令牌、短时效访问地址、签名、时间戳、nonce | 防止静态链接泄露 |
| 动态接口地址 | 第三方先通过鉴权接口获取短时效调用地址或网关路由 | 地址定期刷新 |
| 权限范围控制 | 控制第三方只能调用授权商户、门店、接口和数据 | 防止越权 |
| 失败锁定 | 连续3次账号密码或鉴权失败后锁定应用或账号 | 必须人工解锁 |
| 人工解锁 | 平台管理员复核后手动解锁 | 解锁行为写入事件中心 |
| 调用审计 | 记录每次调用的应用、接口、参数摘要、IP、结果、耗时 | 支撑追责 |
| 限流熔断 | 按应用、接口、商户限制调用频率 | 防止刷接口 |
| Webhook订阅 | 第三方可订阅订单、核销、配送、库存、事件等回调 | 回调也需要签名 |
| 沙箱环境 | 提供测试环境、测试商户、测试数据 | 方便联调 |
| 密钥轮换 | 支持密钥定期更换、主动吊销、过期提醒 | 降低泄露风险 |

## 5. 关键边界原则

### 5.1 平台和商户边界

- 平台可以统一售票、统一会员、统一营销、统一结算和统一审计。
- 商户只能管理自己的业务数据。
- 酒吧和游乐设施即使出现在同一张通票里，也必须拆成不同权益项。
- 每个权益项必须有归属商户、核销规则、成本归属和结算规则。

### 5.2 自研和第三方边界

- 餐饮、零售、机器人优先第三方系统。
- 本系统不重复做成熟POS和机器人调度内核。
- 本系统负责接口接入、订单同步、券核销、证据留痕、对账结算和经营分析。

### 5.3 自动留痕和人工补录边界

- 优先使用系统、设备、接口、NFC、二维码、视频自动留痕。
- 自动留痕失败时，才允许人工补录。
- 人工补录必须有权限、模板、证据、审批和修改历史。

### 5.4 员工和客户沟通边界

- 员工工作沟通使用企业微信，不使用私人微信承接业务。
- 企业微信会话每天自动归档到后台，用于服务优化、投诉处理和违规检查。
- 企业微信会话接入使用企业微信已有会话能力，平台负责统一同步、永久存储、质检和审计。
- 员工、客户都需要明确告知服务沟通可能用于质量管理和风险审计。
- 管理者查看聊天和视频也必须留痕，并按权限控制。
- 工作手机不允许安装除预装软件之外的任何软件，只允许访问白名单网站。

## 6. 建议开发顺序

### 第一阶段：地基系统

目标是先把多商户、权限、事件、第三方对接的底座做出来。

1. 多商户与组织管理系统
2. 权限、账号与岗位系统
3. 开放平台与安全鉴权系统
4. 企业设备与管理手机系统
5. 全链路事件留痕中心
6. 人工补录与审批系统
7. 第三方集成中心基础框架

### 第二阶段：经营闭环

目标是实现能卖票、能核销、能分账、能看账。

1. 统一票务、通票与权益系统
2. 统一订单、支付、退款与结算系统
3. 统一会员与游客系统
4. 酒吧入场与桌台基础能力
5. 游乐项目与项目核销基础能力
6. 基础经营看板

### 第三阶段：酒吧深度经营

目标是支撑酒吧实际运营。

1. 桌台/卡座完整流程
2. 酒水点单与吧台点单
3. 简餐点单
4. 存酒管理
5. 酒水库存和库房管理
6. 物料、配方和成本核算

### 第四阶段：第三方生态对接

目标是接入外部成熟系统。

1. 餐饮POS对接
2. 零售POS对接
3. 机器人系统对接
4. 视频监控系统对接
5. 企业微信会话接入
6. 闸机、NFC、扫码设备接入

### 第五阶段：风控与智能分析

目标是从数据留痕进入管理决策。

1. 风控预警中心
2. 员工行为审计
3. 客户需求分析
4. 服务质量分析
5. 财务差异分析
6. 商户经营评级
