# 完整后台管理端 SRS V0.1

**项目**：综合体管理系统
**文档类型**：Software Requirements Specification / 后台管理端专项 SRS
**版本**：V0.1
**日期**：2026-06-16
**状态**：开发基线草案，已可用于拆分后台页面开发任务
**适用对象**：产品、开发、测试、运营、财务、法务/HR、IT、第三方供应商

> 重要口径：当前 Web 端已具备轻量管理/运营入口和部分首批页面，但不得等同于“完整后台管理端已实现”。本 SRS 定义完整后台应建设的页面、权限、字段、接口、状态流、异常流和验收边界，具体实现状态以代码验收矩阵为准。

## 1. 文档目的

完整后台管理端用于承载综合体经营管理、商户运营、酒吧经营、游乐设施运营、票务会员、财务结算、第三方接入、生产运维证据和审计留痕。本文档的目标不是描述概念，而是把后台拆成可设计、可编码、可测试、可验收的系统规格。

## 2. 范围与非范围

### 2.1 范围

完整后台必须覆盖以下业务域：

1. 总控驾驶舱与集团/综合体视图。
2. 综合体、商户、合同、运营主体、合同主体、结算主体、经营对象的治理关系。
3. 员工账号、岗位、权限模板、临时授权、审批和审计留痕。
4. 票务策略、基础价、多人票、新人票、学生票、渠道价、动态定价、出票、核销和退款追踪。
5. 酒吧订台、卡座、转卡、合并、续卡、入场权益、订单、出品、账单、存酒、年龄核验和提成。
6. 游乐设施、项目、场次、安全告知、电子免责和事故工单；团体/包场、预约排队和集团视图按后续阶段扩展。
7. 库存台账、高价值酒水在线核销、库存调整、盘点和差异。
8. 财务应收应付、结算、对账差异、商户账单和经营报表。
9. 商户服务、维修、投诉、整改工单。
10. 第三方供应商双向开放接口、Webhook、轮询校验、补偿、签名、字段映射和联调证据。
11. 风控、审计事件、生产前置证据、备份恢复、密钥轮换、运行状态检查。

### 2.2 非范围

1. 不把 C 端小程序/App 的游客购票体验并入后台页面，但后台必须能查看、配置、追踪其业务结果。
2. 不把第三方供应商专有后台复制进本系统，但必须保留配置、映射、回调、轮询、补偿和证据入口。
3. 不在 P0 强行实现完整商业地产 SaaS，但 P1/P2 页面必须保留商户服务、财务账单和经营分析扩展位置。
4. 不把移动端作为完整后台替代；移动端只要求关键查看、审批、异常处理不遮挡、不丢字段。

## 3. 用户角色与权限原则

| 角色 | 主要职责 | 权限原则 |
|---|---|---|
| 总控负责人 | 查看全局经营、审批高风险操作、处理异常 | 全域只读 + 高风险审批 + 配置变更授权 |
| 综合体运营经理 | 管理综合体、商户、场地、运营配置 | 按综合体范围授权，不能越权查看其他主体敏感财务 |
| 酒吧主管 | 管理卡座、订单、核销、存酒、年龄核验、员工提成 | 仅限所属酒吧，跨酒吧需总控授权 |
| 游乐主管 | 管理游乐项目、场次、安全、事故工单 | 仅限所属项目或综合体范围 |
| 财务 | 应收应付、结算、对账、报表 | 财务数据读写需强留痕，关键调整需审批 |
| 商户运营 | 商户档案、服务工单、投诉整改 | 不能修改财务主口径，不能越权操作合同核心字段 |
| 仓库/采购 | 库存、盘点、入出库和差异处理 | 高价值酒水核销必须在线校验 |
| IT/系统管理员 | 账号、设备、接口、运行证据、密钥台账 | 不默认拥有业务审批权，配置变更必须留痕 |
| 审计/风控 | 审计事件、异常订单、权限变更、补偿记录 | 默认只读，不直接修改业务单据 |
| 第三方供应商运维 | 查看自身接口联调、回调和补偿状态 | 仅限授权 endpoint，不允许访问内部业务后台 |

权限必须满足四条底线：

1. 页面可见、按钮可点、字段可编辑、数据范围必须分开控制。
2. 所有新增、修改、删除、审批、核销、退款、补偿、导出、权限变更都必须产生审计事件。
3. 财务、库存、高价值酒水、年龄核验、密钥和第三方接口配置属于高风险对象，必须有二次确认或审批链。
4. 临时授权必须有到期时间或单次有效条件，到期后自动失效，并保留授权人、使用人、使用时间和使用结果。

## 4. 功能需求

### FR-ADM-GOV-001：总控驾驶舱
系统应展示综合体、酒吧、游乐、票务、会员、财务、商户服务、第三方接口、生产运维证据的关键指标和异常入口。

验收标准：
- Given 总控负责人登录后台，When 打开总控驾驶舱，Then 页面显示今日/本周/本月核心指标、异常数量和待处理事项。
- Given 部分指标接口失败，When 页面加载，Then 成功模块正常显示，失败模块显示可重试错误状态，并记录前端错误事件。
- Given 普通员工访问总控驾驶舱，When 权限不足，Then 页面不得展示敏感财务和跨主体数据。

### FR-ADM-GOV-002：主体绑定
系统应支持经营对象、运营主体、合同主体、结算主体不同名、不同公司但唯一绑定到同一业务对象，并在合同和相关流程中留痕。

验收标准：
- Given 一个业务对象已绑定运营主体、合同主体和结算主体，When 用户创建合同或结算单，Then 系统自动带出绑定关系并禁止无权限人员改写。
- Given 用户尝试把同一合同主体绑定到冲突对象，When 保存，Then 系统拒绝并提示冲突对象。
- Given 主体绑定变更，When 审批通过，Then 历史合同和历史结算保持原快照，新业务使用新绑定。

### FR-ADM-ACC-001：账号与权限模板
系统应支持员工账号、账号类型、组织/商户数据范围、初始登录凭证、基础权限模板、复制模板、临时模板。后台手动录入是企业微信关闭时的默认员工入口；必须承接同意/授权凭据或证据附件，手机号只保存不可逆哈希。临时模板可设置有效期或单次有效。

验收标准：
- Given IT/HR 管理员手动创建员工账号，When 提交员工账号、初始密码、organization_id、账号类型和可选 consent_reference/evidence_attachment_ids，Then 系统创建 access_user，写入 auth_credentials 哈希凭证，手机号不落明文，并记录 access.user.changed。
- Given 商户范围管理员手动创建账号，When 请求 merchant_id 与自身 merchant_id 不一致，Then 系统拒绝并返回 CROSS_MERCHANT_FORBIDDEN。
- Given 管理员复制“普通员工”模板为“普通员工01”，When 修改模板权限，Then 原模板不受影响，新模板记录来源模板。
- Given 临时模板设置单次有效，When 被使用一次后，Then 系统自动失效并记录使用结果。
- Given 临时模板到期，When 员工再次访问相关页面，Then 系统按失效后权限重新拦截。

### FR-ADM-TKT-001：票务策略
系统应以平日、周末、节假日价为最高优先级基础价。多人票、新人票、学生票、渠道价可基于基础价派生，也可录入固定价格策略。

验收标准：
- Given 平日基础价已配置，When 创建新人票派生策略，Then 系统允许按折扣、固定金额或固定价生成对应价格。
- Given 节假日价缺失，When 用户发布依赖节假日价的策略，Then 系统阻止发布并提示缺失日期范围。
- Given 动态定价规则发布后产生订单，When 后续规则调整，Then 历史订单价格快照不变。

### FR-ADM-BAR-001：卡座与订台
系统应支持卡座资源、预订、入场人数、仅限预订酒吧入场、转卡、合并、续卡和状态追踪。卡座权益不得抵扣低消；票务和卡座消费彼此独立。

验收标准：
- Given 卡座 A 允许 6 人免通票进入酒吧 X，When 第 7 人尝试免票进入，Then 系统拒绝并提示人数超限。
- Given 客人持卡座权益尝试进入酒吧 Y，When 该卡座属于酒吧 X，Then 系统拒绝并记录越权入场尝试。
- Given 用户发起卡座转卡，When 原卡座存在未结账订单或未完成核销，Then 系统必须要求先处理未完成事项或走主管审批。
- Given 两个卡座合并，When 合并成功，Then 系统形成合并后的账单、人数、最低消费和审计链，不丢失原卡座记录。
- Given 卡座续卡，When 续卡成功，Then 新有效期、金额、提成人员和原记录关联必须可追溯。

### FR-ADM-BAR-002：酒吧账单、存酒、年龄核验
系统应支持点酒、出品、核销、拆单、合单、转台、挂账、服务费、低消差额补齐、配方成本、员工提成和存酒管理。酒吧年龄核验要求强制人脸或第三方实名/年龄能力；供应商未确定前，后台只保留配置、调用记录、失败处理和人工复核入口。

验收标准：
- Given 高价值酒水领取，When 终端离线，Then 系统拒绝领取并提示需在线核销。
- Given 年龄核验供应商返回失败，When 客人尝试入场，Then 系统阻止入场并提供人工复核入口。
- Given 销售人员售卖卡座，When 产生可提成消费，Then 系统按 15% 计算；非销售人员按 10% 计算；通票不参与卡座提成。

### FR-ADM-AMU-001：游乐安全与事故
系统应支持游乐项目、场次、容量、安全告知、电子免责、核销记录、安全巡检、异常上报、事故工单、处理记录、附件、责任人和关闭验收。

验收标准：
- Given 游乐项目缺少安全告知，When 用户开放售票或场次，Then 系统阻止并提示补齐安全告知。
- Given 事故工单缺少处理记录或附件，When 用户关闭工单，Then 系统拒绝关闭。

### FR-ADM-FIN-001：应收应付台账
P0 必须支持完整应收应付台账，至少覆盖来源单据、交易对方、应收/应付方向、金额、币种、到期日、状态、核销/付款记录、调整记录和审计留痕。

验收标准：
- Given 订单或合同产生应收，When 业务单据确认，Then 财务台账自动生成或可人工确认生成应收记录。
- Given 财务调整应收金额，When 保存，Then 必须填写原因并产生审计事件。
- Given 应收已部分核销，When 查看台账，Then 系统显示原金额、已核销金额、剩余金额和核销明细。

### FR-ADM-INT-001：第三方双向开放
系统应支持“我们接入第三方”和“第三方调用我们”两种模式。供应商资料未到位时，后台必须先保留 endpoint、字段映射、签名、Webhook、轮询、补偿、对账口径和联调证据入口。

验收标准：
- Given 第三方仅提供 SDK/API，When 供应商适配器启用，Then 后台仍能记录调用配置、鉴权方式、字段映射和失败补偿策略。
- Given Webhook 未到达，When 定时轮询发现状态变化，Then 系统补偿拉取并标记来源为轮询校验。
- Given 供应商回调签名失败，When 系统收到请求，Then 拒绝处理、记录安全事件、可在后台查看失败原因。

## 5. 页面与接口要求

完整后台页面必须逐页满足以下最小结构：页面 ID、业务模块、页面名称、路由、所属阶段；可访问角色、按钮权限、字段读写权限、数据范围；关联 API、关联数据表/模型、状态流；新增、编辑、删除、审批、导入、导出、补偿、核销等操作的前置条件和结果；空状态、加载状态、错误状态、权限不足状态、并发修改状态；审计事件名称和关键留痕字段；对应 UI 自动化验收 ID。

页面明细以 `docs/full-admin-page-permission-field-matrix-v0.1.csv` 为准。

## 6. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-ADM-PERF-001 | 性能 | 常规查询 P95 小于 800ms；大报表允许异步生成并显示任务状态。 |
| NFR-ADM-SEC-001 | 权限 | 所有后台 API 必须执行服务端权限校验，前端隐藏按钮不能作为安全边界。 |
| NFR-ADM-SEC-002 | 审计 | 高风险操作必须记录 actor、角色、对象、前后值、原因、IP/设备、时间和 trace_id。 |
| NFR-ADM-UX-001 | 可用性 | 表单校验错误必须定位到字段，保存失败不得清空用户已填内容。 |
| NFR-ADM-REL-001 | 可靠性 | 第三方失败、超时、限流、重复回调不得造成重复核销、重复入账或状态倒退。 |
| NFR-ADM-MOB-001 | 窄屏 | 窄屏至少支持查看、审批、异常处理和关键状态，不要求完成复杂批量配置。 |
| NFR-ADM-DATA-001 | 数据一致性 | 财务、库存、核销、订单状态变更必须保证幂等和事务一致性。 |

## 7. 可验收条件

完整后台任一页面进入“已完成”状态前，必须同时满足：

1. 已登记在页面权限字段矩阵中。
2. 已有路由、页面入口、接口契约或 mock 契约。
3. 至少覆盖 happy path、表单校验、权限拦截、空状态、错误状态。
4. 高风险页面覆盖审计事件和二次确认。
5. Playwright 或等效 UI 验收存在真实断言，不允许只检查页面能打开。
6. 后端接口有单元/集成/契约测试之一；涉及第三方时有 mock/stub 覆盖成功、失败、超时、鉴权失败、限流、重复请求和异常数据。

## 8. 对抗式风险结论

1. 如果没有页面矩阵，完整后台会退化成“菜单堆砌”，开发无法判断字段、权限、状态和接口边界。
2. 如果权限只到角色级，不到按钮、字段、数据范围，高风险操作会被误授权。
3. 如果只做 Web 页面，不补 API 契约和审计事件，测试无法验收，运营事故无法追责。
4. 如果第三方接口未到位就跳过 mock，核心业务闭环会在联调阶段集中暴露。
5. 如果当前轻量 Web 被当成完整后台，会导致进度假完成；本 SRS 明确两者边界。

## 9. 下一步开发拆分建议

1. 先做后台框架、导航、权限守卫、审计事件基座和统一表格/表单组件。
2. 第一批页面优先：总控驾驶舱、账号权限、票务策略、卡座订台、订单核销、应收应付、供应商适配器、生产证据。
3. 第二批页面扩展：库存盘点、存酒、商户服务、游乐安全、对账差异、经营分析。
4. 第三批页面扩展：团体/包场、预约排队、商业地产增强、完整移动审批和高级报表。
