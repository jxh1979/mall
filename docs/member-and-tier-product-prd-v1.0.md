## 1. 文档定位

本文承接会员身份、成长值、会员等级、升级、保护和降级的现行业务规则并提供产品细化。与三个最高业务解释权 HTML 不一致时以 HTML 为准；本文新增而 HTML 尚未记载的业务规则，在用户批准并写入相应 HTML 前不生效。

以下规则不在本文重复定义：

- 积分产生、冻结、有效期、兑换和虚拟券：见 `docs/points-and-voucher-product-prd-v1.0.md`。
- 商户积分费用、兑换定价、核销补偿和账期：见 `docs/merchant-points-settlement-rules-v1.0.md`。
- 储值余额、储值资金、储值退款和储值账户责任：属于储值业务域。

其他文档可以引用本文作为产品细化资料，但不得据此覆盖三个 HTML。

## 2. 目标与非目标

### 2.1 目标

- 以完成短信验证的手机号为唯一标准，建立全国唯一、跨城市和跨项目使用的免费会员账户。
- 将成长值与可消费积分彻底分账。
- 用滚动周期、即时升级、保护期和通知期形成可解释的等级状态机。
- 使等级门槛、倍率、活动和版本均由系统承载并可追溯。

### 2.2 非目标

- 不建立付费订阅会员。
- 不定义积分余额、积分商城或虚拟券。
- 不拥有储值账户或资金责任。
- 不规定代码、接口、数据库或页面实现。

## 3. 统一术语

| 术语 | 定义 |
|---|---|
| 会员 | 主动注册，以手机号完成短信验证，填写生日，满足平台年龄要求并同意会员及隐私条款后形成的全国统一免费身份。 |
| 会员身份 | 同一已验证手机号在全国平台内唯一的业务身份，跨城市、跨项目复用；系统不据此声称识别同一自然人。 |
| 成长值 | 只用于会员等级评定的数值，不可消费、抵扣、兑换或转赠。 |
| 合格付费消费 | 已完成履约且符合平台成长规则的付费消费；积分加现金兑换不属于该类消费。 |
| 等级计划 | 平台版本化配置的一组等级名称、门槛、权益和积分倍率。 |
| 保护期 | 升级后从升级日开始的等级保护期间；期长为业务参数，全平台统一可配，出厂默认十二个月，须同时配置上下限。 |
| 等级评估日 | 系统按规则重新计算会员等级的业务日期。 |
| 等级规则版本 | 对等级名称、数量、门槛、权益和倍率的一次完整、可追溯配置。 |

## 4. 角色与职责

| 角色 | 职责 |
|---|---|
| 会员 | 注册、完成手机号短信验证、填写生日、满足年龄要求、同意条款并查看成长值及等级。 |
| 全国平台 | 管理会员身份去重、成长值基础规则、等级计划、审批、生效和通知。 |

| 审批人 | 审批等级计划、成长值活动倍率和规则版本；不得与申请人为同一人。 |
| 审计人员 | 按会员、订单、项目、商户、规则版本和审批记录追溯状态变化。 |

## 5. 会员身份

### 5.1 注册成立条件

会员身份只有在以下条件全部满足后成立：

1. 会员主动发起注册。
2. 以手机号完成短信验证。
3. 填写生日并满足平台年龄要求。
4. 明示同意当前有效版本的会员条款和隐私条款。

全部条件满足后系统自动注册成功并直接创建 `ACTIVE` 会员身份；任一条件不满足时本次注册失败且不创建会员身份，不产生“注册中”或“未通过”状态。系统必须保存手机号验证结果、生日与年龄校验结果、条款版本、隐私版本、同意时间、渠道及项目来源。

### 5.2 全国唯一与跨项目复用

- 同一已验证手机号只能存在一个全国会员账户。
- 会员进入新城市或新项目时复用原身份、成长值和等级，不另建项目会员。
- 项目可以保留会员与项目的业务关系，但该关系不得生成独立会员身份或独立等级。
- 不同手机号不得仅凭姓名、生日或其他弱信息自动合并；系统不得声称已经识别为同一自然人。

### 5.3 免费会员边界

- 全国会员身份免费，不设置付费订阅状态。
- 历史“付费会员”不得被解释为新的会员等级或身份类型。
- 商业权益可以通过商品、券或活动提供，但不得改变会员身份免费的原则。

## 6. 成长值

### 6.1 账本边界

- 成长值与积分分别计算、分别记账、分别展示。
- 成长值不可消费、抵扣、兑换、转赠或提现。
- 积分余额、积分倍率结果或积分活动奖励不得反向作为成长值。

### 6.2 成长值来源

只有完成且符合资格的付费消费产生成长值。

以下事件均不产生成长值：

- 注册；
- 签到；
- 生日；
- 营销奖励；
- 储值充值；
- 押金；
- 积分兑换；
- 零元订单；
- 积分加现金兑换。

### 6.3 成长值规则

- 平台分别配置积分规则和成长值规则，二者不得共用倍率或计算结果。
- 特殊通票或 SKU 可以分别配置固定积分和固定成长值；任一固定值不能推导另一固定值。
- 成长值采用平台基础规则。
- 平台可以配置成长值活动倍率，但必须经过审批、限定适用期限、适用范围并生成版本。
- 项目和商户不得自行修改平台成长值基础规则或活动版本。
- 缺少有效成长值规则时，不得静默按积分规则计算。

### 6.4 退款与纠错

- 退款期内发生退款时，按原订单规则版本和退款后保留的合格消费结果重算并冲回差额成长值。
- 确认后发生特殊退款、拒付、欺诈或系统纠错时，冲回对应成长值并触发等级重新计算。
- 冲回必须关联原订单、原成长值明细、原因、处理主体和时间。

## 7. 等级计划

### 7.1 初始六级

平台初始等级从低到高为：

1. 新乐会员
2. 银卡
3. 金卡
4. 白金
5. 钻石
6. 黑钻

等级名称、数量、成长值门槛、权益和积分倍率均由平台版本化配置。

> **口径标注（2026-08-04 第三轮用户裁决 HC-08 / DEC-R6-21 定稿）**：上列六个等级名称（新乐会员 / 银卡 / 金卡 / 白金 / 钻石 / 黑钻）为**出厂默认名称，HTML 已载**——已写入 ENUM「等级与成长值」条，具**业务事实源效力**，原「示例配置、非业务口径、不得对外发布或作为接口枚举真源」的降格标注**已删除**。等级名称属**业务参数、全平台统一可配**，此六个名称为出厂默认值；同理「六级」是**出厂默认的等级数量**，等级数量本身可配（见 §7.2）。原 C 类登记 AUD C-15 **已关闭**。

### 7.2 配置完整性

等级计划启用前必须同时满足：

- **等级数量 ≥ 2**（**六级为出厂默认配置**；等级数量由等级规则版本配置，**不以「必须恰好六级」作为启用校验条件**——否则与 §3、§7.1「数量由平台版本化配置」互斥）；
- 每级上下界明确；
- **区间连续、无重叠、无空档**（相邻等级的上下界必须首尾相接，既不重合也不留缝）；
- **最低等级覆盖零成长值会员**（零成长值必须落在最低等级区间内，不得出现无等级可归的会员）；
- 每级权益和积分倍率有明确值；
- **每级积分倍率 ≥ 1**（硬约束，见 §9）；
- 生效时间和审批记录完整。

任一条件不满足，系统必须阻止等级计划启用。

### 7.3 统计周期

- 等级评定使用评估时点向前滚动的**滚动统计周期**内的有效成长值。**滚动统计周期为业务参数，全平台统一可配，出厂默认十二个月，须同时配置上下限。**
- 自然年、注册周年或项目经营年度不得替代该滚动周期。
- 每笔成长值必须保留发生时间，超出滚动窗口后不再参与当前等级计算，但历史账本不删除。

### 7.4 三项等级参数的可配置口径

| 参数 | 参数性质 | 出厂默认 | 约束 |
|---|---|---|---|
| 滚动统计周期 | 业务参数，全平台统一可配 | 十二个月 | 须同时配置上下限 |
| 升级保护期 | 业务参数，全平台统一可配 | 十二个月 | 须同时配置上下限 |
| 降级提前通知天数 | 业务参数，全平台统一可配 | 三十天 | 须同时配置上下限 |

- 上述三项参数的变更**须经审批**、**只对后续周期生效**，**不追溯已确认的等级**。
- 项目和商户不得覆盖这三项参数；本文各处出现的「十二个月」「三十日」均为出厂默认值，实际以生效版本为准。

## 8. 升级、保护与降级

### 8.1 即时升级

- 会员在滚动统计周期（业务参数，全平台统一可配，出厂默认十二个月，须配上下限）内的成长值达到更高等级门槛时立即升级。
- 可以一次跨越多个等级，直接升至实际符合的最高等级。
- 升级日即为新等级保护期起点；**升级保护期为业务参数，全平台统一可配，出厂默认十二个月，须同时配置上下限**。
- 升级必须保存评估时点、成长值快照、原等级、新等级和规则版本。

### 8.2 保护期

- 保护期内，即使滚动成长值暂时下降，也不因普通窗口滚动而降级。
- 保护期内再次达到更高等级时立即升级，并从新升级日按当时生效的保护期参数重新开始计算保护期。
- 等级规则版本变化不得追溯缩短已经开始的保护期；保护期参数变更只对后续周期生效，不追溯已确认的等级。
- 特殊退款、拒付、欺诈或系统纠错造成成长值冲回时，系统按冲回后的成长值重新计算；该纠错不受“普通窗口滚动不降级”的保护限制。

### 8.3 降级评估与通知

- 保护期结束时，系统按届时滚动统计周期内的成长值重新计算等级。
- 会员可直接降至实际符合的等级，不要求逐级下降。
- 系统必须按后台配置的**降级提前通知天数**（业务参数，全平台统一可配，出厂默认三十天，须同时配置上下限）在保护期结束前发出**降级预警**，告知按发出预警当日的成长值测算将降至哪一等级。
- **降级预警只是提醒，不是降级决定**：最终等级一律以保护期结束当日、按届时滚动周期内的成长值重新定级的结果为准（BSM「等级与成长值」条）。
- 发出预警后至保护期结束前，会员成长值重新达到原等级门槛的**不降级**，并向其发出「已保级」通知。
- **保护期结束时应当降级但此前未曾发出预警的（含预警发出后成长值又下滑至更低等级的情形），降级仍照常执行，并在降级生效后立即补发通知**——未发预警不阻断降级、不构成降级无效（BSM「等级与成长值」条）。
- 通知期内新增长值达到更高门槛时，评估结果随最新有效成长值更新。
- 降级生效时保存成长值快照、原等级、新等级、规则版本、通知记录和生效时间。

## 9. 等级积分倍率

- 等级可以为基础积分配置永久倍率，但不得放大成长值。
- **等级倍率 ≥ 1（硬约束）**：倍率小于 1 会使 `等级加赠积分 = floor(基础积分 × (倍率 − 1))` 为负、会员总积分**少于**基础积分，与「等级**加赠**」语义相反。**倍率 < 1 的等级规则版本不得通过审批、不得生效**；倍率 = 1 表示该级不加赠（合法）。本约束与 `docs/points-and-voucher-product-prd-v1.0.md` §7.1 同步，并作为 §7.2 等级计划启用校验的一项。
- 等级加赠积分的成本由发生消费的商户承担。
- 等级积分倍率由全国平台统一配置、审批、生效和版本化，覆盖范围内的商户必须接受并执行，不在商户合同中另行约定倍率或倍率上限。
- 基础积分和等级加赠积分的成本均由发生该笔有效消费的商户承担。
- 缺少全国有效倍率版本时不得发放等级加赠积分。
- 订单使用哪个倍率版本、如何计算积分，由 `docs/points-and-voucher-product-prd-v1.0.md` 定义。

## 10. 状态与版本

### 10.1 会员身份状态

| 状态 | 含义 | 允许的主要后继状态 |
|---|---|---|
| `ACTIVE` | 全国会员身份有效。 | `RESTRICTED`、`CLOSED`、`DEREGISTERED` |
| `RESTRICTED` | 因合规或风控原因限制部分权益。 | `ACTIVE`、`CLOSED`、`DEREGISTERED` |
| `CLOSED`（已关闭） | **平台的主动行为**，已按适用规则关闭会员关系。 | 该手机号**不得再次注册** |
| `DEREGISTERED`（已注销） | **由客人自行发起**的账户注销。 | 该手机号**可以重新注册**，新账户与原账户之间不建立任何关联 |

会员身份共有 `ACTIVE`（有效）、`RESTRICTED`（受限）、`CLOSED`（已关闭）、`DEREGISTERED`（已注销）四种状态。「已关闭」与「已注销」必须明确区分：前者是平台主动关闭、手机号不得再注册；后者是客人自行发起、手机号可以重新注册，且新账户与原账户之间不建立任何关联（不继承成长值、等级、积分、券或历史消费关系）。

关闭（黑名单）审批链：**将客人列入黑名单即为关闭其账户**；黑名单**全平台通用**；审批链为**保安团队申请 → 夜班值班经理批准 → 娱乐平台负责人批准**，三个环节齐备才允许关闭，并留申请人、各级审批人、原因和时间。

**手机号唯一性的作用域（2026-08-04 补）**：§5.2「同一已验证手机号只能存在一个全国会员账户」的唯一约束**限定于非 `DEREGISTERED`（已注销）状态**——已注销手机号可以重新注册，其历史账户行必须保留且**不得占用唯一名额**，故该唯一性须以**部分唯一索引**（仅对非已注销状态的会员行生效）承载，不能用无条件唯一约束。`CLOSED`（已关闭）手机号**不得再次注册**，但该限制**不由唯一索引实现**——已关闭账户行虽仍占唯一名额，其拦截依据应是**另立的不可注册名单**（黑名单，全平台通用），在注册前置校验阶段拒绝，从而与「已注销可重注册」互不干扰。

> **实现现状（待改造缺口 E-12，2026-08-04 登记）**：现库对客人手机号为**无条件 UNIQUE**（`customers.phone VARCHAR(20) NOT NULL UNIQUE`，V009；`customers_phone_hash_key UNIQUE (phone_hash)`，V188），**既无状态条件的部分唯一索引，也无不可注册名单**。据此，客人自行注销后以原手机号重新注册将被唯一约束直接拒绝，与本条及 ENUM「会员身份状态」条 冲突；同时「已关闭手机号不得再注册」目前只能依赖历史行占位这一副作用实现，缺乏显式承载。属**待改造缺口**，改造前不得对外声称已实现「已注销可重注册 / 已关闭不可注册」的区分。

若未来需要恢复 `CLOSED` 会员，必须先由用户批准并写入三个 HTML，PRD 不预设恢复流程。

**注销重注册的新人资格与异常预警（2026-08-04 第三轮用户裁决 UD-08 / DEC-R6-11）**：注销后以同一手机号重新注册的，**默认不穿透历史**——新账户视为新人、**可再享新人资格**（与本节「新账户与原账户之间不建立任何关联」一致）。反复套利以**异常预警**而非阻断注册的方式管控：**同一手机号一年内注销＋注册合计次数超过阈值触发异常预警**（业务参数、全平台统一可配、须同时配置上下限，**出厂默认一年内合计 3 次**）；**预警只作提示、不自动阻断注册**，汇入「异常预警页面」供风控岗查看处置。同一口径见 `docs/ticketing-entitlement-checkin-product-prd-v0.1.md` §5.1。**实现改造列入排期**：注销重注册计数与预警触发当前无承载（缺口登记见修复台账 §7.4）。

本文不定义储值账户关闭或资金处置；客人端注销申请入口、注销时的存酒与储值余额处置、个人信息删除与钱账留存口径见 `docs/customer-app-miniapp-product-prd-v0.1.md`。

### 10.2 等级规则版本

- 新版本必须包含完整等级集合，不允许只发布单级差异。
- 新版本必须指定未来或当前可审计生效时间，不得覆盖历史版本。
- 订单、成长值明细、等级评估和通知必须引用实际使用的版本。
- 已开始保护期按开始时有效规则继续计算保护截止日；新版本只影响生效后的新评估，除非用户另行批准明确迁移规则。

## 11. 异常控制与审计证据

- 注册、成长值入账、成长值冲回、升级、通知和降级必须具备业务幂等性。
- 重复消费事件不得重复增加成长值。
- 缺少有效规则、等级计划、全国倍率版本或审批时，相关能力不得生效。
- 申请人与审批人必须分离。
- 系统不得静默修改成长值或等级；所有调整必须形成关联原业务的调整记录。
- 审计记录至少包含主体、时间、项目、商户、订单、成长值变化、原等级、新等级、规则版本、原因、申请人和审批人。

## 12. 顺从性验收

1. 同一已验证手机号在两个项目注册时，第二次注册复用同一会员身份，不产生第二等级账户；不同手机号不自动合并。
2. 注册、签到、生日、充值、押金、积分兑换、零元订单和积分加现金兑换均不会增加成长值。
3. 合格消费可以同时产生按独立规则计算的成长值和积分，但二者计算结果互不推导。
4. 达到更高门槛时立即升级，并从升级日开始按生效的保护期参数（出厂默认十二个月）计算保护期。
5. 保护期结束时按滚动统计周期（出厂默认十二个月）内的成长值直接降至实际符合等级，且按生效的提前通知天数（出厂默认三十天）提前发出降级预警；**预警只是提醒不是降级决定，最终以保护期结束当日重新定级的结果为准；应当降级但未曾发出预警的，降级仍照常执行并在生效后立即补发通知**（BSM「等级与成长值」条）；三项等级参数（滚动统计周期、升级保护期、降级提前通知天数）的变更须经审批、只对后续周期生效，不追溯已确认的等级。
6. 等级数量少于 2 级，或各级门槛存在重叠、空档、缺项，或最低等级未覆盖零成长值，或存在小于 1 的等级倍率时，等级计划不能启用；**「六级」是出厂默认的等级数量，不作为启用校验的硬性数量条件**。
7. 等级倍率只影响基础积分，不改变成长值。
8. 商户不能另行约定、关闭或限制全国等级倍率；缺少全国有效倍率版本时拒绝发放等级加赠积分。
9. 规则版本切换不会追溯缩短已开始保护期，历史评估可以按版本复现。

## 13. 对抗性验收

| 反例 | 必须结果 |
|---|---|
| 项目试图为本项目会员创建独立等级 | 阻断；复用全国会员身份和等级。 |
| 商户把营销积分当作成长值 | 阻断；两类账本和规则分离。 |
| 使用自然年替代滚动统计周期 | 判为不合规，按评估时点及生效的滚动统计周期重新计算。 |
| 保护期结束后只降一级 | 判为不合规，直接降至实际符合等级。 |
| 未提前通知即降级 | **不阻断**：降级照常执行，并在降级生效后立即补发通知（BSM「等级与成长值」条）。原「阻断降级并补齐通知流程」写法**已废止**——预警只是提醒、不是降级决定，未发预警不构成降级无效。 |
| 项目自行修改成长值规则 | 阻断；只能使用平台有效版本。 |
| 新等级版本覆盖历史门槛 | 阻断覆盖；必须生成新版本并保留历史。 |
| 重复消费消息重复入账 | 幂等拦截，只认一次。 |
| 特殊退款冲回成长值但不重算等级 | 判为不合规，必须触发等级重新计算并留痕。 |
