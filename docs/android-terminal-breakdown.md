# 安卓端专项拆分：员工工作手机、酒吧点酒平板、触摸屏一体机

## 1. 安卓端定位

安卓端分为三类：员工工作手机、酒吧点酒平板、触摸屏一体机。它们不是普通游客 App；员工工作手机和平板也不是代客售票入口。门票主路径由客人通过官方 App/小程序或第三方平台自助购买；少量到店服务场景下，授权服务人员可在启用售票能力的一体机上辅助购票；酒吧点酒平板不得出现购票入口。

安卓端核心目标：

- 员工只能使用公司统一配发设备工作。
- 设备领用、归还、绑定、交接班全流程留痕。
- 员工工作手机支持门票、赠饮、礼物、游乐等权益扫码核销。
- 员工私人手机可安装轻量 App，仅用于注册、通知、状态查看和**设备凭证绑定（安装期生成存 Keystore 的设备公钥/不可逆设备指纹，phone-3/D8 废止读手机本机 NFC 唯一标识）**，不做现场业务操作。
- 员工工作手机只允许使用企业微信进行工作沟通，企业微信会话每天自动上传到后台。
- 酒吧点酒平板只支持绑定酒吧和卡座/桌台后的点酒下单、最低消费校验和支付引导。
- 触摸屏一体机分售票型和非售票型：售票型支持授权服务人员辅助到店客人购票、取票和订单查询；非售票型支持扫码展示/领取权益、订台下单、吧台买酒下单、游乐设施状态查看和授权状态检查。
- 工作手机不允许安装除预装软件之外的任何软件，只允许访问白名单网站。
- 所有关键操作进入后台事件中心。
- 支持 MDM 或设备管控策略，减少私用、绕单、飞单和数据泄露风险。

## 2. 设备形态

### 2.1 员工工作手机

适合移动员工随身使用。

| 使用人 | 典型场景 |
|---|---|
| 服务员 | 门票附赠权益核销、客诉记录、客户沟通、酒水送达确认 |
| 核销员 | 入园核销、酒吧入场核销、游乐项目核销、赠饮或礼物领取核销 |
| 现场主管 | 异常审批、员工调度、风险预警处理 |
| 巡检员 | 设备巡检、安全检查、拍照留痕 |
| 库管 | 出库、入库、调拨、盘点、机器人取货确认 |

特点：

- 便携
- 必须绑定员工和班次
- 适合扫码、NFC、拍照、定位
- 现场任务可预留离线能力，但票务二维码 P0 必须在线核验，截图无效
- 必须强管控，禁止私人微信、私自安装应用和访问非白名单网站
- 预装企业微信，工作聊天每日自动上传后台用于服务分析和违规检查

### 2.1.1 员工私人手机 App

适合员工入职或上岗前的轻量身份确认。

| 场景 | 说明 |
|---|---|
| 注册 | 员工提交个人信息、岗位申请、联系方式和设备信息 |
| 设备凭证绑定 | 私人手机 App **安装期生成并存于 Keystore 的设备公钥/不可逆设备指纹**作为唯一身份标识；换手机必须先解绑旧设备凭证再绑定新设备凭证。**废止"读手机本机 NFC 唯一标识"**（Android 不可行，见下方修订说明） |
| 审批 | 后台审核通过后生成员工账号、角色、职级和权限 |
| 通知 | 收发公司通知、查看班次、查看审批状态 |
| 风险 | Root、调试、**设备凭证/指纹变化或不匹配（mismatch）**时 App 失效 |

> 修订说明（2026-06-10，phone-3 / 统一口径基准 D8）：原"NFC绑定=读取手机 NFC 唯一标识"技术不可行——Android NFC API 只能读取**外部**标签/卡片 UID，不向普通 App 暴露"本机手机稳定 NFC 硬件唯一标识"（HCE 也不提供），编码期取不到该值，会导致身份绑定/换机解绑/一一对应关系全部落空。故改为"安装期生成存 Keystore 的设备公钥/不可逆设备指纹"凭证；**仅持久化不可逆哈希/公钥指纹，不存原始标识**（PIPL 数据最小化，C4）。注意：**工作手机通过摄像头/扫码模块读取外部客人二维码；NFC 仅读取外部 NFC 腕带、标签、卡或设备中的权益标识**（见 §4.3）。

边界：

- 私人手机 App 不允许核销、点单、放行、结算和补录。
- 私人手机与公司发放工作手机建立一一对应关系。
- 员工进入办公区或现场作业区后，私人手机需要寄存，现场只允许使用公司受管工作手机。

PIPL 合规要求（私人手机 App 个人信息处理，回填合规文档 C4）：

- **告知同意：** 安装/注册时单独告知并取得同意——生成/绑定设备凭证、做 Root/调试检测、采集必要设备指纹；在"员工注册审批"页留存同意凭据。
- **数据最小化：** 仅存不可逆哈希/设备公钥指纹，不存原始唯一标识；用途限定身份绑定与可信校验。
- **解绑删除：** 换机解绑或离职注销时删除对应设备绑定凭据。
- **统一监控告知（C10）：** Root/调试检测、设备指纹采集并入"员工数据处理与监控合规"统一告知（入职协议/规章制度），用途限定与查看审计。

### 2.2 安卓平板

平板只作为酒吧点酒下单工具，不承担门票购买、门票核销、游乐核销、库存盘点和主管后台操作。

| 使用点位 | 典型场景 |
|---|---|
| 酒吧吧台 | 选择所属酒吧、确认卡座/桌台、点酒下单 |
| 酒吧卡座服务点 | 绑定卡座、选择酒水、校验最低消费 |
| 酒吧服务台 | 生成支付二维码、扫描客人付款码、查看卡座账单 |

特点：

- 屏幕更大
- 适合桌台图、卡座状态、酒水列表、账单金额
- 可以固定在岗位，也可以交接领用
- 可以与扫码枪、打印机连接
- 不显示票种、门票购买、游乐权益购买入口

### 2.3 安卓触摸屏一体机

适合固定点位长期运行。

| 点位 | 典型场景 |
|---|---|
| 权益领取点 | 客人扫码后展示可领取酒水、礼物和其他权益 |
| 酒吧吧台旁 | 展示赠饮、积分兑换礼物、领取状态，也支持订台和吧台买酒下单 |
| 入口或票务服务点 | 售票型一体机支持授权服务人员辅助到店客人购票、取票和订单查询 |
| 游乐或活动服务点 | 展示可领取/可使用权益，展示游乐设施状态，并支持授权员工做状态检查 |

特点：

- 常驻固定点位
- 不一定绑定个人，但必须绑定点位和设备编号
- 更适合 kiosk 模式
- 需要防退出、防切应用、防断网异常
- 可以接扫码器、NFC、打印机、摄像头
- 售票型一体机承担授权服务人员辅助到店客人购票、取票和订单查询，必须复用票务价格、库存、聚合支付、出票和防伪二维码能力
- 非售票型一体机不承担门票购买；领取确认、订台、吧台买酒、游乐状态检查都需要写入事件中心

| 模块 | 功能 |
|---|---|
| 员工登录 | 工号/手机号/企业微信身份登录 |

### 4.3 员工工作手机票务/权益核销

| 功能 | 说明 |
|---|---|
| 二维码核销 | 扫游客票码或权益码 |
| NFC核销 | 读取**外部**客人腕带、卡片、设备标签的 UID 或加密 payload |
| 手动输入 | 自动核销失败时由授权员工输入票号或手机号 |
| 离线核销 | P1 预留；P0 票务二维码必须在线核验，截图无效 |
| 重复核销提醒 | 本地和服务端双重判断 |
| 核销证据 | 时间、地点、员工、设备、照片可选 |
| 异常上报 | 过期、重复、无权益、票码异常 |

> 修订说明（2026-06-07，phone-3 / D8）：此处"NFC核销"指**工作手机读取外部客人腕带/卡片/标签**做权益核销，与"私人手机身份绑定"完全不同，**保留不受影响**。被废止的只是"私人手机读手机本机 NFC 唯一标识作为身份依据"（见 §2.1.1 修订说明）。

## 5. 关键流程

### 5.1 上班领设备流程

1. 员工到岗。
2. 扫码或 NFC 领取公司设备。
3. App 读取设备编号。
4. 员工登录。
5. 系统绑定员工、设备、班次、区域。
6. 后台开启当班权限。
7. 生成 `device.checked_out` 事件。

### 5.2 下班归还设备流程

1. 员工点击交班。
2. App 检查未同步数据。
3. App 检查未完成订单、核销、补录、工单。
4. 员工归还设备。
5. 主管或设备柜确认。
6. 后台解除员工和设备绑定。
7. 生成 `device.returned` 事件。

### 5.3 离线核销流程（P1 预留，P0 不启用）

1. App 检测网络断开。
2. P0 提示必须恢复网络后在线核验；P1 才允许进入离线核销模式。
3. 使用本地可核销权益缓存。
4. 记录本地核销流水。
5. 本地防重复核销。
6. 网络恢复后上传离线流水。
7. 后台二次校验。
8. 正常则确认，冲突则进入异常工单。

### 5.4 存酒取酒流程

1. 客人提供手机号、会员码或存酒二维码。
2. 员工查询存酒。
3. 库管或吧台扫描瓶身二维码。
4. 客人确认取酒。
5. 员工拍照或签名留痕。
6. 系统扣减存酒状态或剩余量。
7. 生成存酒取用事件。

### 5.5 机器人交接流程

1. 后台生成机器人任务。
2. 机器人到取货点。
3. 库管扫描订单码和物料二维码，确认订单、物品和数量匹配。
4. 库管扫描或点击确认交给机器人，形成 `inventory.handover_to_robot` 事件。
5. 机器人配送并被动上报配送状态。
6. 机器人到达酒吧后厨或指定点位。
7. 后厨员工扫描物料二维码确认接收。
8. 服务员扫描物料二维码确认从后厨取走。
9. 服务员送达客人或卡座后扫码或订单确认送达。
10. App 记录签收，视频证据中心自动关联摄像头片段。

机器人交接不是只记录机器人状态，还必须记录每一次人和物、人和机器人、人和客人的责任交接。

### 5.6 工作手机扫码→一体机展示跨设备协同

> 修订说明（2026-06-07，phone-4）：原始需求隐含一个跨设备动作——员工用工作手机扫客人附赠酒水/权益二维码，结果在就近/指定一体机大屏向客人展示可领取内容。原文（§2.3、§4.4）把它实现为两个互不关联的入口，缺设备/点位配对、触发与会话关联，导致客人需在一体机重复扫一次或场景无法落地。本节补齐。详细字段、API 与事件见 `android-device-terminal-development-design §5.5/§14.5`。

产品形态（采纳）：工作手机扫码 → **指定/就近一体机推送展示**（非"一体机自助扫码"）。两端通过点位配对，共享同一 `entitlement_session_id` 关联同一权益实例（`issued_entitlement`）。

流程：

1. 工作手机扫客人附赠权益码。
2. 后端校验权益实例，生成 `entitlement_session_id`。
3. 后端按当前点位/区域解析"就近可展示一体机"，或员工手动指定目标一体机编号。
4. 推送优先（WebSocket/长连）、一体机轮询兜底，目标一体机大屏展示可领取内容。
5. 客人在一体机确认领取，领取结果回写同一 `entitlement_session_id`。
6. 工作手机收到领取结果回执（成功/超时/取消）。

关键约束：

- `entitlement_session_id` 设短时效（默认 5 分钟），超时失效并通知工作手机，避免错领。
- 一体机展示页明确显示会话来源（哪台工作手机/哪位员工）与权益摘要；同一会话只能被领取一次，领取以服务端为准。
- 点位→可展示一体机列表随当班上下文/点位配置下发。

### 8.3 工作手机受管态准入（P0 前置，A8）

> 修订说明（2026-06-10，phone-6 / 决策 A8 已拍板）：原文把"是否采购 MDM"列在历史暂缓事项（§11、§12），但 §8.1 又要求"禁止私装应用/网站白名单"。普通业务 App 无法稳定完成系统级强管控，因此工作手机/平板正式方案已确认为 **Android Enterprise / Android Management API + 商业 MDM**，并作为 P0 准入前置。详细分档见 `android-device-terminal-development-design §13.1.1`。

| 档位 | 前置条件 | P0 验收口径 |
|---|---|---|
| 受管态（强管控） | Android Enterprise / Android Management API + 商业 MDM；下发应用/网站白名单与禁止私装策略 | 不能安装非预装软件、不能访问非白名单网站、强制仅企业微信、远程锁定可达；策略命中与封禁留痕 |
| 应急试点（非正式发放） | 未完成商业 MDM 接入前，仅验证业务 App、扫码、企微状态和设备档案 | 只能检测并上报，**不得作为正式发放工作手机**，不得通过 P0 强管控验收 |

**总控拍板（2026-06-10）：** 正式方案采用 Android Enterprise / Android Management API + 商业 MDM，由平台公司 IT 选型、采购、配置和运维；自研 DPC 或未接入商业 MDM 只可作为试点。

### 8.4 权限封禁处置（策略违规闭环）

> 修订说明（2026-06-07，phone-5）：原始工作手机管控口径曾混用"阻止访问"与"封禁权限"。本节区分"阻止访问"（白名单拦截，已落地为 `device.policy_violation` + 设备锁定）与"封禁权限"（收回违规员工/设备业务操作权限）。后者原文缺触发条件、封禁对象、状态机、解封流程与留痕字段。本节补齐使其可编码，并与 `data-risk-ai-development-design §10.7` 设备策略违规规则 `STAFF_DEVICE_ABNORMAL` 联动。详细字段与状态机见 `android-device-terminal-development-design §13.4`。

| 环节 | 内容 |
|---|---|
| 违规阈值（触发） | 白名单违规 24h≥N 次 / Root 调试设备指纹异常 / 企微未上传或私单高风险 / 受管设备私装 / 人工研判 → 由 `STAFF_DEVICE_ABNORMAL` 产出封禁建议 |
| 封禁动作（分级） | 停用相关权限点（账号仍可登录） / 解除当班绑定（强制交班重新领用） / 停用设备（置 locked 触发远程锁定），可组合 |
| 留痕字段 | `ban_id`、`subject_type`(staff/device/staff_device)、`subject_id`、`ban_scope`、`affected_permission_points`、`ban_reason`(含触发规则码)、`triggered_by`(auto/manual)、`operator_id`、`banned_at`、`status`、解封申请/审批/时间 |
| 解封审批与状态机 | active → unban_requested → (approved→released) / (rejected→active)；高风险封禁不允许自动解封，普通员工只能申请由主管/安全审批 |
| 事件 | `device.permission_banned`、`device.permission_ban_lifted`，与 `STAFF_DEVICE_ABNORMAL` 关联同一事件链 |

封禁（主体级收回业务操作能力，可只封某些权限点）与设备远程锁定（设备级停机）不同，可独立或叠加。

## 11. 第一阶段 MVP

第一阶段安卓端先做“员工工作手机核销 + 酒吧平板点酒 + 售票型一体机授权服务人员辅助购票/取票/订单查询 + 非售票型一体机自助服务 + 设备绑定和留痕”。

必须做：

1. 员工登录。
2. 设备识别。
3. 设备领用和归还。
4. 员工、设备、班次、区域绑定。
5. 员工工作手机二维码核销。
6. NFC预留接口。
7. 离线核销本地队列（P1 预留，P0 不启用）。
8. 恢复联网后同步。
9. 人工补录基础能力。
10. 事件中心上报。
11. 设备锁定和强制同步。
12. 酒吧平板绑定酒吧和卡座/桌台。
13. 酒吧平板点酒下单和最低消费校验。
14. 客人扫码支付和平板扫客人付款码支付。
15. 售票型触摸屏一体机由授权服务人员辅助到店客人购票、取票和订单查询；绑定酒吧门口/前台时只能售卖本酒吧单店门票。
16. 非售票型触摸屏一体机扫码展示/领取可领取酒水、礼物和权益。
17. 触摸屏一体机订台下单：选择酒吧、时段、卡座/桌台/吧台位、人数和备注。
18. 触摸屏一体机吧台买酒：选择酒水、套餐、数量，生成待支付订单。
19. 触摸屏一体机游乐状态：查看开放、排队、容量、暂停、故障和维护状态。
20. 触摸屏一体机授权状态检查：员工授权后记录检查结果和异常原因。
21. 工作手机预装企业微信，员工工作会话每天自动上传后台。
22. 工作手机应用白名单和网站白名单基础管控。
22. 企业微信会话基础规则质检，命中违规内容进入后台复核。
23. 员工私人手机 App 注册、**设备凭证绑定（Keystore 设备公钥/不可逆设备指纹，phone-3/D8 废止读手机本机 NFC 唯一标识）**、换机解绑重绑（先解绑旧设备凭证再绑新）、Root 检测、审批状态查看、PIPL 告知同意/最小化/解绑删除（C4）。
24. 员工私人手机、**设备公钥指纹**、公司工作手机一一对应关系。
25. 工作手机受管态准入（A8，phone-6）：正式发放设备必须接入 Android Enterprise / Android Management API + 商业 MDM，并回传设备档案、策略摘要、合规状态、启停和审计记录；未配置商业 MDM 的设备只能用于开发/应急试点，不得通过 P0 强管控验收。
26. 策略违规权限封禁闭环（phone-5）：违规阈值→封禁动作→留痕→解封审批与状态机，与 STAFF_DEVICE_ABNORMAL 联动。

暂缓：

1. 酒吧复杂存酒和库存深度联动。
2. 完整库存盘点。
3. 企业微信 AI 深度语义分析和员工服务评分模型。
4. 商业 MDM **增强**集成（更细策略中心、批量远程清除、自动合规报表、跨厂商策略模板）；注意：工作手机**受管态准入本身已升级为 P0 前置（A8，见 §8.3 第 25 项）**，此处暂缓的是增强能力，不是 P0 设备管控准入。
5. 机器人完整调度。
6. 桌台图复杂交互。
7. Android SDK自动打包流水线。
