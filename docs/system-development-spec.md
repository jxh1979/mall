本文档是项目后续拆解、评审和编码的总入口。目标不是写概念方案，而是形成可以直接指导后端、前端、安卓端、运维和数据服务开发的系统规格。

## 1. 文档目标

完整系统文档必须回答以下问题：

- 系统有哪些业务域、子系统和模块。
- 每个模块负责什么，不负责什么。
- 每个模块有哪些核心对象、状态机和业务流程。
- 每个模块需要哪些数据库表、字段、索引和约束。
- 每个模块暴露哪些 API，入参、出参、权限和错误码是什么。
- 每个关键操作如何写入事件中心，如何审计和追溯。
- 每个模块和多综合体、多商户、权限、合同准入、票务、酒吧、游乐、第三方、安卓设备、数据分析之间如何协作。
- 第一阶段先做什么，哪些功能暂缓。

## 2. 总体技术路线

> 修订说明（2026-06-10）：下表为**正式技术栈（已拍板）**。本规格全部 `*-development-design` 均以下表 Java 路线为准。依据《统一口径基准》D10、A1，finding devtech-9、status-1。

| 层级 | 技术方向 | 说明 |
|---|---|---|
| 核心后端 | Java 21 + Spring Boot 4.x | 承接多综合体、多商户、合同准入、权限、开放平台、票务、酒吧、游乐、结算、事件中心 |
| 数据库 | PostgreSQL + Flyway | 正式主库和版本化迁移 |
| 缓存与锁 | Redis | 短期 Token、动态鉴权、限流、幂等、热点缓存 |
| 异步事件 | NATS | 业务事件、第三方回调、异步补偿、风控分析 |
| 对象存储 | MinIO | 图片、视频证据索引、附件、导出文件 |
| 管理后台 | React | 平台端、商户端、运营看板 |
| 安卓端 | Kotlin Android | 员工私人手机 App、员工工作手机、企业微信管控、酒吧点酒平板、触摸屏一体机、扫码、外部 NFC 读取、P1 预留离线核销、最低消费校验、订台、吧台买酒、游乐状态 |
| 数据分析/AI | Java 内置规则处理器（P0）；独立 Python AI 服务（P2） | P0 指标体系、基础风控规则、企业微信基础质检和经营分析由 Java 后端承接；高级 AI/Python 服务后置 |
| 运维部署 | Ubuntu 160 + Nginx + systemd + Docker Compose | 开发/预生产一体环境 |

## 5. 第一阶段 P0 闭环

第一阶段目标是打通“可运营、可核销、可留痕、可部署”的最小闭环。

P0 必须完成：

- Java Spring Boot 后端骨架。
- PostgreSQL + Flyway 迁移。
- 多综合体/多商户、合同准入、账号权限、开放应用、事件中心。
- 员工私人手机 App 注册、设备凭证绑定、职级权限、公司工作手机绑定。
- 票种、通票、权益实例、防伪二维码/串码、二维码核销和事后核对。
- 酒吧入场核销、桌台、基础点单。
- 游乐项目档案、容量、项目核销。
- 安卓端登录、设备绑定、扫码核销、离线队列。
- 管理后台基础页面。
- 160 部署和健康检查。

P0 暂缓：

- 复杂营销。
- 完整会员体系。
- 复杂财务结算自动化。
- 机器人智能调度。
- 视频 AI 自动识别。
- 全量数据仓库。
- 多端复杂大屏。

## 7. 文档汇总规则

- 子线程产出的开发设计必须落到 `docs/`。
- 重要结论必须回填本文档或进度看板。
- 数据库、接口、权限、安全、结算相关变更必须先写设计再编码。
- 任何模块如果影响票务权益、结算、动态鉴权或事件中心，必须回到总控会话统一协调。
