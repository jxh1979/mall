# 工作流与维护线程索引

本项目后续按专项线程维护。主线程继续作为总控协调线程，用于决策、汇总、跨模块排序和最终集成。

## 1. 线程划分

> 修订说明（2026-06-07）：本表按"工作流编号 01-08"组织（共 8 个工作流），与线程 ID 登记表 `thread-registry.md` 的 **10 条专项线程**为同一套工作的两种视图，不是数量矛盾：本表把"业务系统：酒吧/游乐/第三方"合并为 08 一个工作流，而 registry 将其拆为"酒吧""游乐""第三方集成"三条独立线程；两边都含 03 Java 后端、04 前端两条工程实现线程。**thread-registry 只对线程 ID 有效，不是业务口径权威**；三份业务 HTML 拥有最高业务解释权，其他文档不得覆盖。`master-roadmap` 所称"8 个专项线程"= 本表 01-08 工作流口径，线程总数以 registry 的 10 条为准。依据 finding xref-6、status-3。

## 2. 主线程职责

主线程只做以下事情：

- 总体架构决策。
- 子系统优先级排序。
- 跨线程冲突处理。
- 阶段性汇总。
- 最终集成和发布节奏。

具体模块细化和开发，优先进入对应专项线程。

## 3. 当前建议推进顺序

### 第一批：开发地基

1. 03 核心后端：Java Spring Boot 架构
2. 01 地基系统：多商户、权限
3. 02 开放平台与安全鉴权
4. 06 160服务器：部署、运维、安全

目标：完成 Java 后端骨架、数据库迁移、商户/权限/开放应用最小闭环，并能部署到 160。

### 第二批：管理后台

1. 04 前端管理后台：React 控制台
2. 01 地基系统：多商户、权限
3. 02 开放平台与安全鉴权

目标：做出可用后台，支持商户、账号、开放应用、鉴权日志、事件查询。

### 第三批：核心业务

1. 07 业务系统：票务、通票、权益、结算
2. 08 业务系统：酒吧、游乐、第三方集成
3. 05 安卓端：工作手机、点酒平板、一体机

目标：客人自助购票、权益拆分、工作手机核销、酒吧平板点酒、游乐基础运营和现场操作。

## 5. 维护原则

- 每个线程只处理自己的专项范围。
- 跨模块改动先回到主线程确认。
- 重要设计更新必须同步到 `docs/`。
- 涉及数据库、鉴权、安全、结算的改动必须先写设计再编码。
- 服务器系统配置变更必须同步更新 `docs/server-160-runbook-v0.2.md`。
- 线程 ID 以 `docs/thread-registry.md` 登记表为准（仅对线程 ID 有效）。非 HTML 登记表不是唯一权威；三份业务 HTML 拥有最高业务解释权，其他文档不得覆盖。
