> **口径修订（2026-08-06 R10）：「人工放行」已废止**——ENUM「核销记录状态」条 明确「**系统不提供人工放行：核销要么成功、要么拒绝或失败，任何岗位、任何权限都不能以人工方式让一笔不满足规则的核销通过**」（DEC-CFG-2026-08-03-12 / DEC-R6-08）。本文原有的「人工放行」取值、端点、按钮、指标、权限点与复核类型**一律废止**，废止处就地标注「原含『人工放行』，已废止·见文首口径」；已实现的端点、权限点与状态取值待代码轮下线，期间不得新增调用、不得新写入。**注意**：合同或基础定义违规被卡住后「由更高级审核放行」的准入场景仍然存在，那是准入阻断的升级放行，与核销域无关，不得回读为「可以人工放行一笔核销」。

## 1. 文档定位

本文档把综合体管理系统 P0 范围从“模块任务”转换成“角色目标、业务旅程和可验收用户故事”。它用于迭代计划、开发任务拆分、测试用例设计和运营验收。

本文档不替代 PRD、接口契约、权限矩阵、事件矩阵和端到端验收文档；它负责回答：

1. 谁在使用系统。
2. 他们要完成什么业务结果。
3. 哪些故事组成 P0 最小运营闭环。
4. 每个故事如何验收。
5. 每个故事依赖哪些 P0 任务、接口和留痕。

## 1.1 版本分层收口（MVP / 第二期 / 未来版本）

2026-06-12 默认方案收口：本文的 P0 切片即 MVP，所有开发排期、验收和接口承诺必须先满足 MVP 闭环。第二期和未来版本只保留方向，不得反向挤占 MVP。

### 1.2 P0/P1/P2 边界补强

1. P0 客人端只承诺积分余额、会员等级和最近积分摘要；积分明细、礼物列表、兑换发起和兑换记录进入 P1。
2. P0 数据分析只承诺页面查看、核心指标和经营风险概览；CSV/Excel 导出和复杂排版报表进入 P1。
3. 售票型一体机进入 P0，必须支持售票、取票和查单；非售票型一体机不得展示售票入口。
4. 卡座免通票入场只限预定卡座所在酒吧和配置人数，不得抵扣最低消费。
5. 第三方真实供应商未确定时，P0 只做统一接口、mock adapter、字段映射占位、Webhook 和定时轮询校验。
6. 生产前置项未通过时，自有系统可继续开发和演示，但不得标记真实生产就绪。

## 5. 用户故事明细

### US-0001 后端骨架启动

作为后端开发，我希望创建正式 Java 21 + Spring Boot 4.x + Maven 工程，以便团队不再依赖旧 TypeScript/SQLite 原型。

验收标准：

Given 空白开发环境，  
When 启动后端服务，  
Then 健康检查接口返回正常。  

Given 开发者查看工程说明，  
When 其查找后端构建入口，  
Then 只能看到 Maven 作为 P0 后端主线。

Given BE-000 尚未通过验收，  
When 任一业务域开发任务准备进入“正式并行开发完成”状态，  
Then 任务必须被阻断，并提示先完成 Java/Spring/PostgreSQL/Flyway 工程准入。

关联：BE-000、BE-001、OPS-001、`prototype-deprecation-and-technology-baseline-v0.1.md`、`java-backend-platform-foundation-development-design.md`。

### US-0002 API 契约输出

作为前端、Android、一体机和第三方开发者，我希望有统一 API 契约，以便各端可以并行开发并减少接口扯皮。

验收标准：

Given P0 API Contract Pack 已发布，  
When 后端输出 OpenAPI，  
Then 路径、响应格式、错误码、幂等、Webhook 和权限事件映射必须与契约一致。  

Given 任一写接口被重复提交，  
When 幂等键相同，  
Then 系统返回第一次处理结果，不得重复产生业务影响。  

关联：BE-002、BE-003、`p0-api-contract-pack-v0.1.md`。

### US-0101 商户与空间建档

## 7. INVEST 检查

| 检查项 | P0 处理 |
|---|---|
| Independent 独立 | 每个故事按角色目标拆分，可单独排期和验收 |
| Negotiable 可协商 | 故事说明价值，接口和表结构由设计文档承接 |
| Valuable 有价值 | 每个故事对应真实经营、财务、合规或上线价值 |
| Estimable 可估算 | 每个故事关联 P0 任务编号和依赖 |
| Small 小颗粒 | 每个故事控制在一个业务结果内 |
| Testable 可测试 | 每个故事包含 Given/When/Then 验收标准 |
