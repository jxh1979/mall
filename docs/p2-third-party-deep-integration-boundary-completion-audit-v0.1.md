# P2-E 第三方深度联动边界完成审计 V0.1

## 1. 审计结论

P2-E 已完成边界收口，不进入厂商特定编码。当前系统已有通用供应商适配器、开放平台、Webhook、事件查询、重试、补偿和对账能力，足以承接后续机器人、视频、设备、人脸/年龄核验供应商资料到位后的正式接入。

## 2. 为什么不继续写厂商实现

- 供应商 API/SDK 未确定。
- 签名、回调、错误码、轮询限制、对账口径未确定。
- 人脸/年龄核验涉及采购和合规审查，不能用假接口替代。
- 硬编码某个厂商会破坏“双向开放 + 可替换供应商”的架构目标。

## 3. 已收口内容

| 项目 | 结论 |
| --- | --- |
| 统一 API 能力 | 使用现有开放平台和供应商适配器承接 |
| 签名和回调 | 走开放平台签名、Webhook、事件台账 |
| Webhook 与轮询 | 默认 Webhook + 定时轮询校验 |
| 机器人/视频/设备 | 作为 provider adapter 类型，不进入核心业务硬编码 |
| 人脸/年龄 | 仅保留 `face_age` 类型，正式启用依赖供应商和合规资料 |
| 密钥 | 只保存 `credential_ref`，不保存明文 |

## 4. 后续进入正式编码的触发条件

- 至少一个供应商确定。
- API/SDK、签名、Webhook、轮询、错误码、对账口径齐备。
- 沙箱账号可用。
- 合规和采购审批完成。
- 明确生产 credential_ref 和轮换责任人。

## 5. 当前状态

状态：边界完成；厂商特定实现暂缓。
