# 会员积分体系系统配置覆盖检查表 V0.1

日期：2026-08-01

状态：系统能力覆盖检查表，不是运行时配置真源

## 1. 文档定位

本文用于检查会员、积分和商户积分结算所需的系统配置是否完整承载。本文不得填写后直接驱动生产，不得作为线下运营参数表，也不得覆盖系统中已审批生效的版本。

现行业务规则只见：

- `docs/member-and-tier-product-prd-v1.0.md`
- `docs/points-and-voucher-product-prd-v1.0.md`
- `docs/merchant-points-settlement-rules-v1.0.md`

## 2. 使用规则

- 检查结果只允许记录“已覆盖、部分覆盖、未覆盖、不适用”。
- 参数值、审批、预算、生效时间和历史版本必须在对应系统页面维护。
- 本表不得保存商户私有业态积分率、项目外价格、人工补贴口径或绕过审批的临时值。
- 发现系统未覆盖时形成产品缺口，不得以线下表格代运行。

## 3. 系统配置覆盖项

| 编号 | 配置域 | 系统必须承载的对象 | 完整性与阻断检查 | 权威文档 |
|---|---|---|---|---|
| A | 业态积分获取 | 全国业态、每 1 积分所需消费金额、审批、生效时间、版本 | 商户必须绑定有效业态；项目和商户不可覆盖；缺失时积分能力不得启用 | 积分与虚拟券 PRD §6 |
| B | 成长值 | 平台基础规则、特殊通票或 SKU 固定成长值、活动倍率、期限、审批、版本 | 积分和成长值分别配置；无有效规则时不得互相推导 | 会员与等级 PRD §6 |
| C | 特殊积分 | 特殊通票或 SKU 固定积分、适用范围、审批、生效时间、版本 | 商户不得自行新增；无有效特殊规则时使用业态公式 | 积分与虚拟券 PRD §7.4 |
| D | 冻结与退款期 | 各业务退款期、履约完成条件、确认时点、原订单版本引用 | 冻结期内不可用；部分退款按保留有效消费和原版本重算 | 积分与虚拟券 PRD §8 |
| E | 积分有效期 | 账户活跃窗口、合格消费最低金额、通知、审批、生效时间、版本 | 默认窗口和默认最低金额来自权威 PRD；项目和商户不得降低平台门槛 | 积分与虚拟券 PRD §9 |
| F | 会员等级 | 六级名称、连续门槛、权益、积分倍率、审批、生效时间、版本 | 缺级、重叠、空档或无合同倍率上限时不得启用 | 会员与等级 PRD §7 至 §9 |
| G | 券种与兑换 | 券种、履约主体、资格、转赠开关、有效期、库存、兑换类型、版本 | 资格型券强制不可转赠；发券前校验积分、库存、预算和待追回积分 | 积分与虚拟券 PRD §10 至 §11 |
| H | 零售参考价 | 项目、SKU、滚动 30 天成交快照、新 SKU 首发公开价审批 | 只使用同项目同 SKU；不可直接手工覆盖；外部渠道排除 | 商户积分结算规则 §8 |
| I | 内部结算价 | 每项目独立管理页、SKU 目录、审批、生效时间、历史版本 | SKU 只能关联本项目价格；不得跨项目或在 SKU 重复录价 | 商户积分结算规则 §9 |
| J | 平台价格参数 | 全国积分发行单价、兑付系数、审批、生效时间、版本 | 商户不可使用不同单价；未配置兑付系数时使用权威默认值 | 商户积分结算规则 §10 |
| K | 兑换下限 | 纯积分双下限、积分加现金三项约束、价格与参数版本锁定 | 普通方案任一约束不满足不得发布 | 商户积分结算规则 §11 至 §12 |
| L | 特殊审批 | 原因、目标、期限、数量、缺口、申请人、审批人、成本承担方、预算 | 申请审批分离；预算不足禁止发券；结算中心不默认补贴 | 商户积分结算规则 §13 |
| M | 会员系统服务费 | 合同、比例或固定月费模式、费率或金额、生效期、版本 | 两种模式二选一；允许为 0 但仍需保存完整配置 | 商户积分结算规则 §7.2 |
| N | 营销活动成本 | 发起项目、发起平台法律主体、承担主体、预算、科目、分摊、期限、审批 | 比例合计 100%；固定额覆盖预算；各主体分别锁定预算 | 商户积分结算规则 §15 |
| O | 账单与冲正 | 总额应收应付、争议期、付款日、封账、冲正、原单和发票关联 | 不得只存净额；历史封账不可改；跨月在当期冲正 | 商户积分结算规则 §16 至 §18 |
| P | 储值边界 | 储值实际支付结果、充值事件、退款事件与原消费关联 | 储值支付可作为实际支付；充值本身不产生积分或成长值 | 储值 PRD §11；积分与虚拟券 PRD §6.2 |

## 4. 上线门禁

以下任一情况存在时，对应能力不得启用或继续发放：

- 商户没有有效业态或业态积分规则；
- 等级计划缺项、区间重叠或存在空档；
- 合同没有最高等级倍率或服务费模式；
- 兑换 SKU 没有本项目有效零售参考价依据或内部结算价；
- 兑换方案不满足价格下限且没有有效特殊审批；
- 库存、履约能力或预算不足；
- 营销成本承担主体不明确或分摊不守恒；
- 规则缺少审批、生效时间或版本；
- 系统只能依赖线下表格才能运行。

## 5. 审计记录

每次覆盖检查必须记录检查日期、系统环境、检查人、配置对象、系统页面或记录编号、结论和缺口单据。检查记录只能证明“系统是否覆盖”，不能成为参数本身。
