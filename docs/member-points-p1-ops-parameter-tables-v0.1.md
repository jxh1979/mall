# 会员积分体系系统配置覆盖检查表 V0.04

日期：2026-08-01

状态：系统能力覆盖检查表，不是运行时配置真源

## 1. 文档定位

本文用于检查会员、积分、商户积分结算、储值、连续签到和生日权益所需的系统配置是否完整承载。本文不得填写后直接驱动生产，不得作为线下运营参数表，也不得覆盖系统中已审批生效的版本。

现行业务规则只见：

- `docs/member-and-tier-product-prd-v1.0.md`
- `docs/points-and-voucher-product-prd-v1.0.md`
- `docs/merchant-points-settlement-rules-v1.0.md`
- `docs/member-loyalty-and-stored-value-product-prd-v0.1.md`
- `docs/stored-value-membership-checkin-birthday-prd-v0.1.md`

## 2. 使用规则

- 检查结果只允许记录“已覆盖、部分覆盖、未覆盖、不适用”。
- 参数值、审批、预算、生效时间和历史版本必须在对应系统页面维护。
- 本表不得保存商户私有业态积分率、项目外价格、人工补贴口径或绕过审批的临时值。
- 发现系统未覆盖时形成产品缺口，不得以线下表格代运行。

> 本段规则已归口至 `docs/scope-wide-coding-rule-canonical-V0.01.md` §B-18，本文不再重复记载。

## 3. 系统配置覆盖检查项

下表只列系统必须承载的配置对象，不填写运行时参数值。检查人员须在系统页面、配置记录、审批记录和版本记录中取证。

| 会员受限恢复时长 | 按项目配置的恢复时长具备上下限、审批、生效时间和版本，满时长自动恢复与客服主管提前解除均留痕 |  |  |
| 注销注册异常预警 | 同一手机号一年内注销与注册合计次数上限具备全平台配置、上下限、审批和版本；超限只触发预警、不自动阻断注册 |  |  |
| 六级会员等级 | 现行六级清单、各级名称、成长值门槛、封闭权益、积分倍率、上下限、审批、生效时间和版本均有系统承载；后台不能增删等级 |  |  |

| 积分有效期 | 滚动有效窗口与最低刷新金额同时具备上下限、审批和版本；缺配时阻断并告警 |  |  |

## 4. 检查结果填写模板

每一检查项只能填写“已覆盖、部分覆盖、未覆盖、不适用”之一；空白表示尚未执行检查，不构成覆盖结论。部分覆盖或未覆盖必须填写缺口单据，已覆盖必须填写可复核的系统页面或记录编号。

## 5. 审计记录

每次覆盖检查必须记录检查日期、系统环境、检查人、配置对象、系统页面或记录编号、结论和缺口单据。检查记录只能证明“系统是否覆盖”，不能成为参数本身。
