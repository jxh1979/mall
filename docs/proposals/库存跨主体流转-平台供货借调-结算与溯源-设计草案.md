# 设计草案：库存跨主体流转（平台供货 + 商户借调）+ 结算 + 溯源（待立项）

> 状态：草案，待业务拍板。缘由：2026-07-08 用户提出——增加"平台级供货公司（酒水/中央餐饮）"送货给商户 + 结算；商户 A 的酒可借调给商户 B + A-B 结算；均与溯源码打通。本方案合并原「立项方向 #2 + #3」（同一子系统）。

## 1. 主体建模（✅ 已拍板：新增组织层）

**决策（2026-07-08）：平台级供货公司作为"新增组织层"建模**（不走特殊商户捷径，走规范建模）。

组织层级现状（见 settlement-canonical）：平台 → 项目公司 → 管理公司 → 商户。
**新增"供货主体（supply_entity）"作为平台级实体**（酒水公司/中央餐饮公司），跨项目向各商户供货：
- 新建 **supply_entities 表**：id、name、type(liquor/central_kitchen/...)、level='platform'、status、结算账户信息、created_at。
- 供货主体拥有自己的**库存/仓库**（warehouses.owner_type 增加 'supply_entity'；或独立供货仓）。
- **溯源码归属**从"只挂商户 merchant_id"扩展为"挂主体（owner_type + owner_id）"，owner_type ∈ {merchant, supply_entity}。这需要把 bug#5 修的"登记选商户"泛化为"登记选归属主体"。
- **权限/角色**：供货主体有自己的操作角色（发货、对账），纳入现有 RBAC。

> 影响：比特殊商户方案改动大——涉及 溯源码归属列泛化（merchant_id → owner_type/owner_id）、库存 owner 泛化、新组织实体 + 角色。周期更长但更规范、边界更清晰（供货主体不是"商户"，不参与商户维度的经营统计/结算混淆）。

## 2. 业务模型 —— 两类流转单

| 流转类型 | 从 → 到 | 说明 | 结算方向 |
|---|---|---|---|
| **调拨（供货）** | 平台供货公司 → 商户 | 平台把货（带溯源码）送到需要的商户 | 商户按货款付平台供货公司 |
| **借调** | 商户 A → 商户 B | A 的货借/调给 B | B 按约定价付 A |

借调再分两种：**借**（约定归还，可计占用费）/ **调**（买断，按内部结算价）。

**溯源码全程跟随**：货物在主体间流转时，溯源码归属从 from 主体 → to 主体，支撑防调包 + 结算对账（每瓶酒从哪个主体流到哪个主体可查）。

## 3. 数据模型

- **流转单 inventory_transfer_order**：id、类型 transfer_type(supply/lending)、借调模式 lending_mode(borrow/purchase)、from 主体、to 主体、状态 status(created/shipped/received/settled/returned/cancelled)、created_by、created_at。
- **流转明细 inventory_transfer_line**：id、流转单、物料 item_id、数量、随货溯源码 trace_codes[]、结算单价 unit_price_cent、金额。
- **流转结算台账 inventory_transfer_settlement**：id、流转单、from/to 主体、金额、状态(pending/settled)、期。
- **溯源码归属变更 trace_code_ownership_history**：trace_code、from_merchant、to_merchant、流转单、变更时间。（溯源码 inventory_trace_codes 已有 merchant_id 归属列。）

## 4. 状态机

`建单 created` →（平台/A 发货）`发货 shipped` →（商户/B **扫溯源码收货**）`收货 received`（溯源码归属 from→to）→ `结算 settled`。
借（borrow）旁支：`received` →（归还）`returned`（反向流转 + 结算冲销）。

## 5. 结算口径

- **平台供货 → 商户**：按供货价结算，商户付平台供货公司。
- **商户 A → B 借调**：借（约定归还，可能计占用费）/ 调（买断，按内部结算价）。
- 挂靠现有内部结算体系（与通票结算、物业费同框架）。

## 6. 接口

- 平台/商户端：建调拨单/借调单、发货、**扫溯源码收货**（防调包核对）、结算。
- 溯源：收货扫码校验、归属变更。

## 7. 与现有系统衔接
- 复用 inventory_suppliers / warehouses / stock 体系；平台供货公司 = 特殊商户。
- 溯源码归属扩展（bug#5「登记选商户」已铺路）。
- 结算挂靠 settlement-canonical 体系。

## 8. 分期实施建议
- **P1**：平台供货 → 商户调拨单（建单→发货→扫码收货）+ 溯源码归属变更。
- **P2**：调拨结算台账（商户付平台供货）。
- **P3**：商户间借调（借/调两模式）+ A-B 结算 + 归还流程。
