## 1. 文档定位与范围

### 1.1 回答的问题

1. 消费如何变成消费积分与成长值？  
2. 积分如何冻结、解冻、过期与续期？  
3. 会员等级如何升、保、降？  
4. 积分如何兑换、如何禁止抵现？  
5. 商户如何承担发分成本、如何获得兑换补偿？  
6. 全国中心、城市子账、商户户如何分工？  
7. 退款时积分与等级如何回滚？

### 1.2 范围内

- 消费积分账本、成长值账本、会员等级  
- 发分规则引擎（业态/商户/SKU/活动/等级加赠）  
- 兑换目录与兑虚拟券  
- 积分清算接口（发行计费、兑换补偿、补贴、冲正、对账、退出）  
- 城市项目结算**统计**子账户  

### 1.3 范围外（本文不展开）

- 储值预付卡本金账户细则（见既有储值章节）  
- 持牌支付/统一收银立项（明确不并入积分中心默认能力）  
- 具体默认单价金额、等级门槛成长值表、业态默认发分表的**运营填数**（结构已定，数值可后配）  
- 代码实现与 OpenAPI 字段级设计（另出设计/契约）

### 1.4 非目标

- 不做城市专属积分币种  
- 不做整单积分抵现  
- 不做积分结算中心代收商户消费款  
- 不把活动加赠与等级加赠混成同一规则源

## 2. 核心概念

| 概念 | 定义 | 边界 |
|---|---|---|
| 消费积分 | 可用于兑换白名单权益的积分 | 会员端统一余额展示 |
| 成长值 | 仅用于等级计算 | 默认不套用消费积分有效期 |
| 冻结积分/冻结成长值 | 已入账但未可用/未计入有效成长 | 退货周期内 |
| 可用消费积分 | 可兑白名单目录 | 解冻后 |
| 有效成长值 | 已解冻、计入滚动 12 月窗口的成长值 | 等级只认有效成长值 |
| 等级加赠率 | 按会员等级配置的加赠比例 | 在基础分之上加赠；成本归商户 |
| 活动加赠 | 活动规则产生的额外积分 | 与等级加赠独立；成本归活动预算 |
| 发行单价 | 发分侧计费单价 | 与兑换结算价分设 |
| 兑换结算价 | 兑换承接侧补偿单价/商品结算约定 | 与发行单价可不相等 |
| 全国会员余额 | 消费者全国统一积分账户 | 独立会员余额 |
| 城市统计子账 | 城市/项目清算统计 | 非会员钱包 |
| 商户结算账户 | 按法人的积分 B2B 账户 | 合资酒吧不合并 |

## 3. 账户与账本架构

### 3.1 三层结构

1. **全国会员及积分结算中心**  
   - 全国会员账户、消费积分/成长值账本  
   - 规则配置、发行计费、兑换核销记账、跨城清算统计  
   - 等级、有效期、负债测算、商户月对账、风控  

2. **城市/项目结算统计子账户**（DEC-CITY-LEDGER-001）  
   - 统计：本城发行分、兑换承接、费用与补偿、净流入流出  
   - **不是**独立会员余额，**不是**城市专属积分  

3. **商户法人结算账户**  
   - 一法人一户；法人/股东/利润分配/收款主体不同必须分户  

### 3.2 会员可见性

- 会员只看到：**可用消费积分**（及可选：冻结中明细）  
- 不向会员拆分展示「基础分/等级加赠/活动加赠」为多套余额  
- 后台必须保留来源拆分：商户基础、等级加赠、活动加赠及费用承担方  

### 3.3 资金两分（DEC-CLEARING-SCOPE-001）

| 资金 | 路径 |
|---|---|
| 消费者消费款 | **直接进经营商户**，或持牌支付/分账；**积分中心不代收** |
| 积分相关资金 | 仅 B2B：发行费、服务费、活动费、兑换补偿、补贴、冲正、异常追偿、通票内部结算等 |

## 4. 发分：规则引擎

### 4.1 强制发分（DEC-MANDATORY-EARN-001）

纳入会员体系的在营商户必须：

- 接入会员识别  
- 按配置发放消费积分与成长值  
- 接受退款冲减与审计  
- 结清积分相关费用  
- **不得**私自关分或改比例  

不因此强制收兑或整单抵现。

### 4.2 计算顺序

对一笔已确认消费订单明细：

1. 匹配发分规则（见优先级）→ 计算 **商户基础消费积分**、**基础成长值**  
2. 按会员当前等级 **加赠率** → 计算 **等级加赠消费积分**（及若配置了成长值加赠则算成长值加赠；默认等级加赠仅作用于消费积分，除非规则显式配置成长值加赠）  
3. 匹配活动规则 → 计算 **活动加赠**（覆盖或叠加见配置）  
4. 取整：默认**向下取整**；应用单笔/日/月上限  
5. 写入账本：状态按 §5 冻结/即消规则  

### 4.3 等级加赠（DEC-TIER-MULT-001）

- 各等级后台可配加赠率（可为 0）  
- 在基础分之上加赠，**不**用等级倍率隐式改写商户基础单价  
- **活动加赠与等级加赠相互独立**  
- **成本**：基础分 + 等级加赠均由 **商户规则承担方** 承担；活动加赠由 **活动预算承担方** 承担  

### 4.4 规则优先级（默认）

同一订单命中多条时：

1. 指定商品规则  
2. 指定通票/SKU 规则  
3. 指定商户规则  
4. 指定活动规则  
5. 城市业态规则  
6. 全国业态默认规则  

活动相对基础规则必须标明：**叠加** 或 **覆盖**（默认建议叠加，可配）。

### 4.5 规则配置最小字段

规则名称、适用城市/项目/法人/商户/业态、发放方式（按金额/固定）、消费积分单位金额与单位分、成长值单位金额与单位成长值、固定分（通票）、取整、最低实付、单笔/日/月上限、是否延长有效期（消费积分）、到账/冻结策略覆盖、退款撤回方式、活动倍数与模式、费用承担方、等级加赠是否适用、生效/失效、审批状态。

## 5. 到账、冻结与解冻（DEC-EARN-EVENT-001）

### 5.1 默认路径

1. **消费确认入账时**计算消费积分与成长值  
2. 默认进入 **冻结**（消费积分冻结 + 成长值冻结）  
3. 该笔消费的 **退货/退款周期** 结束后 → **解冻**  
   - 消费积分 → 可用  
   - 成长值 → 有效成长值（进入等级滚动窗）  

### 5.2 即消例外

以下业态（白名单可配，默认含）：**酒吧、游乐设施**等即时消费、无退货周期的：

- 确认入账后 **立即到账可用**（不冻结）  

### 5.3 可配置

- 业态/商户/SKU 是否冻结、冻结时长（退货周期）  
- 即消白名单  
- 是否向会员展示“冻结中”明细  

### 5.4 等级计算

- 等级只统计 **有效成长值**（已解冻）  
- 冻结成长值不计入滚动 12 个月，直至解冻

## 6. 消费积分有效期（DEC-VALIDITY-001）

### 6.1 默认

- 连续 **12 个月**内至少一笔 **合格消费** → **全部未使用可用消费积分整池续期**  
- 结构：**整池续期**（不是仅延长被触摸批次）  

### 6.2 合格消费默认

- 实付达到最低门槛、且已确认入账的消费  
- 默认 **不** 因：纯赠分、签到、纯积分兑换 而续期（可配打开）  

### 6.3 可配置

- 续期窗口时长（默认 12 个月）  
- 合格消费定义/最低实付  
- 非消费行为是否续期  
- 成长值是否共用该有效期（默认 **否**）  

### 6.4 禁止

- 首期禁止“整池续期”与“分批各自过期且消费不续期”双轨并行  

---

## 7. 会员等级（DEC-TIER-LADDER-001）

### 7.1 档位

六档（名称可本地化，序位固定）：

1. 新乐会员  
2. 银卡  
3. 金卡  
4. 白金  
5. 钻石  
6. 黑钻  

门槛以 **滚动 12 个月有效成长值** 配置（数值可后配）。

### 7.2 升级

- 达到更高等级门槛 → **立即升级**  

### 7.3 保级与降级（STRICT）

- 等级周期到期时按近 12 个月有效成长值重算  
- 达当前或更高：保级或升级  
- **未达当前：一次降至实际满足的等级，允许跨多级下降**  

### 7.4 与倍率

- 不做“等级倍率改写商户基础单价”  
- 仅通过 §4.3 等级加赠率加分  

---

## 8. 兑换与禁止抵现

### 8.1 禁止整单抵现（DEC-NO-OFFSET-001）

- **禁止**结账时用积分当现金抵扣整单或任意应付金额  
- 系统必须拒绝该类支付组合  

### 8.2 允许的兑换

- 仅兑换 **后台白名单兑换目录** 内的：虚拟券、指定商品、套餐、权益  
- 积分只兑虚拟券/目录项，不直接兑未入目录的任意实物（与现行券模型对齐处保留）  

### 8.3 兑换时点与承接（POINTS-VOUCHER-ACCRUAL-001）

- **不采用**“兑换后先冻结，到店核销履约后才计商户承接积分”  
- **兑换成功时点**：  
  1. 扣减消费者可用消费积分  
  2. 按规则记录商户/成本主体的承接或成本  
  3. 券核销只消耗券权益，**不再作为承接入账开关**  
- 券过期/作废/退回：走券生命周期冲回/调账，不得用长期冻结承接代替冲回  

### 8.4 库存

- 实物/服务类券：发券时库存预占等规则沿用既有券模型；与积分扣减事务一致，失败则整笔回滚  

---

## 9. 退款与冲减（DEC-REFUND-POINTS-001）

### 9.1 R-SYM 对称冲减

退款时按退款比例（全额退则全额）：

1. 冲回该笔对应的 **消费积分** 与 **成长值**  
2. **冻结期**：优先扣冻结额度，作废或按比例扣减，**禁止**解冻后再追  
3. **已解冻**：从可用消费积分扣回；可用不足默认扣至 0 并记异常待处理（可配更严策略）  
4. 成长值冲减后按有效成长值 **重算等级**  
5. 即消业态（已立即到账）从可用扣回  
6. 等级加赠、活动加赠按来源批次/比例冲回，费用承担方对账同步  

### 9.2 与支付退款

- 积分冲减与支付退款同一业务闭环触发  
- 不得出现“款已退、分仍可兑且成长值仍撑等级”的默认可成功路径

## 10. 积分清算接口

### 10.1 双价（DEC-POINTS-PRICE-001）

| 价格 | 含义 | 承担/去向 |
|---|---|---|
| 发行单价 | 发分计费 | 发分承担方（通常商户）付给结算中心 |
| 兑换结算价 | 兑换补偿 | 结算中心付给承接商户（或按商品约定） |

- 两价 **分设、可不相等**  
- 差额 → 补贴/毛利/调节科目  
- 可按业态/商户/活动/城市配置，含生效区间与审批  
- **默认金额可后配**，但系统必须实现双价，禁止唯一全球隐式单价  

### 10.2 结算中心处理的资金类型

- 积分发行费  
- 会员系统服务费（若收取）  
- 活动加赠费  
- 积分兑换补偿  
- 平台/城市活动补贴  
- 退款与冲正  
- 异常追偿  
- 通票等内部服务结算  

### 10.3 商户义务与退出

- 强制发分见 §4.1  
- 退出必须结清：发行费欠款、兑换补偿、争议单  
- 未结清可阻断退出/续约（与合同条款对齐）  

### 10.4 对账

- 周期：默认自然月（可配）  
- 输出：发行分、承接分、费用、补偿、补贴、冲正、净额  
- 城市统计子账与商户户、全国中心三方可勾稽  

### 10.5 守恒式（接口验收）

```
会员可用积分变动 = 解冻入可用 + 活动/调整入可用 - 兑换 - 过期 - 退款扣回 ± 调账
商户应付发行费 ≈ Σ(发出基础分+等级加赠分)×发行单价（按承担方规则）
结算中心应付兑换补偿 ≈ 按兑换结算价或商品约定
城市净流 = 本城发行成本相关 - 本城承接补偿相关 ± 补贴
```

## 11. 与储值、票务、酒吧的边界

| 域 | 关系 |
|---|---|
| 储值 | 储值本金/赠金独立；积分不抵现；储值消费可作为合格消费与发分来源 |
| 票务 | 通票/SKU 可固定发分；核销类规则可覆盖到账/冻结策略 |
| 酒吧 | 默认即消立即到账；退酒/退款走 R-SYM；高价值退酒另见 BAR-VOID-A1 |
| 游乐 | 默认即消立即到账 |

## 12. 权限与审计（最小集）

- 规则配置：查看/维护分离；高危变更审批  
- 调账、手工加减分：双人/审批 + 全留痕  
- 商户对账导出：敏感字段按权限  
- 所有积分/成长值变动：不可物理删除，只能冲正  

---

## 13. 验收要点（G/W/T 粗口径）

1. 一笔非即消消费：确认后积分与成长值冻结，周期后解冻，等级只认解冻成长值。  
2. 酒吧消费：确认后立即可用。  
3. 退款在冻结期：冻结额消失，无可用增加。  
4. 退款在解冻后：可用与成长值对称扣，等级下降可跨级（若成长值不足）。  
5. 高等级加赠率 > 0：基础分 + 等级加赠均记商户成本；活动加赠记活动预算。  
6. 结账尝试积分抵现：被拒绝。  
7. 兑换白名单券：扣可用积分，兑换时点记承接；不过核销才首次承接。  
8. 会员只有全国余额；后台可见城市统计子账，无城市专属积分余额。  
9. 结算中心流水无“代收商户消费款”默认科目。  
10. 双价可配且可不相等。

## 18. 本版结论

本 PRD 将会员积分与升级从“多源叙述 + 部分未决”收束为可验收的双账本、冻结解冻、STRICT 六档等级、强制发分、禁止抵现、兑换即承接、双价清算与三层账户（全国会员余额 + 城市统计子账 + 商户户）模型。数值类参数允许后配，但结构决策以 §14 为准，实现不得回退为整单抵现、中心代收消费款、核销才首次承接、或等级隐式改写商户基础单价。
