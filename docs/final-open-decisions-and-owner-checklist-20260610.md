# 最终已确认执行口径与责任人清单 V0.2

> 文档状态：本轮全量文档收口后的总控清单。  
> 结论：产品方向、P0/P1/P2 边界、主要技术路线、票务/酒吧/游乐/治理/财务/第三方/运维默认方案均已按总控口径收口。本文所有事项均按“推荐默认”执行，不再作为开放产品问题；涉及法令强制、供应商真实资料、采购参数和实施账号的内容，作为上线配置或外部输入处理。
>
> 最新总控口径（2026-06-10）：1）总控事项全部按推荐默认执行；2）实名范围仅在国家法令强制要求的场景启用，除此之外不强制实名；财务、HR/法务模板和留存策略按本文推荐默认执行；3）采购/IT 选型按推荐默认执行；4）供应商资料到位后按推荐默认对接策略执行；5）实施前配置按推荐默认执行。

## 6. 已收口且无需再次确认的关键事项

| 事项 | 当前口径 |
|---|---|
| 票务价格策略 | P0 以平日/周末/节假日基础价为最高优先级，多人/新人/学生/渠道价基于基础价生成或固定价覆盖，动态定价 P2 |
| 通票赠酒成本 | 平台承担，字段保留成本归属 |

| P0 权限模板 | 支持基础模板、临时模板、复制模板、有效期、单次有效、撤销和审计；显式拒绝优先级最高 |
| P0 币种 | CNY 单币种，金额整数分；保留 currency 默认 CNY，多币种和汇率 P2 |
| 第三方供应商未确定 | 只写统一接口、适配器、字段映射占位、Webhook+轮询校验、对账和补偿；真实字段等供应商资料到位后补 |
| 酒吧人脸年龄核验 | 正式生产必须接入第三方人脸/年龄核验接口或等效设备；未采购完成前只能测试模拟 |
| 合同日期颗粒度 | 方案 B，标准通用事项台账 + 本地 AI 辅助判断 + 人工确认 |
| 合同审批 | P0 做录入、确认、生效、附件归档和待办；复杂多级审批 P1 |
| Android 离线 | P0 不做离线核销；P1 可离线查看策略摘要；高价值酒水核销保持在线 |
| AI 服务 | P0 Java 内置规则处理器；P2 再引入独立 Python AI 服务 |
| 160 服务器 | P0 预生产/演示，允许脚本，但必须 dry-run、备份、Runbook、可回滚 |
