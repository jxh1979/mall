## 0. 触摸屏一体机（边界块：仅"和谁有关"）

### K-01 一体机对外连接关系（和谁有关）
- 模块：触摸屏一体机
- 功能名称：一体机与各子系统的连接口径
- 页面：无独立页面（口径说明块）
- 用户流程：一体机产生的售票/订台/买酒/权益领取/状态检查动作 → 分别落到票务、酒吧、游乐、支付财务、留痕子系统
- 页面元素：`和谁有关` 无序列表 6 条
- 交互：无（说明性）
- 输入：一体机设备点位、员工权限、下单/领取/检查动作
- 输出：可售票种过滤结果；酒吧订单/账单/最低消费/定金/支付流水；权益状态回写；游乐状态检查、定期检修与主管确认记录；日结/对账/经营看板数据；含设备、点位、时间的留痕
- 状态：—
- 权限：售票一体机"按设备点位和员工权限过滤可售票种"
- 异常：一体机的异常提示需记录设备、点位、时间
- 依赖：票务权益、酒吧管理、游乐管理、支付与财务、留痕与异常
- 证据位置：`L943 · 连接票务权益（售票一体机按设备点位和员工权限过滤可售票种）`；`L944 · 连接酒吧管理（订台和吧台买酒进订单/账单/最低消费/定金/支付流水）`；`L945 · 连接票务权益（扫码展示可领权益、领取确认后回写）`；`L946 · 连接游乐管理（开放状态/容量/异常与状态检查、定期检修、主管确认记录）`；`L947 · 连接支付和财务（订单必须进日结、对账和经营看板）`；`L948 · 连接留痕与异常（记录设备、点位和时间）`

## 1. 酒吧管理（section#bar，L954–L1029）

章节导语（L956）：酒吧管理先做基础经营闭环；平板端服务员协助点酒；一体机可支持订台、吧台买酒和支付引导；吧台酒水按杯/瓶/套餐或其他形式售卖；门票主路径为客人自助购买（官方 App/小程序或第三方渠道），少量到店场景由授权服务人员在该酒吧前台售票一体机辅助购买**本店单店门票**。

### BAR-01 酒吧商户引进与归属
- 模块：酒吧管理
- 功能名称：酒吧门店＝业态为"酒吧"的商户，经招商租赁→合同→商户准入引进
- 页面：商户档案/准入页；各业务页的"所属酒吧"下拉
- 用户流程：招商租赁 → 合同 → 商户准入 → 该商户业态＝酒吧 → 桌台/商品/分类/套餐归属到该酒吧商户
- 页面元素：所属酒吧下拉选择器（不可手工输入）、合作方式字段
- 交互：下拉选择所属酒吧；无独立"新建酒吧"入口
- 输入：商户档案、合同、合作方式（自营/联营/租赁/代运营/服务商接入/其他）
- 输出：可被桌台、商品、分类、套餐引用的酒吧商户主数据
- 状态：商户准入状态（由招商租赁与合同链决定）
- 权限：招商/合同/准入岗位
- 异常：不得凭空「新建酒吧」；不再手工输入所属酒吧
- 依赖：招商租赁与合同履约、基础管理（商户身份/合同/经营范围）
- 证据位置：`L961 · 酒吧门店就是一个业态为"酒吧"的商户`

### BAR-02 入场资格识别
- 模块：酒吧管理
- 功能名称：识别客人是否有酒吧入场资格
- 页面：门口/前台核销端（工作手机、一体机）
- 用户流程：客人到店 → 出示入场凭证 → 系统识别资格 → 放行或拒绝
- 页面元素：核销结果提示
- 交互：扫码核销
- 输入：门票/通票/邀请函对应的入场权益
- 输出：入场资格判定结果
- 状态：有资格 / 无资格
- 权限：现场核销员工
- 异常：无资格拒绝入场
- 依赖：票务权益
- 证据位置：`L962 · 识别客人是否有酒吧入场资格`

### BAR-03 前台补票限本店单店门票
- 模块：酒吧管理
- 功能名称：门口/前台补票只售本酒吧单店门票
- 页面：启用售票能力的一体机售票页
- 用户流程：客人到店补票 → 授权服务人员登录一体机 → 只显示本店单店票种 → 售出
- 页面元素：可售票种列表（按设备点位与员工权限过滤）
- 交互：员工登录后代客选票、下单、支付引导
- 输入：设备点位、员工权限、票种
- 输出：本店单店门票订单
- 状态：—
- 权限：仅"授权服务人员"、仅"启用售票能力"的一体机
- 异常：**不能售卖综合体通票**
- 依赖：触摸屏一体机、票务权益
- 证据位置：`L963 · 客人在本酒吧门口或前台补票时（只能售卖本酒吧单店门票）`

### BAR-04 台位管理与台位状态
- 模块：酒吧管理
- 功能名称：桌台/卡座/吧台位状态管理
- 页面：桌台平面图/台位管理页
- 用户流程：开台 → 服务 → 结账 → 待清台 → 清台登记 → 空闲
- 页面元素：台位卡片/平面图、状态标识
- 交互：点选台位、开台、清台登记
- 输入：台位主数据、服务动作
- 输出：台位实时状态
- 状态：**空闲、已预留、已开台、待清台、停用、异常**（六态）
- 权限：现场服务/管理岗
- 异常：异常态台位需处理
- 依赖：基础管理（酒吧区域、桌台、商户归属）
- 证据位置：`L964 · 管理不同酒吧、桌台、卡座、吧台位的空闲、开台、待清台和异常状态`；`L1002 · 台位状态`

### BAR-05 开台记录与低消归集
- 模块：酒吧管理
- 功能名称：记录卡座位置、服务员、人数、点酒明细、最低消费、账单状态
- 页面：开台/账单详情页
- 用户流程：开台登记 → 点酒累计 → 低消判定 → 结账
- 页面元素：卡座位置、服务员、人数、点酒明细列表、最低消费、账单状态
- 交互：录入人数、指派服务员
- 输入：卡座、服务员、人数、点酒明细
- 输出：账单记录
- 状态：账单状态（见 BAR-21）
- 权限：现场服务岗
- 异常：**人数不参与最低消费计算**
- 依赖：最低消费配置
- 证据位置：`L965 · 记录卡座位置、服务员、人数、点酒明细、最低消费和账单状态`

### BAR-06 订台订单接收与来源记录
- 模块：酒吧管理
- 功能名称：接收多渠道订台订单并记录来源与结果
- 页面：订台管理页
- 用户流程：官方 App/小程序/一体机/销售人员发起订台 → 进入酒吧订台列表 → 到店或取消 → 结果回写
- 页面元素：订台列表、来源字段、定金字段、到店/取消结果
- 交互：接单、标记到店、取消
- 输入：订台来源、销售人员或设备来源、定金
- 输出：订台订单、到店/取消结果
- 状态：到店 / 取消
- 权限：酒吧现场与管理岗
- 异常：—
- 依赖：客人 App/小程序、一体机、员工端
- 证据位置：`L966 · 接收官方 App、小程序、触摸屏一体机和销售人员产生的订台订单`；`L967 · 订台订单必须记录定金、订台来源、销售人员或设备来源、到店和取消结果`

### BAR-07 一体机吧台买酒订单接收

- 功能名称：接收一体机产生的吧台买酒订单
- 页面：酒吧订单页

- 页面元素：订单列表
- 交互：接单
- 输入：一体机订单（酒水/套餐/数量）
- 输出：酒吧订单与账单
- 状态：待支付 → 已支付
- 权限：—
- 异常：—
- 依赖：触摸屏一体机
- 证据位置：`L968 · 接收一体机产生的吧台买酒订单`

### BAR-08 客人扫码点单（仅散台）
- 模块：酒吧管理
- 功能名称：散台扫码自助点单，先付款后出品
- 页面：客人手机点单页（扫桌台二维码进入）、桌台账单页
- 用户流程：扫桌台二维码 → 自助点单 → 即时付款 → 付款成功订单才成立 → 计入该桌位当前账单 → 出品上台 → 客人离开 → 服务员清理散台并在系统登记为可接待新客人 → 新客人看到空账单
- 页面元素：桌台二维码、商品列表、账单逐项明细（物品名称＋价格）、**已上菜/未上菜**标注
- 交互：扫码、下单、付款、追单；服务员清台登记
- 输入：桌台二维码、商品与数量、支付
- 输出：已付款订单、桌台账单、服务归属归集、低消累计
- 状态：已上菜 / 未上菜；桌台：占用 → 待清台 → 可接待
- 权限：**卡座不开放扫码点单**；清台责任由服务员承担（卡座清台责任同样在服务员；每周排班须轮换：卡座与散台之间轮换、卡座与卡座之间也轮换）
- 异常：**未付款不出品、不挂账**；新客人看不到上一位客人的消费
- 依赖：入场年龄核验（点单继承入场核验结论，不再重复验龄）、账单与低消
- 证据位置：`L969 · 支持客人扫码点单：扫码点单只适用于散台，卡座不开放扫码点单`

### BAR-09 吧台售卖形式与按杯扣减
- 模块：酒吧管理
- 功能名称：按杯/按瓶/按套餐或其他形式售卖，按标准出酒量扣库存
- 页面：吧台点单页、库存流水
- 用户流程：选择售卖形式 → 出品 → 扣减库存 → 超出标准部分记损耗
- 页面元素：售卖形式选择、出酒量采集读数
- 交互：出品；配采集设备的吧台由设备采集实际出酒量
- 输入：标准出酒量、实际出酒量（设备采集）
- 输出：库存扣减、损耗记录
- 状态：—
- 权限：吧台岗
- 异常：**配有出酒量采集设备的吧台，实际出酒量必须由设备采集**；**未配备采集设备的必须按标准出酒量配酒，也按该标准计算扣减与标准损耗，不得按零损耗记账**
- 依赖：供应链库存
- 证据位置：`L970 · 支持吧台酒水按杯、按瓶、按套餐或其他形式售卖`；`L1009 · 点酒方式`

### BAR-11 支付方式与线下支付入账
- 模块：酒吧管理

- 页面：收银/支付页
- 用户流程：优先线上（客人手机扫平板二维码 或 平板扫客人手机付款码）→ 现场可用现金/POS → 全部进账单、日结、员工责任链、财务对账

- 状态：待结/部分支付/已结（见 BAR-21）

- 异常：现场支付**必须**进入账单、日结、员工责任链和财务对账
- 依赖：财务对账、聚合支付
- 证据位置：`L972 · 支付优先使用线上支付`；`L973 · 现场必须允许现金和 POS 机支付`；`L1010 · 支付方式`

### BAR-12 票务赠饮权益核销

- 状态：未核销 / 已核销

- 异常：核销失败/拒绝/撤销进入留痕

### BAR-13 核销顺序规则（先入场后酒水，一店一份）
- 模块：酒吧管理
- 功能名称：入场权益优先于酒水权益的强制核销顺序
- 页面：核销端
- 用户流程：同一酒吧商户 → 先核销这家酒吧的入场权益 → 才能核销这家酒吧的酒水（赠饮）权益
- 页面元素：核销校验提示
- 交互：扫码核销
- 输入：入场权益状态、酒水权益
- 输出：核销结果
- 状态：入场已核销 / 未核销
- 权限：—
- 异常：**没先核入场就来核酒水的，系统一律拒绝**
- 依赖：票务权益——一张通票覆盖几家酒吧就为每家各发一份独立入场权益与赠酒权益，一家一份、互不占用；在 A 店核销入场不影响在 B、C 店另行核销
- 特殊规则：**客人进入任何一家酒吧都必须核销入场**（不论资格来自邀请函、通票还是单张门票），**不存在免核销入场的情形**
- 证据位置：`L975 · 核销顺序`

### BAR-14 通票赠酒按酒吧分配与最低杯数
- 模块：酒吧管理
- 功能名称：通票覆盖的每个酒吧赠酒杯数下限与票面写明
- 页面：票种发布/配置页
- 用户流程：配置票种 → 逐店写明赠几杯 → 校验是否达最低赠酒杯数 → 发布上架
- 页面元素：逐店赠酒杯数字段、票面说明
- 交互：配置与发布校验

- 权限：反结与沽清均需主管审批留痕；免单**仅三种情形**——(一)本人当月赠送额度以内的管理岗位赠送，可赠至全额免单；(二)重大责任事故或客人在店内受伤、遭受严重骚扰，须**店长、夜班值班经理与娱乐平台公司负责人三方批准**；(三)客人出现重大情绪不稳定、安全问题或其他必要问题，由**夜班值班经理及以上**免除其通票费用（即退票）。现场打折由店长、主理人、营销负责人、夜班值班经理、娱乐平台公司负责人、项目负责人及更高层级当场给予
- 异常：**除三种情形外不得免单**；打折两个来源（活动获得或积分兑换取得的代金券/打折券按券面规则执行；现场打折）；含代金券与打折券在内一律不得低于折扣下限；**只有额度赠送不受此限**（消耗的是本人额度）
- 适用边界：下限只适用于**卡座与散台的现场消费折扣**（含客人持有的代金券与打折券）；票种定价的折扣构成、会员价、渠道价、动态价的派生均不受此限（通票须先购买才能入场，现场无从赠送或打折）
- 报送对象：店内报送该店主理人与店长；各公司报送该公司最高负责人与平台最高负责人
- 依赖：赠送额度、留痕与异常
- 证据位置：`L1013 · 高危动作`

### BAR-27 销售提成
- 模块：酒吧管理
- 功能名称：销售提成计提、费率版本与退款冲回
- 页面：提成配置页、提成明细、薪资单
- 用户流程：下单时锁定当时费率版本 → 按开台/下单时点所属营业日归属月份 → 月结计算 → 随薪资发放；退款时按订单最终保留收入重算并冲回差额
- 页面元素：费率配置、销售岗标识、提成明细、反向结算记录
- 交互：配置费率并指定生效日期；月结
- 输入：费率（**业务参数，按酒吧可配，出厂默认销售 15%、非销售 10%；配置权归该酒吧主理人，与娱乐平台公司协商决定**）；薪资发放日（**业务参数，按项目可配，须同时配置上下限，不得迟于次月 15 日**）
- 输出：提成金额、反向结算记录
- 状态：已锁定费率版本 / 已月结 / 已冲回
- 权限：主理人配置费率；员工是否为销售岗在员工档案维护，**不按单次是否指派销售人员临时判断**
- 归属规则：一张账单提成**只计一次、只归帮该客人预订的那个人**；**自来客不产生销售提成**；协助服务、加单、送达等其他经手人只留责任痕迹、不产生提成；销售人员可跨酒吧承接订单，一律按**该笔订单实际发生的那家酒吧**配置的费率计提，不按员工档案归属酒吧
- 不计提成项：通票及票务权益整类（不论其中权益是收费还是免费、由谁出资）、卡座入场名额、赠送成本、退款、免单
- 异常：费率变更形成新版本并指定生效日期，只对生效日之后发生的单据有效；重新月结只重算金额、**不改已锁定的费率版本**；提成归属月份以开台或下单时点所属营业日为准，不受发放日影响
- 冲回口径：属于付给酒吧的收入部分，酒吧按实退金额全额退回、提成按最终保留收入重算冲回差额；属于服务费、小费与表演报酬的部分，因退款均发生在发放之前，一律按最终保留收入重算冲回差额、**不由酒吧承担**；所有冲回生成反向结算记录，**不覆盖原归属、原计算与原结算记录**
- 依赖：财务对账、员工薪资
- 证据位置：`L1014 · 销售提成`

### BAR-28 取酒与人工例外
- 模块：酒吧管理
- 功能名称：取酒核验与人工例外放酒四项前置
- 页面：取酒核验页、人工例外申请页、客人查询专门通道
- 用户流程：核验当前客户短信验证码，或由已登录的官方手机应用/小程序出示动态取酒码 → 核对标签 → 记录取用前后剩余量、操作员工与时间 → 留痕；例外情形走四项前置
- 页面元素：手机号检索框（**只能输入手机号**）、验证码、动态取酒码、标签、取用前后剩余量、操作员工、时间
- 交互：核验、检索、发起例外申请、复核
- 输入：消费历史条件（**安全阈值，按项目可配，调整须最高权限审批并留痕，出厂默认：近 1 个月内至少 2 笔、近 3 个月内至少 3 笔、或历史累计至少 5 笔有效卡座消费订单；有效＝已支付且未全额退款**）
- 输出：取酒记录、例外审批记录、查询留痕（谁查的、查的哪个手机号、什么时间、为哪一笔取酒申请）

- 权限：例外须**同时满足四项**——①由店长发起并经另一名主管复核，普通员工不得单独放酒；②申请手机号满足消费历史条件，且该查询须走**客人查询专门通道**、由发起该例外的店长本人鉴权、界面只显示脱敏信息、并留痕；③由该客户对应的营销人员确认身份与取酒申请（营销已离职由其主管确认，历史订单无归属营销由存酒所在酒吧当班营销主管确认）；④**只允许存酒客户本人到场办理，不允许他人代领**
- 异常：**姓名与昵称不得用于检索；手机号也不得单独作为放酒凭证**；**找不到可承担确认责任的营销主管时流程不得通过**；客户需他人取酒必须先恢复短信或官方手机应用/小程序验证能力，再走正常的存酒转让流程变更客户
- 适用边界：人工例外**仅在客户手机遗失、停机等无法获取验证码或动态取酒码时适用**
- 依赖：供应链库存（客人存酒）、短信平台、客人查询通道

### BAR-29 年龄核验

### BAR-30 服务费

- 功能名称：非散台服务费收取、发放与归属判定

- 用户流程：按每笔账单金额固定比例收取 → 商户代收 → 按后台选定分配方式发放给当班服务提供人 → 月结随薪资发放并代扣个人所得税

### BAR-32 拆单/合单/转台/并台/拆台/撤销转台/循环转台
- 模块：酒吧管理
- 功能名称：账单操作族与低消、提成、小费归属规则
- 页面：账单操作页
- 用户流程：拆单（未支付未结算账单按金额拆出子账单，客人分开付）/ 合单并台（把同一酒吧另一张未付账单并入主账单）/ 转台 / 拆台 / 撤销转台
- 页面元素：拆分金额、目标账单、操作记录、原因、发起人
- 交互：拆、合、转、并、拆台、撤销转台
- 输入：循环转台次数上限（**业务参数，按酒吧可配，出厂默认 10 次，须同时配置上下限**）
- 输出：子账单/主账单、低消进度结转、每次操作记录
- 状态：—
- 权限：拆台由授权岗位操作；达转台上限后须**主管审批**才能继续转台
- 规则明细：
  - 拆单：同一台位拆出的全部子账单在最低消费判定上**仍视为一张账单合并计算**；销售提成与小费始终归主账单的相关责任人，**不随拆单分散**
  - 转台：原台已消费金额与低消进度一并结转到新台，按新台适用的最低消费重新匹配（多的不退、少的要补足）；**销售提成跟客人走**（由帮该客人预订的人取得，与台位无关；自来客不产生提成）；**小费跟实际提供服务的人走**，转台后由新台服务提供人取得，同一服务提供人同时照看两个台位时不变
  - 并台：两张台位的最低消费**加总为一个门槛合并计算**；销售提成归属不变仍跟各自客人走；小费按各自台位实际服务提供人**分别记、不合并**
  - 拆台：拆台后最低消费与消费进度按实际消费分别归属各台，各台各自适用自身的最低消费
  - 撤销转台：**按原路回退到转台前的台位与进度并留痕，不得以新建单据代替回退**
- 异常：**平台不提供续卡、续时类产品**；每次拆合都留操作记录、原因和发起人
- 依赖：最低消费、销售提成、小费
- 证据位置：`L1022 · 拆单 / 合单`；裁决注释 `L1021 · DEC-R6-19（补拆台／撤销转台／循环转台三条规则）`

## 2. 服务点单（section#service-order，L1031–L1061）

授权注释（L1031）：2026-07-03 回写服务点单(点舞)业务口径；含用户纠偏「公司收的钱全额入账，分出部分按薪资/提成/成本名录列支」。
章节导语（L1034）：客人在酒吧可点专项服务（比如点舞）。所有服务费由公司统一收款、全额进公司账，**不存在钱不进账的情况**；分给服务人员的部分是入账之后按薪资/提成/成本名录列支的支出。

### SO-01 服务目录维护
- 模块：服务点单
- 功能名称：后台维护服务目录（价格、时长、上下架、管理费）
- 页面：服务目录配置页
- 用户流程：新建服务项 → 定固定价格与时长 → 配管理费方式 → 上架/下架
- 页面元素：价格、时长、上下架开关、管理费方式选择
- 交互：新增、编辑、上下架
- 输入：固定价格、时长；管理费方式（**不收 / 按比例 / 固定金额**）
- 输出：可下单的服务项
- 状态：上架 / 下架
- 权限：后台配置岗
- 异常：—
- 依赖：财务分账
- 证据位置：`L1039 · 后台维护服务目录`

### SO-02 角色定义：点单员与服务提供人

- 功能名称：点单员与服务提供人角色分离
- 页面：下单页
- 用户流程：点单员帮客人下单 → 下单时指定由哪位服务提供人履约
- 页面元素：服务提供人指定字段
- 交互：下单时选择服务提供人
- 输入：服务提供人
- 输出：带履约人的服务单
- 状态：—
- 权限：点单员＝帮客人下单、向客人出示收款码、确认收款并点完成履约的**酒吧现场服务员**；服务提供人＝被点到、实际提供专项服务并参与分账的人员
- 异常：**两者是不同的人，后文不得混称**
- 依赖：员工档案
- 证据位置：`L1040 · 本章的「点单员」指…「服务提供人」指…`

### SO-05 到账自动确认与完成履约门槛

### SUP-14 跨主体流转（平台供货 / 商户借调）
- 模块：供应链库存
- 功能名称：货物在经营主体之间流转的所有权、保管责任与结算
- 页面：调拨/借调页、溯源码详情
- 用户流程：平台级供货主体（酒水公司、中央餐饮）向商户送货（调拨）→ 商户按货款与供货主体结算；商户之间借调 → 按内部结算价结算
- 页面元素：溯源码（记录所有权主体、当前保管主体、借出主体、借入主体、应归还数量和期限）、三个时间字段
- 交互：扫码交接、买断变更归属、收货扫码核对防调包
- 输入：借出/交接/归还扫码事件
- 输出：**三个时间**——借出时间（借出方交货扫码时刻）、每一次保管人变更时间（每次交接扫码时刻，交接几次记几条、全部保留）、实际归还时间（借出方收货扫码时刻）；**均由已有扫码动作自动生成，不设手工填写**
- 状态：借出中 / 已归还 / 已买断
- 权限：跨商户结算一律按内部结算价，**不得另行约定低于内部结算价的价格**
- 借与调的区别：**「借」只转移保管责任、不转移所有权**（借出方始终是所有权人，借入方承担临时保管与使用责任）；**「调」是买断**，成交时所有权转移给接收方
- 可消费物品（酒水、小食等）：借用实质是按内部结算价调用，**交付即按内部结算价出账结算**
- 不可消费物品（设备、器具等）：借用必须约定归还时间，借用期间保管人变更为借入方并在溯源码上登记；**超时未归还系统自动生成一张工单并通知借出方主管**，按与其他工单相同的超时升级路径继续催办，直到归还或双方另行处理；**不强制借入方买断，所有权仍在借出方**
- 异常：酒水与可追责物品的交接每一步都必须扫码（库管出库、后厨接收、服务员取走、送达客人或卡座），**缺任何一步即视为该环节工作未完成、不得进入下一环节**；扫码缺失**可事后人工补录**，但一律须附证据（照片、录音、录像等）并经主管复核后方生效，**补录记录与原始扫码记录并列展示、互不覆盖**
- 依赖：物业工单（超时催办）、财务对账（跨主体流转结算）
- 证据位置：`L1113 · 跨主体流转`；授权注释 `L1111 · 2026-07-08 新增库存跨主体流转`、`L1112 · DEC-R6-09 删补录禁令`

- 模块：游乐管理
- 功能名称：关键安全设备与辅助设备的停机范围规则
- 页面：设备台账、停机判定页
- 用户流程：每台设备按各自安全检查周期巡检 → 巡检超期/不合格/故障 → 按类别处置
- 页面元素：设备台账（登记是否依赖）、判定留痕（谁判的、什么时间、依据哪几项条件）
- 交互：登记、判定、审批
- 输入：设备类别与依赖关系登记
- 输出：停机范围结论
- 状态：设备停用 / 项目继续运行 / 项目停止新增核销并停运
- 权限：辅助设备故障时项目能否继续运行**由工程岗位或安全岗位判断，不得由当班运营人员自己判断**；登记内容变更须经工程或安全审批
- 规则明细：
  - 辅助设备：只停用该台设备本身；**判断结论必须留痕，没有留痕的一律按停止运行处理**
  - 关键安全设备：不存在依赖关系且其余关键安全设备均无故障 → 只停该台故障设备，项目可继续；**存在依赖关系 → 整个游乐项目停止新增核销并停止运行**
  - 依赖判定：按客人走完项目的实际流程判——客人必经环节、少了走不下去＝依赖；有同类设备可顶替或环节可绕过仍能走完＝不依赖

### FIN-01 内部结算价目录

- 状态：待审批 / 已生效 / 历史版本
- 审批归属：餐饮与零售商户（含独立、联营、租赁各种合作模式）统一由**城市项目公司**审批；业态为"其他"的商户由其商户档案上指定的主管公司审批；酒吧由**娱乐平台公司**审批；游乐由**游乐公司**审批；传媒/演出由**传媒公司**审批；中央餐饮供应的酒水或小食由**中央餐饮公司内部差人**审批；城市项目公司直接管理的第三方商户由**城市项目公司**审批；独立餐饮商户由城市项目公司审批，但**中央餐饮供货部分仍由中央餐饮公司审批**

- 依赖：酒吧结算、票务权益

- 异常：**已封账历史账单不回改，跨月退款和调整在当期生成冲正**；**不同税种使用不同的会计科目归集，所有税费一律计入税费成本，不论税种均须记录**；**原期间已经关账、开票或申报的，只能在当前开放期间生成关联原期间的差异调整单**；**国家法律的口径第一，其次以财务的口径为准**
- 平台边界：**正式的会计核算、会计记账、纳税申报和法定凭证一律在专业财税软件中完成，本平台不替代专业财税软件**；平台只接收财税软件回传的数据，或保存经授权人员手工填写并通过审批的数据；**这些数据在平台中用于内部结算、差异解释、经营分析和追溯，不代表平台已经完成正式申报或会计入账**
- 五主体汇总：娱乐平台公司、游乐公司、传媒公司、中央餐饮公司、城市项目公司各自的收入、成本与利润由平台汇总计算；涉税的正式核算数据由专业财税软件回传关键信息，平台据此与自身内部结算数据合并计算
