# G-1 S1 · governance（+4 跨片并入）

基线 032abe93 | 工作面 136 条（governance 132 + 跨片并入 4） | 钱路 4 / 非钱路 128 / 边界 4

判定依据：任务书判据 + 账本内已填 `value_flow` 行的实证格式。所有 136 条均读全 `source_text`（非前 100 字）。

**本片新增判据（编排层裁定，供其他片对齐）：**

> **「决定用哪套规则」本身不构成钱路** —— 要看那套规则管的是钱还是积分/权益。管钱的（账期、计价、分账）→ 钱路；管积分或权益的 → 非钱路。

该判据的由来见「已裁定条目」节。格式参照：钱路行的 `value_flow` 一律取本行 `source_text` 原话，格式对齐同表**真正已填**的 `PGM-0011`/`0014`/`0015`/`0016`（`BSM-0670`/`0392`/`0393`/`0394`/`0750`/`0371` 均为待判空格，不是格式先例）。

归类理由代码（前六项取自任务书情形表，后三项为本片新增，均已在下方逐条写明具体理由）：
- `P` 权限/审批约束（应落 `permission`/`approval`）
- `E` 状态枚举
- `D` 数据流向/对账关系/留痕
- `C` 载体或主体层级定义（不指派钱）
- `M` 只提到钱但本条不定义钱路
- `N` 告知义务
- `U` 界面/展示规范
- `W` 元规则（文档效力、原则仲裁）
- `F` 流程与职责流转（工单、招商推进）
- `J` 积分类规则（积分不是钱；积分 → 虚拟券 → 按内部结算价与商户结算，第三步才是钱）

## 边界条目（需编排层裁）

### PGM-0092
`source_text` 全文：职级只绑定薪资大范围，具体薪资单独填写。

两难：前半句建立了「职级 → 薪资区间」这一绑定关系，落在判据「决定金额：上下限」上；后半句又明确把具体金额推给别处（「具体薪资单独填写」），本条自己不产出任何数额。判钱路会把一条否定性规则写进钱路集合；判非钱路则丢掉「薪资受职级区间约束」这个唯一的约束来源。

倾向：**钱路**。理由是该区间是薪资金额在系统内唯一被声明的上下限来源，`value_flow` 建议取原话「职级只绑定薪资大范围，具体薪资单独填写」。若编排层认为 `value_flow` 只收「实际产生一笔钱」的规则，则应判非钱路并归 `M`。

### PGM-0217
`source_text` 全文：物理项目：是空间、价格、经营数据和权限隔离维度。一个运营公司可以服务多个项目，一个项目也可以同时由多家运营公司分域负责。

两难：「价格……隔离维度」意味着同一标的在不同物理项目可取不同价，即决定了「哪一套价格算」，与已裁的 `BSM-0547`（决定哪套规则算 → 钱路）同型；但整句主旨是组织关系（运营公司与项目多对多），价格只是被并列举出的四个隔离维度之一，与空间、经营数据、权限同级。

倾向：**钱路**，`value_flow` 建议取原话前半句「物理项目：是空间、价格、经营数据和权限隔离维度」。若编排层认为并列枚举中的「价格」不足以构成归属指派，则判非钱路归 `C`。

### PGM-0220
`source_text` 全文：历史合同、财务底稿与既往文件中出现的"资产公司""资产管理公司"，指的就是本主体，同一主体两个叫法；资产业态不另设独立主体，由城市项目公司兼任。

两难：`PGM-0016`（已填 `value_flow`）把场地租金收入归「资产公司」，本条则把「资产公司」解析为城市项目公司——收入实际落到哪个主体，取决于本条，属判据「决定归属：算谁的收入」；但本条形式上是别名统一与主体不另设，接近 `BEQ-0074` 的载体定义先例，且本条明确点名适用对象是「历史合同、财务底稿」。

倾向：**钱路**，`value_flow` 建议取原话「资产业态不另设独立主体，由城市项目公司兼任」。若编排层认为别名映射属载体层，则判非钱路归 `C`——但此时须确保 `PGM-0016` 的「资产公司」在下游有其他解析来源，否则场地租金收入归属主体会悬空。

### BSM-0787
`source_text` 全文：酒吧经营牌照登记在实际经营法律主体名下；场地由具备物业权利的城市项目公司按有效合同提供；资金由实际出资或贷款主体按真实资金关系记录，不能笼统写成"平台出场地、牌照和资金"。

两难：第三分句「资金由实际出资或贷款主体按真实资金关系记录」是对出资/负债的归属指派，而出资关系是 `PGM-0010` 已填 `value_flow` 里「按持股比例定期参与经营净利润分红」的上游；第二分句「场地由……城市项目公司按有效合同提供」同样指向场地租金的付款对手方。但全句的写法是纠正表述（「不能笼统写成……」），三个分句都是权属登记口径，非收付指派。

倾向：**钱路**，`value_flow` 建议取原话「资金由实际出资或贷款主体按真实资金关系记录，不能笼统写成"平台出场地、牌照和资金"」。若编排层认为权属登记不等于钱路，则判非钱路归 `C`。

## 已裁定条目

### `BSM-0547` / `BSM-0677` → 非钱路（积分类先例优先）

本片初判时发现任务书内两条指令对这一对给出相反结果，未自行取舍，上报编排层。**编排层 2026-08-09 裁定：两条均为非钱路，积分类先例优先，成对同裁保持。**

冲突原文：

1. **积分整类先例**（任务书原文）：「积分的获取、扣减、兑换、有效期、**适用哪套规则** → `NOT_STATED`」。
2. **原单条裁定**（任务书原文）：`BSM-0547`「票务规则和商户消费业态规则不得混用」→ 钱路（决定哪套规则算，同 `BSM-0670` 类）；其重复对 `BSM-0677` 同裁。

冲突是实证而非推测：
- `BSM-0547` 的 `entry_name` 为「会员身份、成长值、等级和积分分别按已批准规则计算」；
- `BSM-0677` 的 `domain` 为 `member`，`object` 为「积分\|成长值\|业态规则\|票务规则」，其账本相邻行 `BSM-0678` 为「客人端只展示结果并发起兑换，不自行计算积分或成长值」。

即两条的规则对象都是**积分/成长值适用哪套规则**，正是积分先例明列的 `NOT_STATED` 情形。按积分链路「积分 → 虚拟券 → 按内部结算价与商户结算，第三步才是钱」，这两条停在第一步。

**裁决理由（编排层）**：积分类先例是整类口径，优先级高于单条裁定。原类比链断在「规则」这个词上——

| 条目 | 决定的是什么 | 结论 |
|---|---|---|
| `BSM-0670` | **账期规则** → 直接决定某笔**钱**归哪个账期 | 钱路 |
| `BSM-0547` / `BSM-0677` | **积分/成长值适用哪套规则** → 停在积分链路第一步 | 非钱路 |

同样是「决定用哪套规则」，规则管的是钱还是积分，结果完全不同。由此提炼出本片新增判据（见文首），供其他片对齐。

**写回动作**：两条 `value_flow` 保持 `NOT_STATED`，**不填任何值**，归类 `J` 积分类规则。
