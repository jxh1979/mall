### 正主／镜像的选择

## 附带发现 · A-7 衍生 · 「一个月目标」与「异议期届满后的下一个付账日」存在跑不出来的月份

EV-03-09 | ARITHMETIC_CHECK（对拟改 A-7 文本与既有 §16.1 机制串时间线代实数） | @1c5c0c7d
输入口径（全部取自 EV-03-06 ／ EV-03-07 现文，无一自拟）：

```
账期 = 自然月；账单 = 次月生成（**PRD 未固定出账日**，原文只写「初始在次月生成上月月账单」）；
异议期 = 十个工作日，自账单在商户专区可查看之日的**次日**起算；
付款 = 异议期届满后的**下一个付账日**，付账日 = 每月 5 日 ／ 15 日 ／ 25 日；
顺序硬约束 = 月结定格 → 账单出账 → 异议期届满 → 付账日。
```

代实数（账期 = 1 月，账期结束 = 1/31，「一个月以内」上界 = 2/28）：

```
账单 2/1 可查看  → 起算 2/2  → 十个工作日届满 ≈ 2/13 → 下一个付账日 2/15 → 2/15 ≤ 2/28  达标
账单 2/10 可查看 → 起算 2/11 → 十个工作日届满 ≈ 2/24 → 下一个付账日 2/25 → 2/25 ≤ 2/28  临界达标
账单 2/12 可查看 → 起算 2/13 → 十个工作日届满 ≈ 2/26 → 本月已无满足顺序的付账日 → 顺延 3/5 → 3/5 > 2/28  不达标
```

---

问题：只要出账日晚于当月约 10 日，「账期结束后一个月以内完成」这个目标在**任何**月份都达不到；而 PRD 现文**没有固定出账日**，等于把目标能否成立交给了一个未受约束的变量。

为什么本 shard 仍判拟改 A-7 可直接落（disposition A）：HTML 用词是「**目标**」而非「必须／不得晚于」，拟改文本已逐字保留「目标」并明写「**该时限是完成目标，不构成独立的账期口径**」，**不产生硬性冲突**，故 A-7 本体不被本条阻塞。

但下面这一项**须用户裁决，本 shard 不自拟**：出账日是否要加约束（例如「出账日须配置为使本账期存在满足顺序的付账日」），以及顺延导致超出目标时**是否要留痕／告警**。可比照的凭据是 `DEC-R8-01` 已为付账日建立同构闸门 ——「保存时校验三个付账日中至少须有一个能满足该顺序，一个都不能满足的配置一律拒绝保存」；出账日目前没有对应闸门。
本 shard **不**把「留痕告警」写进 A-7 拟改文本：HTML 未写，属自创口径，且会把一条「目标」悄悄升格为「硬约束」。

依据：EV-03-06 ／ EV-03-07 ／ EV-03-09
severity: P2   disposition: B（需用户裁决出账日约束与超目标处置；裁决前 A-7 拟改可独立落地）
