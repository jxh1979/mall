**FINAL-21（P0）｜opt-in 地基缺失 = 真实越权开放通路**
```
PGM:672 现文：开关默认取值：任何能力在后台没有显式开关配置行时一律默认关闭（opt-in），
要启用必须有人显式打开；开关缺行不得视为开启，也不得由代码或部署脚本代为「视同打开」。
这与拉取失败时的「兜底关闭」是两件事——兜底关闭针对读不到配置的运行时故障，

> 而代码侧正是这样实现的——见 §6 的 `TerminalSwitchGuard.java:20`。**文档缺陷与代码缺陷在此对上了。**

**FINAL-25（P2）｜技术口径 18 次检索全 0**
```

一个正确实现了红线⑤逐笔放行通道的系统，在该通道被行使时**确实会出现同一笔重复生效**，

而 README.md:84 与 architecture-overview:145 仍称其为「交付总闸口（约 50 子闸聚合）」。

**类二｜引文门禁的保护面与缺口**
| 门禁能挡 | 门禁挡不住 |
|---|---|
| 引用了不存在的条名 | 引用了存在的条名，但转述内容与该条**相反** |
| 引用命中多条、有歧义 | 把 A 条的规则挂在 B 条名下（张冠李戴） |
| HTML 改动后账本 source_text 失配（仅**已登记**条目） | 未登记条目的引文 |
| 行号锚点复辟 | 引文断章取义（只抄前半句、丢掉限定词/例外句） |

**当前就绿的反例**（可直接由类一构造）：任何 PRD 只要写
`BSM「容量控制」…按场次容量控量`，条名 `容量控制` 唯一命中 → 检查②放行，
而该条 HTML 现文写的是「**不再按场次**」。**门禁全绿、口径全反。**
