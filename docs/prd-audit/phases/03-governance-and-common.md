## 范围

本阶段审计 `302` 条规则：

- 阶段 2 中领域为 `governance`、`evidence`、`workforce`、`cross-domain` 的规则；
- 治理 HTML「终端开关」「商户侧」中属于治理闸门和数据边界的规则；
- 平台治理 PRD 中与合同准入直接相连、且本阶段发现确定性冲突的四条合同规则。

正式对象仅为 PRD 及直接相关业务文档。代码、迁移、OpenAPI、数据库、测试和运行证据不属于本阶段审计结论；文档中引用这些内容时，只把它们视作当前实现说明，不能反向解释业务 HTML。

## 审计方法

### 顺从性审计

逐条把 HTML 规则映射到主承接文档与章节，检查：

- 事实源与裁决优先级；
- 平台、项目公司、管理公司／业态主体、商户及四类主体绑定；
- 角色、职级、功能权限点、临时授权、高危授权和数据范围；
- 外包／服务商人员与审计人员边界；
- 证据、敏感访问、导出和全链路留痕；
- 终端开关、十类终端及关闭后的后端拒绝；
- 全中文、金额精度、并发幂等、存档和删除等通用规则。

### 对抗性审计

| 反例 | 初始结果 | 收口 |
|---|---|---|
| 同一权限同时允许与显式拒绝 | 已有“显式拒绝优先”，但验收不集中 | 已写入平台治理 PRD、产品规格和 `CONTEXT.md` |
> 本段规则已归口至 `docs/scope-wide-coding-rule-canonical-V0.01.md` §A-21，本文不再重复记载。
| 授权申请人与审批人为同一人 | 高危授权文档未明确拒绝 | 补申请人不得审批自己的授权申请 |
| 外包人员访问未指派对象 | 已明确最小够用、仅被指派范围 | 保持；越界必须拒绝 |
| 审计人员修改业务数据或敏感访问不留痕 | 已明确两类审计人员只读，敏感查看／导出审批留痕 | 保持 |
| 岗位、职级、组织或商户变化后权限残留 | 产品规格仅“提示收回” | 改为立即重算，旧范围派生权限同步失效 |
| 终端开关关闭但业务动作仍被允许 | 已明确前端隐藏不能替代后端拒绝 | 保持 fail-closed；补十端完整拆分 |
| 同一主体在不同 PRD 使用不同术语 | 术语表曾把代码／迁移设为权威 | 改为三份 HTML 最终解释，并建立 `CONTEXT.md` |
