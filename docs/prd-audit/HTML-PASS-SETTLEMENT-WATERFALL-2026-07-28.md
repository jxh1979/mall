## 一、分账瀑布（现行，用户 2026-07-28 拍板）

1. **第三方渠道抽成**（比例/金额后台可配）
2. **赠送权益预估成本** → 归 **娱乐平台公司**
   - 票内加赠的酒水/小食/餐饮/零售，**每一样都是独立权益**，各自绑定提供它的酒吧/餐厅/零售商户，须到对应商户核销
   - 成本按**提供方的内部结算价**计
   - 预扣按票种配置：**按件计** = Σ(票面各权益数量 × 内部结算价)；**按票计** = 该票种赠送部分的售价整额
3. **门票综合服务费** = **娱乐平台公司留存 / 项目管理费**（**同一项，只扣一次**，可配比例/固定额/封顶）→ 归 **娱乐平台公司**
4. 剩余 = **可分配池，仅各酒吧分**；**不再从池内二次扣留存**
5. 各酒吧分成按**整月排名 / 客数**在**月度结算**结出（方式可配）
6. 全部数值可配、禁止写死

> ⚠️ 与本文 2026-07-22 旧版本的差异：旧版写「门票综合服务费 = 项目公司留存」，**已作废**——现归娱乐平台公司。旧版写「酒水预估成本」，现扩为「**赠送权益**预估成本」并给出两种预扣模式。

## 二、赠酒与兑付

- 一张通票覆盖的**每个酒吧至少赠一杯**；各吧杯数**写明票面**；**A 吧赠酒只能在 A 吧核销**
- 核销后由 **娱乐平台公司** 按可配内部结算价与提供商户结算：核销一件结一件、未核销不结算
- 兑付**由娱乐平台公司承担**，不进可分配池、不计酒吧销售提成
- 成本**按提供方商户业态（酒吧/餐厅/零售）分开记账**
- **预扣与核销实付的差额留在娱乐平台公司**，按可配规则调账留痕

| 收入类型 | 归属主体 |

| 订台低消 / 二次消费 / 额外酒水 | 各酒吧商户 ⚠️可重议 |
| 非散台服务费（卡座等） | 各酒吧商户 |

- 「娱乐运营平台」专名已废，一律称 **娱乐平台公司**
- ⚠️「订台低消 / 二次消费 / 额外酒水归各酒吧商户」为**可重议项**：用户从公司利益最大化角度倾向归中央餐饮公司，但**税务上可能过不了**，故先按归各酒吧商户；将来税务方案成立可重议

## 七、第二轮（2026-07-28）：综合／联合通票 A/B/D + 免费权益 C + 内部结算 SKU 目录 E

权威来源：业务 HTML 提交 `e314c595`（PR #257，A/B/D）+ `88eba70c`（PR #260，C/E），用户逐条批准。
本节只做索引与核对锚点，业务解释权仍在三份 HTML 本身。

### 7.1 综合／联合通票的定价构成（A）

售价 =（**游乐业态价** + **酒吧业态价** + **收费的餐饮/零售价**）× **票种折扣**；**免费的（票面价 0）不计入价值**。

### 7.2 综合／联合通票的分账（B）

> ⚠️ **不是第二套瀑布**。§一 的四道扣项顺序、算法与归属主体**一条都没变**，变的是**作用层级**：单业态通票（纯酒吧通票）整单走 §一；综合／联合通票先拆业态份额，**②③两道只作用在酒吧份额**。渠道抽成在两种票上都是**整单先扣**。

1. **整单先扣第三方渠道抽成**（在拆份额之前）
2. 剩余**按各业态票面原价占比拆份额**
3. **游乐份额 → 游乐公司**、**餐饮份额 → 餐厅商户**、**零售份额 → 零售商户**（直接归属）
4. **酒吧份额**再依次扣 **赠送权益预估成本** → **门票综合服务费**
5. 酒吧份额剩余 → **可分配池**，按 §7.3 两段分配给各酒吧商户

**粒度铁律**：拆份额**只按业态大分类**——先区分这份产出由**哪个业态**产生，再按**该业态自己的内部规则**处理；**依附于某业态产生的加赠权益，不作为业态层的拆分对象**，其价值**已含在所属业态的价格内**。
> 与 §二「每样赠品都是独立权益」**不矛盾，是两层**：§二说的是**核销/绑定/成本**层，本条说的是**业态份额拆分**层。

**两个价，不可混用**：

| 价 | 用途 | 不得用于 |
|---|---|---|
| **票面原价** | 定价（A）+ 业态份额拆分占比（B） | 与提供商户结算成本 |
| **内部结算价** | 与提供商户结算兑付成本 + 赠送权益预估成本按件计 | 定价、份额拆分占比 |

### 7.3 可分配池两段分配（D）

| 段 | 参与者 | 算法 | 基数 |
|---|---|---|---|
| **第一段** | 约定「每客单价」或「固定额」的酒吧 | 按约定**绝对金额先拿** | 可分配池 |
| **第二段** | 其余约定「排名档位」的酒吧 | 按档位比例**分尽** | **池 − 第一段合计** |

- **拿了第一段的酒吧不再参与第二段**。
- 守恒式：`可分配池 = 第一段合计 + 第二段合计 + 尾差`（尾差归平台兜底）。
- ⚠️ **替代**原「`by_venue_per_guest` / `by_rank_tier` / `by_fixed_amount` 三选一并列可配」表述。

### 7.4 免费权益的成本承担分两类（C）

| 类 | 定义 | 平台承担成本 | 与商户结算 | 计入赠送权益预估成本 |
|---|---|---|---|---|
| ① **商户让利型** | 餐饮/零售商户为引流**自行让利**搭进通票 | ❌ | ❌ | ❌ |
| ② **平台出资型** | 平台**向商户采购后免费赠客** | ✅ | ✅ 按内部结算价 | ✅ |

- **两类均不参与份额拆分**（票面价 0）。
- 成本承担方**须在票种配置标明**；未标明视为配置不完整，**不得启用**（fail-closed）。
- ⚠️ **原「价格可为 0 的纯赠送/兑换也按内部结算价结算」一刀切口径作废**（原 `D-20260706-2`）。

### 7.8 遗留歧义（本轮 HTML 未逐条写死，落地前建议向用户确认）

- **两段分配的三个边界**：① 第一段合计 ≥ 可分配池时，第二段是否直接为 0、超池部分是否走既有平台负责人特批；② 池内**没有**排名档位酒吧时，余额是留在娱乐平台公司还是倒回第一段追加；③ 池内**只有**排名档位酒吧时第一段为 0（此条与改造前行为一致，风险最低）。当前 PRD 按「① 第二段为 0 + 走特批；② 留在娱乐平台公司不倒回；③ 全池为第二段基数」写入，并已标注为**推导非原文**。
- **业态份额拆分与 §6.4「专属某商户不分摊」的叠加顺序**：一张综合通票里若含 `exclusive_merchant_id` 专属权益，是先拆业态份额再在业态内部处理专属，还是专属先整份摘出。HTML 未写，PRD 未替用户决定。
