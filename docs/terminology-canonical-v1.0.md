## 一、主体类型（多对多协作，不是固定隶属链）

| 类型标签 | 名词 | 定义 | DB 落点 |
|---|---|---|---|
| L1 | **平台** | 顶层平台主体：制定跨项目、跨经营域的统一治理规则并审批跨域规则，可辖多城市多项目；不因处于顶层自动取得某张票、某个项目或某个商户的收入 | `business_entities`(entity_role=platform) |
| L2 | **项目公司** | 某城市的项目经营体(如长沙 NEXT PARK)；同时承担本城市项目的资产职责 | `business_entities`(entity_role=project_company) |
| L3 | **管理公司 / 域主管公司** | 单一经营域的规则、定价和结算主体（娱乐平台公司、游乐公司、传媒公司、中央餐饮公司等） | `business_entities`(entity_role=management_company / spv …) |
| L4 | **商户** | 具体经营单位 | `merchants` 表 |

## 二、当前实现落点（不得反向解释业务术语）

- **无 `organizations` / `org_type` 表**;上述主体类型统一用 **`business_entities` 一表多角色**(`entity_role` 文本,无 CHECK)承载。
- **物理项目与运营公司是多对多关系**，不是固定的「平台→项目公司→域主管公司→商户」隶属链。`business_entities.parent_entity_id` 只表达当前实现里的协作登记，不得解释成行政隶属。
- **`projects` 表 ≠ 项目公司** —— 它是**业态经营单元 / 场馆**(`venue_type` = bar / amusement / ticketing);`project_id` = 综合体维度。两者是两回事,勿混。
- **四主体绑定** = `business_entity_bindings`(binding_type=four_party;每商户至多一条 `active`,重复激活报 409 `ACTIVE_BINDING_EXISTS`);"后续可拆" = 换一条新 active 绑定,不是改 `merchants` 快照列。
- `merchants` / `contracts` 的 `*_entity_id` / `*_subject_id` = 档案 / 签约时快照,与当前绑定可不一致。
- 商户 ↔ 铺位 ↔ 合同 = `merchants`(1)-<`contracts`(N,续约链)-<`contract_spaces`>- `spaces`(多对多);`spaces.status` 仅 `active` / `unavailable`(6 态租赁着色是看板派生视图,非 DB status);无转租(换租户=先退租再招商)。

## 五、结算核心术语（三份业务 HTML 最终解释，结算 PRD 承接）

- **通票分账瀑布**:每张票的票款按固定顺序——① 整单先扣**通路费**（所有支付都有，官方渠道同样产生）→ ② 经第三方渠道售出的再扣**销售渠道费**（官方渠道售出不扣此项）→ ③ 再扣**票务积分发行成本**（域间拆分前从整单扣除、只扣一次）→ ④ 跨域组合通票再**按各业态价格占比拆域**（各业态价格在售票时刻随订单一并固化）→ ⑤ **仅酒吧份额**再扣**赠送权益预估成本**与**门票综合服务费**（该费与「娱乐平台公司留存」「项目管理费」是同一笔钱，全程只扣一次）→ ⑥ 剩余为供酒吧商户分配的**可分配池**。通路费与销售渠道费性质不同不可混用；渠道合同只能约定佣金费率、收付款方式和对账方式，不得改变承担方式。
- **按核销结算 / 未核销按域归属**（2026-08-06 R10 更正，依 ENUM「域归属对照」条、DEC-R8-27/29）:通票权益在核销时才结算给商户;未核销部分票款**不是一律归项目公司**,而是按票种所属**经营域**归属——酒吧域→娱乐平台公司、游乐域→游乐公司、餐饮域与零售域→城市项目公司、演出传媒域→传媒公司;跨域组合通票先按既定域份额拆分再逐域归属。原写「未核销归项目」**已废止**。
- **域归属对照**（2026-08-06 R10 登记，ENUM「域归属对照」条 / DEC-R8-27）:客人未实际取得权益时票款归属的**唯一对照表**,按票种所属经营域确定,与该笔钱是「到期未用」还是「场次终结未核销」**无关**——酒吧域→娱乐平台公司;游乐域→游乐公司;餐饮域与零售域→城市项目公司;演出传媒域→传媒公司。适用两类钱且**两类各自单独立项留痕、不合并**:①**到期未核销票款**(从未完成检票环节的票);②**通票未核销减除额**。跨域组合通票先按既定域份额拆分再逐域归属;顶层平台不因本条取得任何份额。
- **通票未核销减除额**（2026-08-06 R10 登记，ENUM「酒吧通票可分配池」条 / ENUM「主要收入归属」条 / DEC-R8-29）:已完成检票环节(刷码核销成功)、但本张通票覆盖的酒吧当期未被核销入场的,按该票**第二段参与集合**的档位表所对应百分比份额从可分配池中减除的那笔钱。去向按「域归属对照」条逐域归属(酒吧域即娱乐平台公司)。该名目与**到期未核销票款、未分配池余额、金额尾差**四者**分栏列示、不得合并**。
- **场次终结制**（2026-08-06 R10 登记，BSM「核销单位」条）:**一个场次＝一次开门到关门**(跨夜场次以实际闭店时间为准,不按自然日切分)。完成检票环节后该票绑定至当前场次、不得再开启另一个场次;同一场次内不限次数进出且不再重复扣减入场次数。票面各项权益**仅限当场消耗**,场次结束时未核销的权益**即行终结**,不顺延、不折现,作为未核销份额按「域归属对照」条归属。一人多次票与多次通票的**剩余入场次数跨场次保留**至用尽或票面有效期届满,前后场次之间不得挪用权益。
- **综合体入场四词**（2026-08-06 R10 登记，ENUM「核销记录状态」条 / 「年龄限制」条 / DEC-R8-31/32）:**综合体入场**由三道环节**依次分开**完成——**安检环节**(X 光查验随身物品)→**年龄核验环节**(人脸扫描确认满 18 周岁,未成年拒入)→**检票环节**(二维码刷票并核销)。逐道通过,前一道未通过的不得进入下一道;**前两道环节不构成票务核销、不产生核销记录**。「完成检票环节」指其中刷码核销成功的那一刻,与各酒吧入场、各游乐项目入场等**场内单点核销**相区别。原「统一入场刷脸闸／统一入场人脸闸／统一入场闸」等笼统叫法**已废止**,指的是其中第二道年龄核验环节。
- **门票综合服务费**〔规则正文以三份业务 HTML 为准，本表不复述；2026-08-03 起术语表只定名词与主体对应关系〕:**只适用于酒吧相关票务**（原写「所有门票项目都收一道」已作废）,与「娱乐平台公司留存 / 项目管理费」为同一项、分账瀑布中只扣一次、不在酒吧可分配池内再拆;比例或固定额及封顶(项目 × 商户 × 票种)后台可配;**收入归娱乐平台公司**。
- **赠送权益(2026-07-28 口径,替代旧「通票赠酒两段口径」)**:票里加赠的酒水 / 小食 / 餐饮 / 零售,**每一样都是独立权益**,各自绑定提供它的酒吧 / 餐厅 / 零售商户,客人须到对应商户核销;每个权益的成本按**提供方的内部结算价**计。
  - **预扣两种模式(按票种配置)**:**按件计** = 票面各权益数量 × 内部结算价之和;**按票计** = 该票种赠送部分的售价整额。
  - **赠酒按酒吧分配**:一张通票覆盖的每个酒吧**赠酒杯数不得低于后台按票种配置的最低赠酒杯数（出厂默认 1 杯）**,各酒吧分别赠几杯在售票时**写明票面**;**A 酒吧的赠酒只能在 A 酒吧核销**,不得跨吧。
  - **兑付与差额**:核销后由**娱乐平台公司**按该权益可配内部结算价与提供商户结算(核销一件结一件、未核销不结算);对商户的兑付由娱乐平台公司承担,不进入酒吧可分配池、不计酒吧销售提成;成本**按提供方商户业态(酒吧/餐厅/零售)分开记账**;**预扣与核销实付的差额留在娱乐平台公司**,按可配规则调账留痕。
- **综合／联合通票定价构成(2026-07-28 A)**:售价 =(**游乐业态价** + **酒吧业态价** + **收费的餐饮/零售价**)× 票种折扣;**免费的(票面价 0)不计入价值**。
- **业态份额拆分(2026-07-28 B)**:综合／联合通票按上条瀑布在扣完通路费、销售渠道费与票务积分发行成本后，**按各业态价格占比**拆成各业态份额——游乐份额归**游乐公司**、餐饮归**餐厅商户**、零售归**零售商户**;**仅酒吧份额**再依次扣赠送权益预估成本、门票综合服务费,剩余进可分配池。拆份额**只按业态大分类**;**依附于某业态产生的加赠权益不作为业态层拆分对象**(其价值已含在所属业态的价格内)。⚠️ 与「每样赠品都是独立权益」不矛盾:后者说的是**核销/绑定/成本**层,前者说的是**业态份额拆分**层,两层别混。
- **各业态价格 vs 内部结算价(2026-07-28 B,不可混用;2026-08-05 R7 术语统一,原称"票面原价")**:**各业态价格**用于**定价**与**业态份额拆分占比**;**内部结算价**用于**与提供商户结算成本**。每个权益同时带这两个价、分别录入,**禁止互相回退顶替**。
- **可分配池两段分配(2026-07-28 D,替代原「三选一」)**:第一段——约定为「每客单价」或「固定额」的酒吧按**绝对金额先拿**;第二段——**余额**(= 池 − 第一段合计)由其余「排名档位」酒吧按档位比例**分尽**;**拿了第一段的不再参与第二段**。守恒式 `可分配池 = 第一段合计 + 第二段合计 + 尾差`。
- **免费权益成本承担两类(2026-07-28 C)**:票面价 0 的免费权益按成本承担方分——①**商户让利型**(餐饮/零售自行让利搭进通票):平台**不承担成本、不结算**;②**平台出资型**(平台向商户采购后免费赠客):平台按**内部结算价**与提供商户结算、**计入赠送权益预估成本**。两类**均不参与份额拆分**;承担方须在票种配置**标明**。原「价格可为 0 的纯赠送/兑换也按内部结算价结算」一刀切口径**作废**。
- **内部结算 SKU 目录(2026-07-28 E,🆕 新需求·未开发)**:全平台内部结算价**集中一个目录、成本侧唯一真源**;每条绑**提供商家**(业态随商家)+ 归**品类**,商家/业态/品类三维可筛;多处可引用并就地新建、但**只进同一目录**;**目录是唯一可编辑处**,改价走**草案 → 他人复核转正 → 对后续生效**;**核销/结算时把当时价固化到流水**,已发生的账不受后续改价影响、固化价**只读**;条目可下线归档不影响历史引用;内部结算价属**敏感信息、仅授权后台可见**。
